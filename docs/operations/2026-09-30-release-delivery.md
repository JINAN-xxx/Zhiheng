# 版本化镜像交付与回滚验收

日期：2026-09-30。代码位于 `fix/platform-integration-review` 当前工作区，包含此前尚未提交的模块化改造。本轮增加了镜像发布入口，没有升级现有 `zhiheng` 实例。

## 交付内容

`./deploy.sh release` 提供 `build`、`verify`、`deploy`、`rollback`、`status`。构建生成前后端与四类基础设施镜像的离线包、版本清单和独立运行脚本。服务器使用包内 `release.sh` 与固定安装目录，实例密钥、数据和基础配置位于版本目录之外。详细命令见[发布手册](../../deploy/release/README.md)。

发布前校验包内容、镜像 ID、实例身份、实际数据库迁移及插件版本；启动后校验插件路由、Nginx 反代 OpenAPI 和版本。健康检查成功才提交版本记录。兼容更新失败时恢复前一应用，并保留未完成恢复记录供重试。

回滚保留当前合法的插件启停选择，只在版本和迁移身份匹配时修复运行错误状态。清除目标版本的单个 Redis ready 标记，让正常启动重新同步插件资源；中断恢复先停止同实例遗留的 oneoff 写入者。不会执行旧版数据库初始化或自动降级数据。

## 适用边界

当前支持 Linux amd64，运行端需要 Python 3.10+ 与 Docker Compose v2。快捷升级和回滚要求数据及基础运行契约相同；SQL、插件版本、持久格式或基础服务变化必须先规划备份和专项迁移。非 SQL 的不兼容数据变化需提升 `deploy/release/data-version`。本功能不自动备份业务数据、不接管旧源码实例，也不提供无中断滚动发布。

代码、文档与验收产物均在本地，尚未提交或推送；现有服务继续使用其原发布版本。
