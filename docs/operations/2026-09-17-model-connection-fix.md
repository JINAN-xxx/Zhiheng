# 模型连接地址复用与诊断修复

本版修复硅基流动等 OpenAI 兼容服务在复用已有凭据时丢失服务地址、混选不同服务商及失败提示不明确的问题。运维入口为 `data/agent-releases/20260917-model-connection-fix/manage.sh`，后端镜像为 `ruoyi-backend-pg:model-connection-fix-20260917`。

## 根因与处理

旧 `siliconflow-embedding` 凭据只保存 API Key，地址保存在原 Qwen 向量部署中。接入新模型时仅提交凭据名称，没有继承地址，LiteLLM 按 OpenAI 协议默认访问 OpenAI 服务；当前网络下连接测试在 60.02 秒后超时。相同 Key 显式提供硅基地址后测试成功，排除了凭据和模型本身不可用。

- 后台统一解析凭据的服务地址。显式地址优先；缺失时读取全部引用部署，只有地址唯一且有效时才自动继承。缺失、冲突及含用户信息、查询串、片段或控制字符的地址不会被默认为 OpenAI。
- 凭据列表新增安全的 `connectionProfile`。前端按真实地址区分硅基流动、DeepSeek 官方、OpenAI 官方及自定义接口，并展示当前连接实际使用的地址。未知或冲突连接不自动选中。
- 测试、创建部署和编辑部署更换连接使用同一套解析规则。新部署明确保存地址；编辑切换同时同步目标地址，拒绝隐式跨服务商切换。
- 如果旧部署有显式地址而目标只有 SDK 默认地址，因 LiteLLM PATCH 不能通过 null 删除旧字段，该类原地切换会明确拒绝，需要重新接入，避免将新凭据发送到旧地址。
- 连接测试返回固定类别及固定中文消息，区分超时、网络、鉴权、权限、余额、限流、模型不存在、参数和上游不可用。前端只显示白名单消息，审计增加失败类别，不保存请求里的秘密字段或上游错误原文。

原有凭据没有被修改，现有模型目录和内部调用授权保留。旧硅基连接不需要重新输入 Key，也无需手动填写别名。
