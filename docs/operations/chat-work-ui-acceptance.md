# 聊天与工作交互验收

运行真实页面组件；测试拦截 API 以模拟成功、失败和延迟响应，后端持久化与权限另由真实数据库会话测试验证。

## 桌面主流程

1. 进入 `/ai/chat`；空态中心可见“聊天 / 工作”，模型与技能入口可见，记录所有请求并断言没有知识库目录请求。
2. 选择技能并发送一条聊天消息，验证请求中的 `skillSlugs`，以及不存在 `knowledgeBaseIds`。流式结束后中心开关隐藏，聊天历史恢复有效。
3. 从侧栏“新建工作”进入 `/ai/work`；历史区只显示工作任务。中心选择两个已发布智能体，明确指定当前执行者。
4. 输入工作目标；模拟创建接口失败，断言原目标、成员和执行者保留；重试创建后只出现一个任务。
5. 首次生成展示执行者名称、版本和流式文本；中心开关隐藏。第二条消息手动切换执行者，检查发送的 `agentId` 与消息来源一致。
6. 浏览器刷新并前进后退，任务标题、目标、成员、状态及历史消息恢复；从任务 A 切到 B 后，A 的延迟流不能写入 B。
7. 生成中停止，断言取消接口命中当前 `taskId/runId`，已产生内容和取消状态保留；失败可用明确的“重试”恢复。
8. 添加成员、移除成员、主动更新发布版本；移除后旧消息仍保留来源信息。
9. 编辑目标、标题，标记完成，重新打开，再归档；归档后默认列表隐藏，归档筛选中可查看，任务页面不能发送。
10. 返回聊天模式，只显示聊天历史；工作页不呈现模型、知识库或技能配置编辑入口。

## 边界

- 权限只有 `work:query` 时：已有任务深链可读，但不能创建、修改、删除或运行。
- 无 `agent:use` 时：不允许添加执行成员或运行，历史仍可读。
- 智能体下线：成员显示不可用，禁止选择执行；其他可用成员仍可运行。
- 列表刷新失败：保留已有任务并显示警告；详情不存在或越权使用同一错误文案。
- 多个窗口重复发送：后端只允许一个活动运行，重传相同幂等键不再次调用模型。
- 320px、390px 与桌面：最长合法标题、成员名和长消息不遮挡发送/停止按钮；断言按钮边界与截图，而非只检查页面 scrollWidth。
