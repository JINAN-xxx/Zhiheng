## 模型删除与引用保护

模型目录现装配真实组合检查器，删除前检查：

| 数据所有者 | 检查范围 |
| --- | --- |
| AI SQL 数据 | 聊天会话/运行、密钥模型授权、价格版本、调用用量记录；原外键继续兜底 |
| Agent 扩展 | 当前草稿模型、发布 JSON 中 camel/snake 两种字段、Work 成员冻结配置、运行审计模型；保留记录即计入引用 |
| 知识库 | Embedding/LLM 配置、索引模型、图谱配置、历史版本、预览及其模型快照 |

已有引用则拒绝物理删除，不级联删除业务数据。原“仅未发布草稿或停用模型可删除”规则保留。引用冲突文案统一为“模型仍被业务数据引用，不能删除”；检查不可用返回固定提示，不能当作无引用。

`backend.resourceReferences` 是可选声明。核心遍历所有已安装插件，包含停用与运行异常状态；未安装插件不加载查询。注册表保留已安装但缺源码的 ID，遇到这些情况、无注册表、回调失败或非 bool 结果均拒绝不完整检查。Agent 通过自己的 public 查询读取所属数据，AI 不穿透其 DAO/ORM。

SQL 引用写入先锁模型，再锁业务行，多个模型按 ID 排序。删除持有同一模型锁并用当前锁定读取检查扩展引用。知识库在校验模型到持久化 metadata 之间持共享引用锁，删除持独占锁直到 SQL 提交，文件原子事务保持原样。共享锁保留了原有“解析模型期间仍可更新图谱配置”的并发行为。

独立审查复现并促成两处修正：Agent 更新/发布与删除原锁顺序相反，现统一并重验权限、版本和目标模型；知识库关闭图谱时曾跳过非空 LLM ID 校验，现所有待持久化模型 ID 都先验证。两项均增加红灯回归，最终在真实 PostgreSQL 和知识库行为测试中复验通过。
