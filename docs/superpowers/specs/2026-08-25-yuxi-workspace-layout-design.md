# Yuxi 工作台式布局改造设计

## 目标

将智衡平台从“传统后台叠加 AI 装饰”的布局，调整为接近 Yuxi 的桌面工作台：安静、平铺、功能优先。AI 只体现在对话和模型能力中，不通过大标题、营销文案、发光效果或卡片堆叠强调。

本轮只改桌面端布局与视觉层，不改业务接口、权限模型和已有功能，不扩展移动端布局。

## 设计原则

1. 全局只有一条主导航，不再叠加常驻顶部导航栏。
2. 页面内容直接占满剩余空间，不将整个页面包进浮动卡片。
3. 业务页面根据任务采用列表、详情、表格、分栏和抽屉，而不是统一做成仪表盘卡片。
4. 使用中性灰白表面和单一克制强调色；暗色模式使用中性黑灰，不使用蓝紫渐变或发光效果。
5. 页面文案只描述对象和操作，不出现“智能驱动”“AI 赋能”等装饰性表达。
6. 所有布局以高频操作、扫描效率和状态辨识为优先。

## 全局壳层

### 左侧导航

- 展开宽度为 `230px`，折叠宽度为 `56px`。
- 品牌、折叠按钮、主要菜单、最近对话、底部用户区全部位于左侧导航内。
- 导航项高度为 `32px`，图标为 `16px`，圆角不超过 `8px`。
- 默认状态使用中性灰文字；选中状态使用浅强调色背景和强调色文字，不使用大色块。
- “新建对话”作为第一操作项；“搜索”紧随其后。
- 最近对话位于主菜单下方，使用剩余高度滚动；折叠后隐藏。
- 管理后台入口、主题切换和用户信息位于底部固定区域。
- AI 工作区导航将“模型目录、开发接入、用量记录”归入“模型中心”视觉分组；底层页面路径保持不变，兼容已有书签和外部跳转。

### 顶部区域

- 删除当前常驻的全局顶部栏。
- 页面标题、刷新、新建等操作由页面自己的 `PageHeader` 承担。
- 通知和账户操作收进左侧底部用户区或弹出菜单，不再占用整个平台横向空间。

### 内容区域

- 内容区高度为视口剩余高度，使用 `min-height: 0` 和局部滚动。
- 页面根节点不设置装饰性外边距和大圆角容器。
- 页面头部固定为紧凑标题栏，主体自行决定单栏、双栏或表格布局。

## 页面布局规范

### 智能对话

- 对话区直接铺满内容区域，不放入卡片。
- 会话历史继续由全局左侧导航承担。
- 模型选择、参数和会话操作放在对话页紧凑工具栏。
- 消息正文保持宽度约束，但不使用大面积气泡卡片或渐变背景。
- 输入区固定在底部，发送、附件和停止按钮保持稳定尺寸。

### 模型中心

- 使用“资源列表 + 详情区域”的工作台布局。
- 左侧展示模型列表、搜索和状态；右侧展示概览、部署、价格和测试等标签页。
- 新建与编辑使用抽屉或弹窗，不将配置表单长期堆在主页面。
- 模型类型、生命周期和绑定状态使用紧凑状态标签。
- 模型列表不再展示“能力”列；接入表单不要求用户手动勾选能力，前端按模型类型提交兼容默认值。
- 后端 `capabilities` JSON 字段和响应契约暂时保留，用于兼容历史数据和已有调用方；本轮不做数据库删除迁移。
- 生命周期操作必须完整：草稿显示“发布”，已发布显示“停用”，已停用显示“重新启用”。“重新启用”复用发布接口并保留首次发布时间。

### 开发接入

- 保留已完成的“左侧应用列表 + 右侧详情标签页”结构。
- 去掉外层卡片感，改为连续的边框分区。
- 概览、访问密钥、模型授权、调用记录沿用当前子页面。
- 应用停用、启用和删除集中在详情头部，不重复出现在各标签页。

#### API 说明入口

- 不新增一级或二级菜单。
- 在开发接入页面标题栏右侧增加带文档图标的“API 说明”按钮，位置在刷新和新建应用操作之间。
- 点击后进入模块内独立视图 `/ai/application?view=docs`，不依赖当前是否已选择应用。
- 返回操作恢复进入文档前的应用、标签页和查询参数；浏览器前进、后退行为保持一致。
- API 说明视图使用与开发接入一致的工作台标题栏、分隔线、表格和状态组件，不使用外部文档站主题或卡片堆叠。

#### API 说明页面

- 左侧为紧凑接口目录，右侧为可滚动文档正文。
- 页面顶部提供“返回应用管理”、复制调用地址、打开 Swagger 和打开 ReDoc 操作。
- 调用地址基于当前站点生成，公开接口根路径为 `/v1`。
- 文档目录固定包含：接入说明与 Bearer 鉴权、授权模型、对话生成、向量生成、文本排序、流式调用、错误码。
- 对外接口与当前后端保持一致：
  - `GET /v1/models`
  - `POST /v1/chat/completions`
  - `POST /v1/embeddings`
  - `POST /v1/rerank`
- 对话接口同时说明普通响应和 `stream: true` 的 SSE 流式响应，流式调用作为主要示例。
- 每个接口包含用途、请求字段、响应字段、`curl` 示例和 Python 示例；文案使用中文，协议字段和代码保持原始英文。
- 所有示例只使用 `<DEVELOPER_API_KEY>`、`<MODEL_CODE>` 等占位符。页面不读取、回填、缓存或复制真实访问密钥。
- Swagger 和 ReDoc 作为完整协议参考在新标签页打开，模块内页面负责开发者最小接入闭环。

### 用量记录

- 使用“页面标题 + 筛选工具栏 + 数据表格”的标准运营页面。
- 指标仅作为表格上方的紧凑摘要，不使用大尺寸统计卡片阵列。
- 筛选、分页和刷新保持在固定位置，避免内容加载造成布局跳动。

### 管理后台

- 保持传统管理工具的效率：搜索表单、数据表格、批量操作和抽屉详情。
- 不强行套用对话页样式，不增加 AI 文案或智能化装饰。
- 系统管理菜单仍通过权限动态生成，但视觉上沿用同一左侧导航体系。

## 共享组件边界

### `PlatformSidebar`

负责品牌、折叠、主导航、最近对话和底部用户区。它不负责加载具体业务页面数据。

### `WorkspacePage`

负责满高页面、标题栏和主体滚动边界，不提供装饰性卡片样式。

### `PageHeader`

统一页面标题、副标题和操作区。标题使用紧凑字号，副标题可选；操作按钮右对齐。

### `ResourceSplitView`

统一模型中心、开发接入等“列表 + 详情”页面的分栏、选中态和窄宽度约束。

### `ResourceTable`

继续承担运营和管理页面表格，统一行高、空状态、加载状态和分页。

## 颜色与排版

- 主背景使用白色或接近白色的中性灰。
- 分隔线使用低对比中性灰，不使用重阴影区分层级。
- 强调色只用于选中项、主按钮、链接和关键运行状态。
- 正文字号以 `14px` 为主，页面标题约 `20px`，面板标题约 `15px`。
- 不使用随视口缩放的字体，不使用负字距。
- 中文状态和按钮文案禁止换行；长名称使用省略号和悬浮提示。

## 交互与数据加载

- 路由切换保留当前页面状态，不因壳层调整重复请求数据。
- 最近对话只在用户拥有对话权限时加载。
- 页面刷新只刷新当前页面资源，不触发无关模块请求。
- 折叠导航只改变布局宽度，不卸载当前页面。
- 抽屉、弹窗和菜单关闭后正确释放临时状态与敏感数据。

## 错误和空状态

- 错误、空数据、无权限和加载状态嵌入当前工作区域，不占据整个页面。
- 已有数据刷新失败时保留旧数据并显示轻量过期提示。
- 无权限页面不展示不可执行按钮，也不发起对应接口请求。

## 验收标准

1. 桌面端不再出现常驻全局顶部栏。
2. 左侧导航展开与折叠后均无文字、图标和状态重叠。
3. 对话、模型中心、开发接入、用量记录和管理后台采用各自合适的工作布局。
4. 页面不存在外层大卡片、卡片嵌套、装饰渐变或大面积 AI 文案。
5. `1280x800` 和 `1440x900` 下无横向页面溢出，长中文名称正确截断。
6. 浅色和暗色模式均保持中性表面、清晰分隔和可读对比度。
7. 页面首次加载和路由切换不新增无关接口请求。
8. 开发接入标题栏可以进入 API 说明，并可返回进入前的应用与标签状态。
9. API 说明准确覆盖四个现有公开接口、Bearer 鉴权、SSE 流式调用和稳定错误结构。
10. API 说明页面及代码示例不包含任何真实访问密钥。
11. 左侧导航将模型目录、开发接入和用量记录显示为同一模型中心分组，原有页面路径仍可访问。
12. 模型列表和接入表单不要求用户维护能力字段，已停用模型可以重新启用。
13. 前端插件测试、生产构建和 Playwright 桌面截图检查全部通过。

## 非目标

- 不重写后端 API。
- 不调整数据库结构和权限编码。
- 不新增知识库、智能体或工作区业务能力。
- 不照搬 Yuxi 的品牌素材和业务文案。
- 不实现浏览器内在线调试或自动发送公开 API 请求。
- 不处理移动端布局。
