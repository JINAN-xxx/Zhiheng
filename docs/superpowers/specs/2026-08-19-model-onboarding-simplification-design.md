# 模型快速接入简化设计

## 背景

当前模型接入界面直接呈现 Provider 凭据、引擎部署、平台模型、Binding 和发布五段资源链。该链路适合平台治理，但要求普通使用者理解过多内部概念，首次接入成本偏高。

本次改造只简化用户操作，不改变后端资源模型、事务边界和安全约束。

## 目标

- 默认接入流程只要求用户理解 Provider、API Key 和模型名。
- 一次提交自动完成连接测试、凭据、Deployment、平台模型、Binding 和发布。
- 已成功创建的资源在后续步骤失败时继续保留，允许安全重试，不自动补偿删除。
- 保留四个高级管理标签，供运维人员检查和维护底层资源。
- 不回填、不记录、不缓存 Provider Secret。

## 非目标

- 不合并或删除现有后端表、Service、DAO 和 Runtime Adapter。
- 不新增自动探测 Provider 计费、模型能力或上下文长度的外部请求。
- 不改变现有权限编码和 API 路由。
- 不在本阶段增加批量导入、多 Provider 容灾或自动轮换凭据。

## 信息架构

模型中心默认展示“平台模型”列表和一个主要操作“接入模型”。页面中的引擎部署、Provider 凭据和运行状态继续保留，但归入“高级管理”区域，默认不抢占首次接入视线。

快速接入抽屉包含三个连续区段：

1. **选择 Provider**：选择 Provider；若存在兼容凭据，可选择复用或创建新凭据。
2. **填写连接信息**：新凭据仅填写 Provider 动态必填字段；模型名使用 Provider 默认提示或手工输入；连接测试是进入下一步的必要条件。
3. **确认接入**：填写平台显示名称和可选模型编码，确认后自动完成剩余资源编排。

超时、流超时、重试次数、RPM、TPM、描述、Alias 和默认模型参数放入折叠的“高级设置”。默认值由平台生成，普通用户无需填写。

## 数据与编排

前端继续调用现有 API，不复制后端业务规则：

1. 加载 Provider 字段定义、可复用凭据和平台模型。
2. 创建或复用 Credential。
3. 使用 Provider、Credential 和上游模型执行连接测试。
4. 创建或精确复用 Deployment。
5. 创建或复用 draft 平台模型。
6. 创建或 CAS 更新 Binding。
7. 发布平台模型。

Deployment 对账必须使用 canonical Provider、Alias、上游模型、Credential、blocked 状态和用户显式提交的高级字段。存在同 Alias 但配置不同的 Deployment 时必须提示冲突，不能静默复用或覆盖。

## 状态与失败处理

抽屉只展示面向用户的阶段状态：

- `连接信息`
- `测试连接`
- `正在接入`
- `接入成功`
- `需要处理`

失败提示必须指出失败阶段和可采取的动作，但不回显 Secret、原始上游正文或内部异常。

重试规则：

- Credential 已创建：重试时复用，不重复创建。
- Deployment 已创建：重试前先精确对账，匹配则复用。
- draft Model 或 Binding 已创建：保留并继续后续步骤。
- 发布失败：保留全部前置资源，修正问题后重新发布。
- 创建响应不确定：先查询并对账，确认不存在后才能再次创建。

关闭抽屉后重新打开，可以从服务器资源恢复可确认的进度；Secret 不持久化，若仍需使用则要求用户重新输入。

## 权限与安全

“接入模型”入口继续要求完整权限交集：Credential 查询/创建、Deployment 查询/创建、模型查询/创建/编辑/发布和连接测试。缺少任一权限时隐藏快速接入入口，不显示一个注定失败的按钮。

Management Key 未配置时，保留已有列表和只读能力，但禁用所有控制面写操作。

Provider Secret 只允许出现在 HTTPS 请求正文中，并继续设置 `repeatSubmit: false`，避免进入浏览器重复提交缓存。密码、Token、私钥、证书、上传和多行凭据字段永不使用上游默认值回填。

## 响应式交互

- 桌面端使用不超过 760px 的右侧抽屉。
- 760px 以下使用全屏抽屉。
- 主操作保持在底部稳定区域，动态字段滚动时不丢失。
- 错误文案、字段和按钮不得造成 320px 视口横向滚动。

## 验收标准

- 新用户可只填写 Provider、Credential Secret、模型名和平台名称完成接入。
- 高级设置默认折叠，现有四个高级管理标签仍可访问。
- 已有凭据可安全复用；新凭据的 Secret 不回填。
- 六个编排阶段任一失败后，前置资源保留且重试不重复创建。
- Connection Test、未知创建结果、Alias 冲突、Management 未配置和权限不足有明确且脱敏的界面状态。
- 1440、390 和 320 三种视口无横向溢出，移动端抽屉可完成整个流程。
- 现有模型中心转换测试、插件测试、生产构建及 Playwright 核心流程全部通过。
