# AI 工作台菜单与全局布局改造设计

## 文档状态

本文是 `feat-litellm-deployment` 分支的全局菜单与应用外壳改造规格，基于 2026-08-20 用户确认的前端原型。

本文增量替代 `2026-08-18-yuxi-style-platform-ui-design.md` 中仍允许传统 RuoYi 树形主菜单、常驻面包屑和 AI 主菜单并列 Developer API 的部分。未被本文明确替代的颜色、排版、组件、业务页面、权限和移动端规则继续有效。

参考项目为 `https://github.com/xerrors/Yuxi`。本项目只借鉴其 AI 工作台优先的信息架构、紧凑侧栏和空间关系，不复制其品牌、业务代码或资源。

## 问题

当前平台已经应用青绿色设计变量和 Workspace 组件，但全局框架仍保留传统 RuoYi 后台结构：

- 多层树形菜单承担全部产品导航。
- 面包屑、多标签页和大量顶部工具常驻。
- AI 对话、模型中心和 Developer API 作为并列后台菜单。
- 管理功能与 AI 高频工作流处于同一视觉层级。
- 移动端只是缩小旧后台，而不是面向 AI 工作流重新组织。

因此页面颜色已变化，但信息架构和交互模型仍显得老旧、分散。

## 目标

- 登录后优先进入 AI 工作台，而不是传统管理首页。
- 使用一套全局应用外壳承载 AI 工作台和管理控制台。
- 将 Developer API 归入 AI 资源的应用接入域。
- 让新建对话、最近会话和 AI 资源成为最高频入口。
- 管理控制台保留全部动态菜单、RBAC 和运维能力，但不干扰 AI 工作流。
- 桌面端和移动端都具备明确、紧凑且无横向溢出的导航体验。
- 保持现有业务 URL、后端接口和权限码兼容。

## 非目标

本阶段不负责：

- 重写模型、应用、用量或系统管理的后端接口。
- 复制 Yuxi 的品牌标识、图片、源码或 Ant Design Vue 组件实现。
- 更换 Element Plus、Pinia、Vue Router 或动态菜单基础设施。
- 新增全平台聚合计费用量接口。
- 重做所有业务页面内容；只处理全局外壳、菜单和 AI 资源容器。
- 删除系统管理、监控、工具、代码生成、锁屏或暗色模式能力。

## 选定方案

采用“AI 工作台优先”方案。

未选方案：

- 统一运营控制台：改造成本较低，但仍以传统后台菜单为中心，不能解决产品感不足的问题。
- 产品切换器加上下文菜单：扩展性更强，但需要重构动态路由和权限映射，超过当前阶段所需复杂度。

## 信息架构

### AI 工作台

```text
AI 工作台
├─ 新建对话
├─ AI 对话
├─ 最近会话
├─ AI 资源
│  ├─ 模型
│  ├─ 应用接入
│  └─ 用量
└─ 管理控制台
```

职责：

- `AI 对话`：当前会话工作区。
- `最近会话`：搜索、切换和管理已有会话，在整个 AI 模式中常驻。
- `AI 资源 / 模型`：Platform Model、Binding、部署、凭据、连接测试和费率。
- `AI 资源 / 应用接入`：Application、Developer API Key、模型授权和配额。
- `AI 资源 / 用量`：先选择有权访问的应用，再调用现有应用用量 API 展示调用台账。
- `管理控制台`：切换到管理模式，不打开第二套旧视觉外壳。

### 管理控制台

```text
管理控制台
├─ 返回 AI 工作台
├─ 用户与权限
├─ 系统配置
├─ 审计与日志
├─ 监控
└─ 系统工具
```

管理菜单继续来自现有动态路由和 RBAC 数据。前端仅排除 AI 产品菜单并重组展示，不复制静态管理菜单。

## 全局应用外壳

平台只保留一套 `PlatformShell`，支持 `ai` 和 `admin` 两种模式。

模式必须由当前路由和用户权限纯函数推导，不依赖上一次本地状态。刷新、直接输入 URL、浏览器返回、Logo 点击和模式往返必须得到一致结果。

两种模式共享：

- 品牌与设计变量。
- 主题和界面密度。
- 用户菜单与登录状态。
- 桌面侧栏折叠能力。
- 移动端抽屉。
- 路由守卫和权限数据。

两种模式只切换侧栏内容和顶部辅助导航。

## 桌面端布局

### 侧栏

- 展开宽度为 `230px`。
- 收起宽度为 `56px`。
- 菜单项高度为 `32px`。
- 顶部依次为品牌和“新建对话”主操作。
- 主导航只显示 AI 对话和 AI 资源。
- 最近会话位于主导航下方，并占用剩余可滚动空间。
- 底部固定管理控制台入口、主题和用户信息。
- 收起后只显示有 tooltip 的主导航、模式入口和用户图标，不显示最近会话。

### 顶部栏

- 高度约 `48px`。
- AI 模式只保留当前页面标题、全局搜索、主题和用户操作。
- 源码、文档、界面密度和布局设置移入用户菜单。
- AI 模式不显示面包屑和多标签页。
- 管理模式显示紧凑页面标签，支持关闭、刷新和常用多页面切换。
- 管理模式提供明确的“返回 AI 工作台”操作。

### 内容区

- 使用现有 Workspace 设计变量和 Element Plus 基础控件。
- 页面区块采用轻边框或无框布局，不把每个页面区域包装为悬浮卡片。
- 页面标题、页面级标签、工具条、内容和分页形成稳定垂直层级。
- 固定格式表格和工具栏需要稳定宽度约束，动态状态不得造成布局跳动。

## 移动端布局

- 视口小于 `992px` 时，全局侧栏转为全高抽屉。
- 顶部只保留菜单按钮、品牌和用户头像。
- 抽屉包含完整主导航、最近会话、管理控制台入口和用户操作。
- 路由切换、会话切换和浏览器返回后自动关闭抽屉。
- 移动抽屉状态与桌面折叠状态相互独立。
- 表格隐藏低优先级列，行操作收进“更多”菜单。
- `390px` 和 `320px` 视口不得产生文档级横向滚动、标题单字竖排或操作重叠。

## AI 资源容器

新增 `AiResourceShell` 作为模型、应用接入和用量的统一页面容器。

容器负责：

- 统一标题和说明。
- 根据权限展示页面级标签。
- 保持标签和路由同步。
- 渲染子路由内容。
- 在单个标签失败时隔离错误，不阻断其他标签。

标签映射：

| 标签 | URL | 最低可见权限 |
|---|---|---|
| 模型 | `/ai/model` | `ai:model:list` |
| 应用接入 | `/ai/application` | `ai:application:list` |
| 用量 | `/ai/usage` | `ai:application:list` |

用量页面先加载用户可见应用。选择应用后调用现有 `GET /ai/applications/{application_id}/usage`，不新增后端聚合接口。

缺少某个标签权限时只隐藏该标签，不得触发对应 API，也不得让整个 AI 资源入口不可用。用户没有任一 AI 资源标签权限时隐藏 AI 资源主导航。

## 路由与默认入口

保留现有业务 URL：

- `/ai/chat`
- `/ai/model`
- `/ai/application`

新增 `/ai/usage`。

默认入口规则：

1. 拥有 `ai:chat:list` 时，`/index` 跳转 `/ai/chat`。
2. 否则跳转用户有权访问的第一个 AI 资源标签。
3. 没有任何 AI 权限时进入第一个有权访问的管理控制台页面。
4. 不允许跳转到无权限页面，也不允许形成重定向循环。

旧收藏链接和直接访问继续有效。页面模式由目标路由重新解析，不依赖导航来源。

## 前端组件边界

### `PlatformShell`

负责：

- AI/管理模式。
- 桌面和移动布局。
- 侧栏和顶部栏组合。
- 抽屉遮罩及滚动边界。

不负责业务数据和权限规则计算。

### `PlatformSidebar`

负责：

- 品牌、新建对话和 AI 主导航。
- 最近会话的搜索、切换和更多操作。
- 折叠显示和移动抽屉显示。
- 管理控制台、主题和用户入口。

会话加载失败时保留最后成功数据并标记“可能已过期”。该错误不得阻止 AI 资源或管理控制台导航。

### `AdminSidebar`

负责使用现有动态菜单数据展示管理菜单，并提供返回 AI 工作台入口。菜单过滤、排序和分组由纯函数完成。

### `PlatformTopbar`

负责当前页面标题、搜索、主题、用户菜单，以及管理模式的紧凑标签页。

### `routeWorkspaceResolver`

纯函数输入：

- 当前路由。
- 动态路由树。
- 权限集合。

纯函数输出：

- 当前模式。
- 默认入口。
- AI 主导航。
- AI 资源标签。
- 管理菜单树。

不得读取 DOM、网络或本地存储。

## 状态管理

- 当前模式由路由推导，不持久化。
- 桌面侧栏折叠偏好可以持久化。
- 移动抽屉只保存在内存中，路由变化后关闭。
- 最近会话使用独立 request generation，迟到响应不得覆盖新数据。
- AI 资源各标签保留自己的加载、错误、空态和最后成功时间。
- 旧 `navType`、顶部菜单和混合菜单选项停止生效，并从布局设置中移除。

## 权限与安全

- 所有导航项和页面级标签基于真实权限独立显示。
- 直接 URL 无权限继续由现有路由守卫拒绝。
- 隐藏入口不能替代后端权限检查。
- 未授权标签不得发起预加载请求。
- 菜单、本地缓存、日志和错误提示不得保存 API Key、Provider Credential 或认证头。
- 最近会话标题按现有安全响应展示，不渲染任意 HTML。
- 管理动态菜单的 URL 和外链继续经过现有安全校验。

## 错误与降级

- 最近会话失败只影响会话区。
- AI 资源某个标签失败只影响当前标签。
- 已有数据刷新失败时保留旧数据并显示“可能已过期”和最后成功时间。
- 首次失败展示错误态，不伪装为空数据。
- 管理菜单解析失败时显示稳定错误和返回 AI 工作台入口，不渲染部分不可信菜单。
- 路由解析遇到未知模式时 fail closed 到用户有权访问的默认入口。

## 可访问性

- 可点击导航使用原生链接或按钮，不使用仅有 `div` 点击事件的伪按钮。
- 图标按钮具有可访问名称和 tooltip。
- 支持 Tab、Enter、Space 和 Escape。
- 当前菜单使用 `aria-current="page"`。
- 移动抽屉开启后限制焦点，关闭后焦点返回菜单按钮。
- 收起侧栏的图标必须可通过 tooltip 识别。
- 颜色不是状态的唯一表达方式。

## 视觉规则

- 主色继续使用 `#3996AE`，深色主色使用 `#24839A`。
- 使用现有 Workspace 字体、间距、状态色和浅色/暗色设计变量。
- 卡片圆角不超过 `8px`，菜单项圆角建议 `6px`。
- 页面不使用装饰性渐变、光斑或大面积插画。
- 菜单激活态使用浅青背景、深青文字和明确文字权重。
- 管理控制台保持紧凑、可扫描和高信息密度，不改造成营销页。

## 测试与验收

### 纯函数测试

- 路由到模式解析。
- 权限到默认入口解析。
- AI 资源标签过滤。
- 管理菜单过滤与分组。
- 未知路由和空权限 fail closed。

### 组件测试

- 侧栏展开和收起。
- AI/管理模式往返。
- 最近会话加载、过期数据和迟到响应。
- AI 资源标签切换和错误隔离。
- 用户菜单中的主题、密度和布局设置。

### Playwright

覆盖 `1440px`、`1024px`、`390px`、`320px`：

- 登录后的默认入口。
- 直接 URL、刷新和浏览器返回。
- 新建、搜索、切换和管理会话。
- AI 资源三个标签及权限组合。
- 管理控制台往返和动态菜单。
- 桌面折叠与移动抽屉。
- 键盘导航、焦点恢复和 Escape 关闭。
- 浅色、暗色和刷新错误状态。
- 文档宽度不超过视口，文本和操作不重叠。
- Console 和 page error 均为空。

### 回归要求

- 原有动态菜单和 RBAC 不回归。
- 系统管理、监控、工具、标签页、锁屏和暗色模式保持可用。
- AI 对话、模型中心、Developer API 和用量 API 不改变后端契约。
- 前端插件测试和生产构建通过。

## 实施顺序

1. 建立路由模式解析和菜单过滤纯函数。
2. 实现 `PlatformShell`、`PlatformSidebar`、`AdminSidebar` 和 `PlatformTopbar`。
3. 接入最近会话和移动抽屉。
4. 实现 `AiResourceShell` 与用量标签。
5. 迁移现有 AI 页面到新外壳。
6. 收敛旧 Navbar、Sidebar、TagsView 和布局设置兼容层。
7. 完成权限、响应式、可访问性和视觉回归。

每一步必须保持现有业务页面可访问，不进行一次性大爆炸替换。

## 完成标准

- AI 工作台成为默认产品入口。
- Developer API 不再作为独立主菜单出现。
- AI 资源包含模型、应用接入和用量三个权限隔离标签。
- AI 与管理模式使用同一视觉外壳并可稳定往返。
- AI 模式不再显示传统面包屑和多标签页。
- 最近会话在 AI 模式中常驻，侧栏收起时隐藏。
- 四个验收视口无横向溢出和菜单重叠。
- 原有 URL、RBAC、后端接口和管理功能无回归。
