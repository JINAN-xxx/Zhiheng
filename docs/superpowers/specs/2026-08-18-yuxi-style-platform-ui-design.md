# 智衡 AI 平台统一 UI 设计规格

## 目标

在不改变现有业务接口、权限标识和路由契约的前提下，将平台前端统一为接近 Yuxi 的 AI 工作台体验：登录后默认进入对话，AI 能力成为主入口，系统管理保留为独立的管理控制台。

参考项目：`https://github.com/xerrors/Yuxi`。本项目只借鉴其信息架构、空间关系、设计变量和交互模式，不复制其业务代码或品牌资源。

## 已确认决策

- 采用 AI 工作台优先的导航结构。
- 登录后的默认页面是 AI 对话工作台，最近会话直接显示在左侧。
- 系统管理进入独立的“管理控制台”分组。
- 默认品牌名为“智衡 AI”，继续支持系统配置覆盖名称和 Logo。
- 保留 Element Plus，不进行一次性组件库迁移；通过主题变量和平台组件封装实现参考风格。
- 改造范围包括登录/注册、全局壳、AI 对话、模型中心、Developer API 和系统管理页面。
- 后端接口、数据库、权限码、路由名称和现有业务状态机不在本次视觉改造中改变。

## 视觉系统

### 色彩

建立平台级 CSS 变量并映射到 Element Plus：

- 主色使用 Yuxi 风格青绿色，亮色基准为 `#3996AE`，深色基准为 `#24839A`。
- 页面背景使用白色、浅灰和深灰分层，不使用大面积渐变、装饰性光球或高饱和紫色。
- 文本至少提供主文本、次文本、辅助文本和禁用文本四级对比度。
- 成功、警告、错误和信息状态使用独立色阶，状态不只依赖颜色，同时显示文字或图标。
- 暗色主题沿用同一套语义变量，不在业务页面写死亮色值。

### 尺寸与表面

- 圆角仅使用 4px 和 8px 两档。
- 页面、面板、表格和输入控件使用统一间距变量。
- 普通资源页面采用轻边框和低阴影；浮层、抽屉和弹窗才使用明显层级。
- 模型 ID、Key 前缀、Provider 和请求标识使用等宽字体。
- 图标按钮必须有 tooltip 或可访问名称；熟悉操作优先使用图标，破坏性操作保留文字确认。

## 信息架构

### 全局壳

- 桌面端使用窄侧栏作为主导航，支持展开显示文字和收起显示图标。
- 主导航包含：新建对话、最近会话、模型中心、Developer API。
- 底部区域包含用户菜单、主题切换、个人设置和管理控制台入口。
- 管理控制台继续读取现有动态路由和权限树，不复制一套新的权限来源。
- 移动端侧栏变为抽屉，主内容宽度始终不产生横向溢出。
- 原有标签页、面包屑和锁屏能力保留；视觉上降级为辅助导航，不遮挡 AI 工作区。

### 登录与注册

- 登录页采用简洁的双区域工作台入口：品牌/产品说明区域与表单区域。
- 默认标题使用“智衡 AI”，实际名称和 Logo 读取现有系统配置。
- 保留验证码、记住密码、注册入口、错误提示、暗色主题和无障碍标签。
- 登录、注册、退出和重定向逻辑不变。

## 页面设计

### AI 对话工作台

- 左侧会话列表支持搜索、新建、归档、当前会话高亮和加载/空状态。
- 顶部工具栏显示模型选择、对话状态、偏好设置和当前会话动作。
- 消息区采用无嵌套卡片的连续流式布局：用户消息右侧、AI 消息左侧。
- AI 消息保留 Markdown、代码、思考过程、用量、流式光标、失败提示和重试。
- 输入区固定在工作区底部，支持多行输入、图片附件、发送、停止和快捷键提示。
- 加载、生成、完成、取消、中断和失败都提供文字状态，不仅使用颜色区分。
- 页面刷新和打开历史会话时，必须保留已有数据的加载、错误和空状态边界。

### 模型中心

- 模型、部署、凭据和 Runtime 状态继续使用现有四标签结构。
- 各标签统一使用页面标题、工具栏、轻量资源列表、空状态和错误状态。
- 状态标签使用统一语义：active、disabled、draft、stale、misconfigured、unknown。
- 详情抽屉、凭据表单、部署表单统一间距、字段标签、校验反馈和确认操作。
- 秘密字段只允许一次性展示，刷新、编辑和失败重试不得回填秘密。
- 移动端将低优先级列和行操作收进“更多”菜单。

### Developer API

- 应用、Developer Key、模型授权和调用状态使用同一套资源面板语言。
- Key、模型 ID、授权状态和调用统计使用可复制的等宽文本展示。
- 创建、轮换、吊销和授权操作继续遵守原有权限码、一次性秘密返回和审计要求。
- 错误状态需要区分未配置、无权限、网络失败和上游失败。

### 管理控制台

- 保留用户、角色、菜单、监控、系统工具和代码生成等现有功能。
- 统一顶部栏、侧栏、标签页、查询区、操作区、表格、分页和弹窗的视觉变量。
- 管理页面优先信息密度和可扫描性，不使用营销式 Hero、装饰性卡片堆叠或大面积插画。
- 表格、筛选和操作权限继续由现有路由元信息、`v-hasPermi` 和后端响应控制。

## 组件边界

新增或整理平台级样式与组件，避免在每个页面复制样式：

- `WorkspaceShell`：AI 工作台导航和主内容区域。
- `WorkspaceSidebar`：主导航、最近会话和移动端抽屉。
- `WorkspaceToolbar`：页面标题、状态、筛选和操作区域。
- `WorkspacePanel`：轻边框面板和统一内边距。
- `WorkspaceStatus`：状态文字、图标和语义颜色。
- `WorkspaceEmptyState` / `WorkspaceErrorState`：统一空数据、首次失败和 stale 数据展示。
- `WorkspaceMoreMenu`：移动端行操作收纳。

这些组件只负责展示与交互外壳，不持有业务请求、权限判断或数据库状态；业务页面继续负责调用现有 API 和服务。

## 数据与错误边界

- 本次改造不改变 API 请求路径、请求体、响应字段或 SSE 协议。
- 页面必须区分首次加载失败与已有数据刷新失败；已有数据刷新失败时保留旧数据并标记可能过期。
- 异步请求采用代次或卸载保护，迟到响应不能覆盖新页面状态。
- 写操作在按钮层和 handler 层都保留权限/配置门禁。
- 错误文案不得输出 Key、密码、Provider secret、完整请求体或内部 URL。

## 实施顺序

1. 设计变量、Element Plus 主题映射、基础工作台组件和暗色主题。
2. 全局 App Shell、窄侧栏、管理控制台入口、登录/注册页。
3. AI 对话工作台和会话导航。
4. 模型中心和 Developer API 资源页。
5. 系统管理页面的统一表格、查询、弹窗和状态样式。
6. 移动端、响应式边界、暗色回归和视觉清理。

每一步都保持后端不变，并在进入下一步前完成构建和页面回归。

## 验收标准

- 前端生产构建成功，现有插件测试通过。
- 桌面端 1440px、平板端和移动端 390px/320px 无横向溢出、遮挡或不可操作控件。
- AI 对话普通响应、流式响应、历史会话、停止、失败和重试功能不回归。
- 模型中心和 Developer API 的权限、秘密字段、状态和写操作行为不回归。
- 管理控制台的动态菜单、权限指令、标签页、锁屏和暗色模式不回归。
- 关键页面在首次加载、空数据、刷新失败、配置缺失和网络错误时均有明确状态。
- 视觉回归截图体现统一青绿色设计变量、轻边框层级、紧凑侧栏和 Yuxi 风格的 AI 工作区。
