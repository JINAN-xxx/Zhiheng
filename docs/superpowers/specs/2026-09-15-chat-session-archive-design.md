# 对话归档设计

用户已确认：归档从常用列表移出，在已归档中查看，可恢复继续对话；保留永久删除。项目结构整理暂停。

数据库范围：当前部署使用 PostgreSQL，用户确认本功能按 PostgreSQL 验收，不继续扩展 MySQL 兼容工作。仓库遗留 MySQL 配置的清理归入已暂停的结构整理。

## 行为

- 侧栏提供“最近会话 / 已归档”切换与分页；菜单提供归档、恢复、重命名、永久删除。
- 归档只修改现有 `AiChatSession.status`，消息、运行记录、模型绑定均保留，不需要数据库迁移。
- 归档当前对话后返回新对话；查看已归档对话时保留历史阅读，输入区域显示恢复入口。
- 恢复后重新进入最近会话，可在原会话继续发送。新建对话切回最近会话。
- 归档和恢复必须检查当前用户所有权。其他用户的会话与不存在的会话均返回 404。
- pending/running 会话不能归档，返回 `CHAT_SESSION_BUSY`。归档会话不能发送新消息，返回明确的 409 错误。
- 重复提交相同状态保持幂等，不反复修改更新时间。永久删除仍需用户二次确认。

## 接口与状态

- `GET /ai/chat/session/list?status=active|archived&pageNum=1&pageSize=20`，默认 active，分页总数基于用户与状态过滤。
- `PATCH /ai/chat/session/{session_id}/status`，请求 `{ "status": "archived" }` 或 `{ "status": "active" }`，返回更新后的 `PlatformSessionModel`。
- 状态更新沿用所有权行锁、事务回滚、操作审计。保留现有重命名与删除接口。
- 前端加载按请求代次丢弃迟到响应；切换状态时清空旧列表；归档、恢复、删除成功后失效旧请求并刷新当前页，必要时回退一页。
- 当前阅读页通过已确认的状态变更同步恢复状态；打开会话时以详情接口状态为准。
