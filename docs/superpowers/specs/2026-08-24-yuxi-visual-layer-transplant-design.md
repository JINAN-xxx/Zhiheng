# 智衡平台 Yuxi 视觉层移植设计

## 文档状态

本文定义智衡平台前端下一阶段的视觉统一方案。主题架构、整体界面结构、组件交互、实施范围和验收标准已于 2026-08-24 经用户确认。

参考项目为 [Yuxi](https://github.com/xerrors/Yuxi)。Yuxi 使用 MIT License，本项目可以复用和修改其视觉 Token 与样式模式，但必须保留许可证和版权声明。

本文是以下既有设计的增量修订：

- 延续 `2026-08-21-ant-design-vue-full-migration-design.md` 中保留业务层、迁移视觉组件体系的方向。
- 延续 `2026-08-24-frontend-layout-unification-design.md` 中的中文工作台、紧凑信息架构和业务验收要求。
- 替代上述文档中“深色侧栏”“智衡自定义青绿色主题”以及“只借鉴、不直接复用 Yuxi Token”的视觉决策。

后端接口、数据库、权限码、路由、Pinia 状态和业务状态机约束继续有效。

## 背景与问题

当前前端已经完成 Ant Design Vue 核心页面迁移和 AI 最小业务闭环，但实际视觉只部分接近 Yuxi：

- 当前主色是偏绿色的 `#2F7E78`，与 Yuxi 的青蓝色 `#046A82` 不一致。
- AI 工作台采用深青黑侧栏，而 Yuxi 默认使用浅色侧栏和低对比边界。
- `workspace.scss`、`variables.module.scss` 和旧 RuoYi 全局样式同时定义颜色，主题来源不唯一。
- 旧全局样式仍保留 `#409EFF`、`#20B2AA`、`#42B983` 等蓝色和绿色硬编码值。
- 核心 AI 页面已经使用工作台变量，但管理页面和低频工具页面仍可能呈现旧 RuoYi 视觉。
- Ant Design Vue 与剩余 Element Plus 页面没有完全共享同一套语义 Token。

因此，本阶段不能只替换一个主色，而要移植完整视觉层，建立唯一主题来源。

## 已确认方案

采用“完整移植 Yuxi 视觉层，保留智衡业务层”的方案。

直接复用或等价移植：

- Yuxi 浅色与暗色 Token。
- 浅色侧栏、顶部栏和页面表面层级。
- Ant Design Vue 主题映射。
- 字体层级、间距、圆角、边框和阴影规则。
- 列表、表格、表单、按钮、状态标签和空状态样式。
- hover、focus、disabled、loading、selected 和 error 交互状态。

继续保留：

- “智衡平台”名称、Logo 和品牌资源。
- 当前路由、菜单、权限、接口、SSE、Pinia 和业务组件逻辑。
- 智能对话、模型中心、开发接入、用量记录和管理后台功能。

不直接复制 Yuxi 的业务页面、接口调用、路由、状态管理、品牌名称、Logo 或业务资源。

## 备选方案与取舍

### 方案一：只替换颜色 Token

工作量最小，但无法消除深色侧栏、旧页面结构和硬编码颜色造成的混搭感，不采用。

### 方案二：完整移植视觉层，保留业务组件

视觉一致性高，同时不触碰已经验证的业务链路。主题、组件皮肤和页面壳可以独立验证，是本次采用的方案。

### 方案三：直接移植 Yuxi 页面组件

需要重写接口、路由、权限和状态适配，工作量接近重新开发前端，并会显著提高业务回归风险，不采用。

## 视觉 Token

### 浅色主色

以 Yuxi `base.css` 为准：

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--main-700` | `#046A82` | 主按钮、选中态、关键链接、焦点 |
| `--main-600` | `#24839A` | hover、次级强调 |
| `--main-500` | `#3996AE` | 图表、图标、普通强调 |
| `--main-50` | `#E1F6FB` | 菜单选中、浅提示背景 |
| `--main-30` | `#F7FBFD` | 主色弱分区 |
| `--main-5` | `#FCFEFE` | 浅色侧栏 |

`--main-color` 固定映射到 `--main-700`。平台不再向普通用户提供任意主题色选择，避免主题变量和 Yuxi Token 冲突。

### 浅色中性色

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--gray-0` | `#FFFFFF` | 页面和主要内容表面 |
| `--gray-10` | `#FBFCFC` | 次级表面 |
| `--gray-25` | `#F8FAFA` | 弱分区 |
| `--gray-50` | `#F5F7F7` | 应用背景、hover |
| `--gray-150` | `#EEF0F0` | 轻边框、分割线 |
| `--gray-200` | `#E4E6E6` | 输入框和强调边框 |
| `--gray-500` | `#979999` | 占位和禁用文本 |
| `--gray-600` | `#697070` | 次要说明文本 |
| `--gray-900` | `#1E1F1F` | 正文 |
| `--gray-1000` | `#151616` | 标题和主要文本 |

### 语义色

- 成功：`#52C41A`，浅背景 `#E6F7E6`，深文字 `#389E0D`。
- 错误：`#FF4D4F`，浅背景 `#FFF2F0`，深文字 `#CF1322`。
- 警告：`#FAAD14`，浅背景 `#FFFBE6`，深文字 `#D48806`。
- 信息：`#1890FF`，浅背景 `#E6F7FF`，深文字 `#096DD9`。
- 辅助青色：`#13C2C2`，只用于少量补充强调，不替代主色。

状态色只表达状态，不作为装饰色。状态必须同时有文字或图标。

### 暗色模式

以 Yuxi `base.dark.css` 为准：

- 页面背景：`#030303`。
- 侧栏背景：`#141414`。
- 内容容器：`#1F1F1F`。
- 浮层：`#262626`。
- 暗色主色：`#4A9FB8`。
- 主要文字：`#FFFFFF`。
- 次要文字：`rgba(255, 255, 255, 0.65)`。
- 三级文字：`rgba(255, 255, 255, 0.45)`。

暗色模式覆盖同名语义 Token，不在业务组件中写死浅色值，也不使用简单反色滤镜。

## 主题架构

### 唯一 Token 来源

建立独立的 Yuxi Token 文件，包含浅色和暗色定义。`workspace.scss` 不再拥有另一套品牌色，只保留布局变量、兼容别名和平台公共样式。

当前 `--workspace-*` 在迁移期作为兼容别名：

```text
--workspace-main           -> --main-color
--workspace-main-deep      -> --main-800
--workspace-main-soft      -> --main-50
--workspace-bg             -> --gray-50
--workspace-surface        -> --gray-0
--workspace-surface-muted  -> --gray-10
--workspace-border         -> --gray-150
--workspace-text           -> --color-text
```

新组件直接使用 Yuxi 语义 Token；旧组件通过兼容别名逐步收敛。完成迁移后再评估是否删除 `--workspace-*`，本轮不强制机械替换全部引用。

### Ant Design Vue 映射

平台唯一 `ConfigProvider` 映射：

- `colorPrimary`、hover、active 和 focus ring。
- 页面、容器、浮层和遮罩背景。
- 主文字、次文字和禁用文字。
- success、warning、error 和 info。
- 圆角、控件高度、字号和行高。
- Menu、Table、Form、Input、Select、Tabs、Drawer、Modal、Pagination 和 Tooltip 组件 Token。

业务页面不得再次创建局部品牌主题。

### Element Plus 兼容层

剩余 Element Plus 页面在迁移完成前继续运行，但其 `--el-*` 变量映射到同一套 Yuxi Token。兼容层只解决视觉一致性，不作为长期保留双组件库的理由。

## 全局界面结构

### 浅色侧栏

- 桌面展开宽度保持约 `184px`，收起宽度保持 `56px`。
- 浅色背景使用 `--main-5`，右侧使用 `--gray-150` 边框。
- 普通菜单使用主要或次要文字色，不使用深色反白文字。
- 选中菜单使用 `--main-50` 背景、`--main-700` 文字和图标。
- hover 使用 `--gray-50` 或 `--main-30`，不位移、不缩放。
- 品牌区继续显示智衡名称和 Logo。
- 最近会话与管理后台入口保留当前功能和权限边界。

暗色模式下侧栏使用 Yuxi `#141414`，而不是当前深青灰自定义色。

### 顶部栏

- 高度保持约 `54px`。
- 浅色模式使用白色背景和 `--gray-150` 底边。
- 只展示当前位置、消息、用户和必要工具，不重复页面标题。
- 普通工具按钮使用中性色，hover 才使用主色或浅主色背景。
- 普通顶栏不使用装饰阴影。

### 内容区

- 页面背景使用 `--gray-50`，主要数据表面使用 `--gray-0`。
- 桌面页面间距使用 `24px` 或 `30px`，平板 `18px`，移动端 `14px`。
- 页面标题 `20px` 至 `24px`、字重 `600`。
- 分组标题 `16px` 至 `18px`、字重 `600`。
- 正文 `14px` 至 `15px`；辅助说明 `12px` 至 `13px`。
- 字间距固定为 `0`，不按视口缩放字体。

## 组件与交互

### 表面与列表

- 普通内容表面使用白色、`1px solid var(--gray-150)` 和 `8px` 圆角。
- 普通卡片、页面分区和列表不使用阴影。
- 阴影只用于抽屉、弹窗、下拉菜单和 Tooltip 等真实浮层。
- 同类资源优先放入一个列表容器并使用行分割线，不把每一行包装成独立卡片。
- 内部 ID 默认隐藏，需要排障或开发接入时再展示，并提供复制入口。

### 按钮与图标

- 同一区域只允许一个高权重主按钮。
- 主按钮使用 `--main-700`；普通操作使用中性按钮、文本按钮或图标按钮。
- 搜索、刷新、复制、删除和更多操作使用已有 Ant Design 图标。
- 图标尺寸使用 `16px`、`18px` 或 `20px`，图标按钮提供 tooltip 或可访问名称。
- 控件高度主要使用 `32px` 或 `36px`，loading 状态不得改变按钮宽度。

### 表单

- 输入框、选择器和数值控件主要使用 `36px` 高度和 `6px` 圆角。
- label 稳定显示，placeholder 只提供输入示例。
- helper text 放在字段下方，说明业务影响、范围或单位。
- 错误信息说明修复方式，不输出秘密或内部实现细节。

### 表格与状态

- 表头使用 `--gray-10` 或 `--gray-25` 背景。
- 行高保持约 `44px` 至 `48px`。
- 行内操作保持紧凑，低频操作收进“更多”菜单。
- 成功、错误、警告、信息和普通状态使用浅背景加深文字。
- 正常状态保持安静，只突出异常和需要用户行动的状态。

### 异步与错误状态

- 初次加载保持布局尺寸稳定。
- 空状态说明当前没有什么，并提供唯一的下一步操作。
- 首次加载失败与已有数据刷新失败必须区分。
- 已有数据刷新失败时保留旧数据并标记可能过期。
- hover、focus、disabled、loading、selected、error 和键盘焦点状态必须完整。

## 页面范围

### 本轮结构与视觉完整迁移

- `PlatformSidebar`、`AdminSidebar`、`PlatformTopbar`、TagsView 和移动端抽屉。
- 智能对话。
- 模型中心。
- 开发接入与 Developer API Key。
- 用量记录。
- 登录、注册、锁屏、401 和 404。
- 设置面板和常用管理后台页面。

### 本轮兼容性处理

代码生成器、复杂 Cron、编辑器和其他低频旧页面暂不重写信息架构，只要求：

- 使用统一 Token。
- 不出现明显的旧蓝色或绿色主题。
- 不出现重阴影、大圆角和浅色/暗色穿帮。
- 不产生新的横向溢出和控件重叠。

## 业务与安全边界

- 不改变 API 路径、方法、请求体、响应字段和 SSE 协议。
- 不改变 Vue Router、Pinia、Axios、动态菜单和 RBAC。
- 不改变模型接入、Developer Key、Quota、Usage、Chat、Embedding 和 Rerank 业务状态机。
- 完整 Key 和 Credential 仍只在允许的单次结果中展示，不因视觉迁移进入 DOM 缓存、URL、日志或错误详情。
- 删除、吊销、停用等危险操作继续保留明确文案和确认步骤。
- Yuxi 品牌名、Logo、插画和业务资源不得进入智衡产品。
- 仓库保留 Yuxi MIT License 和来源说明。

## 实施顺序

1. 建立 Yuxi 浅色、暗色 Token 和许可证来源说明。
2. 映射 Ant Design Vue 与 Element Plus 兼容变量。
3. 将全局壳改为 Yuxi 浅色侧栏、白色顶栏和冷灰内容区。
4. 统一智能对话、模型中心、开发接入和用量记录。
5. 统一登录与常用管理页面。
6. 清理会覆盖新主题的旧全局硬编码颜色和阴影。
7. 为低频旧页面补齐 Token 兼容和暗色边界。
8. 完成真实页面截图、业务回归、构建和体积检查。

每个阶段使用职责单一的提交，保持可审查和可回滚。视觉迁移不得夹带后端或业务重构。

## 风险与控制

### 旧全局样式覆盖

旧 RuoYi 样式包含大量高优先级选择器和硬编码颜色。先建立 Token 与组件主题，再按真实页面命中顺序清理，不执行无法审查的全局替换。

### 双组件库过渡

核心页面继续以 Ant Design Vue 为准。Element Plus 只通过兼容 Token 保证低频旧页面不穿帮，不新增新的 Element Plus 业务页面。

### 暗色模式回归

所有新增颜色必须来自同名 Token。第三方编辑器、代码块和图表需要单独验证暗色配置，不依赖父容器反色。

### 视觉复制与品牌边界

复用 Yuxi 的 MIT 视觉 Token 和通用样式规则，保留许可说明；不复制其品牌资源和业务内容，智衡品牌仍是第一视觉信号。

### 业务回归

页面重构只调整模板结构、样式和展示组件，不改变接口与状态机。每个核心页面使用现有真实业务流程和自动化契约进行前后对照。

## 完成定义

- 平台主题只有一套 Yuxi Token 来源。
- 核心工作台视觉层接近 Yuxi，同时保持智衡品牌和业务契约。
- 浅色侧栏、顶部栏、页面、列表、表单、状态和暗色模式形成统一系统。
- 核心路径无旧 RuoYi 蓝色、绿色、重阴影和组件库混搭感。
- 低频旧页面至少完成 Token 兼容，不破坏当前功能。
- 四个视口、明暗主题、关键边界状态和真实业务链路通过验收。
