# 智能体扩展与技能管理设计

## 1. 背景

智衡平台当前已有模型中心、智能对话和开发接入，但缺少统一的智能体扩展目录，也没有可由平台管理员维护、普通用户在对话中选择的技能资源。

本设计参考 Yuxi 的信息架构与 Skill 管理交互，在智衡现有插件机制内新增独立的 `agent_extension` 插件。第一期只实现平台共享技能的管理闭环和对话选择能力。知识库由其他开发人员并行建设，本期只约定集成位置，不修改其业务实现。

## 2. 目标

第一期必须实现以下闭环：

1. 新增“智能体扩展”一级菜单及“技能管理”子菜单。
2. 管理员可上传、确认安装、查看、启用、停用和删除平台共享技能。
3. 普通用户可查看已授权技能，并在智能对话中通过 `@` 选择已启用技能。
4. 所选技能只作用于当前发送的消息，不成为会话永久配置。
5. 技能指令参与现有流式对话请求，但不改变流式响应协议。
6. 技能文件在容器重建后仍然存在，并兼容 PostgreSQL 与 MySQL。
7. 页面复用现有主题变量，与模型中心和开发接入保持一致。

## 3. 非目标

第一期不实现以下能力：

- 普通用户上传或安装个人技能。
- 部门级、用户级共享范围配置。
- 在线编辑技能文件或创建技能目录。
- 从 GitHub、ModelScope、skills.sh 等远程来源安装。
- 执行技能包内脚本或自动安装 Python、Node.js 等依赖。
- 沙盒挂载、动态工具加载和技能依赖编排。
- 技能版本覆盖升级、版本回滚和市场分发。
- 知识库、工具管理和 MCP 服务的业务实现。

## 4. 信息架构

最终菜单结构为：

```text
智能体扩展
├── 技能管理
├── 知识库
├── 工具管理
└── MCP 服务
```

第一期只交付“技能管理”。知识库子菜单在知识库功能合并时注册，不创建不可用的占位路由。工具管理和 MCP 服务只保留未来的排序与命名约定。

`agent_extension/plugin.yaml` 是智能体扩展菜单的唯一声明入口，由集成人员统一维护。各业务模块不分别创建同名一级菜单，避免动态菜单重复。

新增独立后端插件和对应前端插件：

```text
ruoyi-fastapi-backend/plugins/agent_extension/

│   └── skill_controller.py
├── dao/
│   └── skill_dao.py
├── domain/

│   └── skill_package.py
├── entity/
│   ├── do/skill_do.py
│   └── vo/skill_vo.py
```

职责约束：

- `agent_extension` 拥有技能元数据、文件存储、包校验、管理接口和可用技能查询。
- `ai` 插件只在对话请求中接收技能标识并消费解析后的技能上下文。
- `ai` 插件不得直接读取技能物理目录或查询技能表。
- 知识库代码放在独立 `knowledge` 业务目录，仅在集成阶段修改统一菜单清单。

## 6. 运行时解耦

两个插件不建立循环依赖。`agent_extension` 启动时在应用状态中注册无状态的技能上下文提供器；`ai` 插件在处理带 `skillSlugs` 的请求时使用该提供器。

提供器接口语义为：

```python
resolve_enabled_skills(db, user_id, skill_slugs) -> ResolvedSkillContext
```

提供器负责：

- 校验技能数量、存在性、启用状态和使用权限。
- 读取并限制技能内容。
- 返回用于模型请求的结构化上下文与用于历史展示的技能快照。

技能插件未安装、未启用或提供器不可用时：

- 不带技能的普通对话继续工作。
- 带技能的请求返回固定的“技能服务暂不可用”错误。
- AI 插件不自行降级为忽略技能，以免用户误以为技能已经生效。

## 7. 数据模型

### 7.1 技能主表

表名：`agent_skill`

| 字段 | 说明 |
| --- | --- |
| `skill_id` | 平台技能编号，使用资源型字符串 ID |
| `skill_slug` | 稳定标识，只允许小写字母、数字和短横线，唯一 |
| `skill_name` | 中文展示名称 |
| `description` | 技能说明 |
| `version` | 技能内容版本字符串 |
| `status` | `enabled` 或 `disabled` |
| `storage_path` | 相对于技能存储根目录的安全路径 |
| `content_hash` | 技能包内容的 SHA-256 摘要 |
| `metadata_json` | 经过白名单解析的扩展元数据 |
| `lock_version` | 状态更新使用的乐观锁版本 |
| `created_by` | 创建人 |
| `created_at` | 创建时间 |
| `updated_by` | 更新人 |
| `updated_at` | 更新时间 |

`skill_slug` 建立唯一约束，`status` 建立检查约束和查询索引。时间字段沿用项目现有数据库时区规范，写入数据库前统一转换为无时区时间值。

### 7.2 对话消息快照

在平台对话消息表新增 `skill_snapshots` JSON 字段，用户消息保存：

```json
[
  {
    "slug": "deep-research",
    "name": "深度研究"
  }
]
```

该字段只保存标识和发送时名称，不保存完整技能内容。技能后续停用或删除后，历史消息仍能展示当时选择的技能。

## 8. 文件存储

默认存储根目录：

```text
data/agent-skills/
├── .drafts/
├── .trash/
└── skills/
    └── <skill_slug>/
        ├── SKILL.md
        ├── references/
        └── assets/
```

通过 `AGENT_SKILL_DATA_DIR` 覆盖默认路径。Docker Compose 必须将该目录挂载为持久卷，后端容器重建不能清除技能文件。

准备阶段将文件解压到 `.drafts/<draft_id>`，并写入包含上传人、解析结果、过期时间和摘要的服务端元数据。草稿 ID 使用高熵随机值，不信任客户端回传的路径和元数据。

确认安装阶段执行：

1. 重新验证草稿归属、有效期、内容摘要和目标标识。
2. 在数据库事务内检查同名技能。
3. 将草稿目录原子移动到正式目录。
4. 写入技能记录并提交事务。
5. 数据库失败时移除已经移动的正式目录。

删除阶段先将正式目录原子移动到 `.trash`，数据库删除提交后再清理垃圾目录；数据库失败时恢复原目录。

过期草稿和残留垃圾目录在插件启动时进行有界清理。

## 9. 技能包规范与安全边界

支持以下上传格式：

- 单个 `SKILL.md` 文件。
- 根目录包含 `SKILL.md` 的 `.zip` 技能包。

`SKILL.md` 使用 YAML front matter 描述元数据，至少包含稳定标识、展示名称和说明。示例：

```markdown
---
name: deep-research
display_name: 深度研究
description: 为复杂主题制定研究计划并生成结构化报告。
version: 1.0.0
---

# 工作方式

按照研究计划分解问题，核对事实并形成结论。
```

校验规则：

- 上传文件最大 10MB。
- 解压后总大小最大 30MB。
- 最多包含 200 个文件。
- 单个 `SKILL.md` 最大 128KB。
- 拒绝绝对路径、父目录跳转、空路径、重复路径和大小写冲突路径。
- 拒绝符号链接、硬链接、设备文件和其他非普通文件。
- 压缩包必须只有一个有效技能根目录。
- 不执行脚本，不解析可执行依赖，不接受客户端指定的存储路径。
- 同名技能不覆盖，管理员必须先停用并删除旧技能。

第一期可随插件交付少量纯提示词内置技能。内置技能可查看和启停，但不可删除；普通上传技能可在停用后删除。

## 10. 权限模型

权限标识：

```text
agent_extension:skill:list
agent_extension:skill:query
agent_extension:skill:add
agent_extension:skill:edit
agent_extension:skill:remove
agent_extension:skill:use
```

权限分配：

| 角色 | 能力 |
| --- | --- |
| 平台管理员 | 列表、详情、上传、确认安装、启停、删除、对话使用 |
| 普通用户 | 查看可用技能、查看允许公开的详情、对话使用 |

管理接口同时校验登录态和对应按钮权限。普通用户使用独立的可用技能接口，该接口只返回已启用技能，不暴露存储路径、完整文件内容和内部元数据。

## 11. 管理接口

接口前缀为 `/agent_extension/skills`。下划线与插件 ID 保持一致，以满足插件运行时的控制器命名空间约束。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/agent_extension/skills` | 管理列表，支持关键词、状态和分页 |
| `GET` | `/agent_extension/skills/{skill_id}` | 获取技能详情 |
| `GET` | `/agent_extension/skills/{skill_id}/content` | 获取经过大小限制的主文件内容 |
| `POST` | `/agent_extension/skills/import/prepare` | 上传并解析技能包 |
| `POST` | `/agent_extension/skills/import/{draft_id}/confirm` | 确认安装 |
| `PUT` | `/agent_extension/skills/{skill_id}/status` | 启用或停用 |
| `DELETE` | `/agent_extension/skills/{skill_id}` | 删除已停用的非内置技能 |
| `GET` | `/agent_extension/skills/available` | 获取当前用户可在对话中使用的技能 |

所有响应继续使用平台现有统一响应模型。分页字段同时遵守当前前端使用的别名契约，避免再次出现 `pageNum`、`pageSize`、`hasNext` 字段不匹配。

## 12. 管理页面

页面采用已确认的精简卡片布局：

- 左侧菜单展开“智能体扩展”，当前子菜单为“技能管理”。
- 页面标题只显示“技能管理”，不增加大段功能说明。
- 管理员右上角显示“上传技能”，普通用户不显示。
- 工具栏只保留搜索、状态筛选和总数。
- 卡片只展示中文名称、用途、状态和“查看”入口。
- 英文标识、版本、文件结构和标准文件名只在详情页展示。
- 详情页提供基本信息、主文件只读预览以及管理员操作。
- 启用状态只能停用；停用状态可以启用或删除。

页面不得定义独立品牌色。全部复用现有主题变量：

```text
页面背景        var(--bg-layout)
内容背景        var(--bg-container)
边框            var(--gray-150)
主文字          var(--color-text)
辅助文字        var(--color-text-secondary)
品牌与选中态    var(--main-*)
状态色          平台现有成功、警告和错误变量
```

本期只验收桌面端布局，不扩大移动端适配范围。

## 13. 上传交互

点击“上传技能”打开两步弹窗：

1. 选择本地 `SKILL.md` 或 `.zip` 文件并上传解析。
2. 展示名称、标识、版本、说明、文件数量和安全校验结果，管理员确认后安装。

解析失败时保持弹窗打开并展示具体原因。确认安装期间禁用关闭和重复提交。安装成功后关闭弹窗、刷新列表，并显示统一成功消息。

## 14. 对话选择与请求协议

智能对话输入区增加 `@` 资源选择器。一期只有“技能”分组，选择结果显示为输入框上方的中文标签，支持多选和单个移除。

请求新增字段：

```json
{
  "sessionId": "session_01",
  "modelId": "mdl_01",
  "clientMessageId": "message_01",
  "message": "分析这份材料",
  "skillSlugs": ["deep-research", "document-summary"]
}
```

规则：

- 每条消息最多选择 5 个技能。
- 同一技能不能重复选择。
- 仅选择当前可用接口返回的已启用技能。
- 发送开始后清空输入文字、图片和技能标签。
- 如果请求在前端校验前失败，沿用现有消息失败恢复行为，不让技能静默生效。
- 历史用户消息显示发送时的技能中文名称。

## 15. 技能上下文注入

后端在解析模型并构建消息列表前完成技能校验。技能正文总量最大 32KB，超限时拒绝请求并返回超限技能名称。

技能只注入当前模型调用的系统上下文，格式采用明确边界：

```text
<selected_skills>
  <skill name="深度研究" slug="deep-research">
    ...经过校验的 SKILL.md 正文...
  </skill>
</selected_skills>
```

系统上下文组装顺序为：

1. 平台基础约束。
2. 当前消息选择的技能。
3. 用户配置的系统提示词。
4. 历史对话和本次用户消息。

过去消息保存的技能快照不重新注入，因此技能严格按消息生效。流式事件、助手消息持久化和会话标题逻辑保持现状。

## 16. 错误处理

后端使用固定公开错误，不泄露物理路径、压缩包内部异常或系统堆栈：

| 场景 | 用户提示 |
| --- | --- |
| 技能服务未注册 | 技能服务暂不可用 |
| 技能不存在 | 所选技能不存在，请重新选择 |
| 技能已停用 | 所选技能已停用，请重新选择 |
| 数量超限 | 每条消息最多选择 5 个技能 |
| 内容超限 | 所选技能内容过大，无法用于本次对话 |
| 同名安装 | 技能标识已存在 |
| 非法压缩包 | 技能包格式不正确或包含不安全文件 |
| 删除启用技能 | 请先停用技能再删除 |
| 删除内置技能 | 内置技能不能删除 |

前端统一提取结构化错误消息，禁止再次出现 `[object Object]`。

## 17. 多人协作约定

- `agent_extension/plugin.yaml` 和顶级菜单结构由集成人员维护。
- Skill 模块只修改 `skill` 相关文件。
- 知识库模块只修改 `knowledge` 相关文件。
- 新增子菜单时采用固定排序：知识库 1、技能管理 2、工具管理 3、MCP 服务 4。
- 本期 Skill 实现不创建知识库占位组件和虚假接口。
- AI 对话桥接集中在单独适配文件，避免 Skill 服务逻辑进入 `platform_chat_service.py`。
- 数据库迁移编号分别由插件内部管理；AI 消息快照迁移仍归 AI 插件所有。

## 18. 测试策略

### 18.1 后端单元测试

- Markdown 与 ZIP 正常解析。
- 路径穿越、符号链接、重复路径、文件数量和大小限制。
- 同名安装冲突与并发确认。
- 启用、停用和仅停用后删除的状态机。
- 内置技能禁止删除。
- 普通用户不能调用管理写接口。
- 可用技能接口只返回已启用技能。
- 技能数量、存在性、状态和正文总量校验。
- 文件操作失败时数据库回滚，数据库失败时文件补偿恢复。

### 18.2 后端集成测试

- PostgreSQL 与 MySQL 迁移结构一致。
- 上传、确认安装、容器目录持久化、启停和删除完整链路。
- 对话请求正确注入技能内容并保存技能快照。
- 历史查询返回技能名称快照。
- 未选择技能时现有对话行为完全不变。
- 技能服务不可用时仅带技能请求失败。

### 18.3 前端测试

- 管理员和普通用户按钮可见性。
- 搜索、筛选、空态、加载态和错误态。
- 上传两步流程及重复提交防护。
- 启停和删除按钮随状态正确切换。
- `@` 选择、去重、最多 5 个、移除和发送后清空。
- 历史消息技能标签展示。
- 所有错误使用可读中文消息。
- 页面使用平台主题变量，不包含独立硬编码品牌色。

### 18.4 浏览器验收

- 1280×800 与 1440×900 桌面视口无重叠和横向溢出。
- 浅色、深色主题下文字、边框、状态和选中态可辨识。
- 技能管理列表、详情、上传弹窗和对话选择器截图检查通过。
- 流式回复过程中输入区和技能标签布局不跳动。

## 19. 完成标准

满足以下条件才视为第一期完成：

1. 独立插件可安装、启动、停用并通过插件结构检查。
2. 管理员完成技能上传、确认安装、停用、重新启用和删除。
3. 普通用户无法上传和修改，但可看到并选择已启用技能。
4. 对话携带技能后仍以现有协议流式回复，历史消息显示技能名称。
5. 非法技能包无法进入正式目录或数据库。
6. 后端、前端、迁移和浏览器验收测试通过。
7. 构建后的前端静态产物更新并可由现有部署脚本直接启动。
8. 不包含知识库业务代码，也不覆盖知识库开发人员的未合并改动。

## 20. 已确认决策

- 采用独立 `agent_extension` 插件，而不是继续扩展 `ai` 插件。
- 第一期采用最小管理闭环，不实现在线编辑与远程安装。
- 管理员管理平台共享技能，普通用户只查看和使用。
- 对话通过 `@` 按消息选择技能，每条消息最多 5 个。
- 支持单个 `SKILL.md` 和包含根目录 `SKILL.md` 的 ZIP 包。
- 技能包不执行脚本、不安装依赖。
- 技能列表采用精简中文卡片，不展示英文标识和版本等技术信息。
- 页面颜色完全复用智衡现有主题变量。
