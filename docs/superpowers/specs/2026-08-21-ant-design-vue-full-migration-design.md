# 智衡 AI 前端 Ant Design Vue 全量迁移设计

## 文档状态

本文定义 `feat-litellm-deployment` 分支的前端组件体系与视觉系统全量迁移方案。设计于 2026-08-21 经用户确认。

参考项目为 [Yuxi](https://github.com/xerrors/Yuxi)。本项目借鉴其 AI 工作台优先的信息架构、空间关系和组件语言，保留“智衡 AI”品牌，不复制参考项目的品牌资源或业务实现。

本文替代以下文档中仍允许 Element Plus 长期存在、只调整全局外壳或只覆盖部分业务页面的内容：

- `2026-08-18-yuxi-style-platform-ui-design.md`
- `2026-08-20-ai-workspace-menu-redesign-design.md`

后端接口、数据库、权限码、路由地址和业务状态机相关约束继续有效。

## 问题

现有前端虽然引入了工作台颜色变量并调整了菜单结构，但实际构建结果与已确认的视觉预设差异明显：

- 旧 RuoYi/Element Plus DOM 结构和后台组件形态仍占主导。
- 页面只是换色和重新排版，没有形成统一的 AI 产品体验。
- 登录、对话、资源页面与管理页面缺少一致的空间、组件和状态语言。
- 新工作台外壳与旧业务页面混合，视觉层级、信息密度和交互方式不统一。
- 自动化验收偏重构建成功和无溢出，缺少对预设稿的逐页视觉比较。

该偏差不是构建缓存问题，而是此前实施范围被收窄为全局菜单与外壳，未完整迁移业务页面和组件体系。

## 目标

- 使用 Ant Design Vue 作为唯一业务组件库。
- 最终产物完全移除 Element Plus 的注册、组件、图标、样式和依赖。
- 以已确认的 Yuxi 风格预设稿作为硬性视觉基线。
- 一次性向用户交付完整的新界面，不交付双组件库混搭过渡态。
- 保留现有 Vue Router、Pinia、Axios、动态菜单、RBAC 和 API 契约。
- 覆盖登录、全局壳、AI 对话、模型中心、应用接入、用量和管理控制台。
- 保持流式对话、模型接入、Developer API Key、Embedding 和 Rerank 等业务能力可用。
- 桌面、平板和移动端共享一致的响应式信息架构。

## 非目标

- 不重写后端接口、数据库或权限模型。
- 不复制 Yuxi 的品牌名称、Logo、插画或业务代码。
- 不同时迁移 Vue Router、Pinia 或 Axios。
- 不在视觉迁移中新增知识库、Agent 编排或其他 Yuxi 业务能力。
- 不用全局 CSS 覆盖冒充组件迁移。
- 不长期保留 Element Plus 与 Ant Design Vue 双栈。

## 交付策略

采用“开发分支内分阶段迁移，最终一次切换”的方式。

内部开发允许短期双栈，以便逐页验证和回滚；任何双栈状态都不得作为完成版本合并或部署。最终合并必须满足：

- 所有目标页面均已迁移。
- Element Plus 生产引用为零。
- 真实后端关键流程通过。
- 四个验收视口完成视觉对比。
- 生产构建、权限和浏览器错误检查通过。

迁移使用多个职责单一的提交，而不是一个无法审查的大提交。用户看到的最终交付仍是一次完整切换。

## 视觉系统

### 设计语言

- 使用浅灰应用背景、白色内容表面和低对比边框。
- 主色沿用智衡 AI 青绿色，避免紫色渐变、装饰光球和营销式 Hero。
- 圆角只使用 4px 和 8px，胶囊仅用于状态或明确的分段选择。
- 普通页面区块使用无框或轻边框布局，不堆叠悬浮卡片。
- 信息层级通过字体、间距、边框和表面层次表达，不依赖阴影堆叠。
- 模型 ID、应用 ID、Key 前缀、Provider 和请求标识使用等宽字体。
- 状态同时显示图标或文字，颜色不是唯一信号。
- 所有工具按钮使用 Lucide 或 Ant Design 图标，并提供 tooltip 或可访问名称。

### Ant Design Vue 主题

全局 `ConfigProvider` 负责：

- 品牌色、语义状态色和暗色算法。
- 字体、字号、行高、圆角和控件高度。
- 表格、表单、抽屉、弹窗、菜单和分页 Token。
- 中文语言、日期语言和空状态文案。
- 弹层容器、层级和主题继承。

业务页面不得重复定义另一套品牌色或控件尺寸。

### 响应式规则

- 桌面端使用固定侧栏、紧凑顶栏和可滚动内容区。
- 平板端收窄侧栏和工具条，保持主要操作可见。
- 小于 992px 时主侧栏进入全高抽屉。
- 390px 和 320px 下，低优先级字段隐藏，行操作进入“更多”菜单。
- 固定格式表格和工具条使用稳定网格约束，不允许标题单字竖排或操作重叠。
- `document.documentElement.scrollWidth` 不得超过视口宽度。

## 信息架构

### AI 工作台

```text
AI 工作台
├─ 新建对话
├─ AI 对话
├─ 最近会话
├─ AI 资源
│  ├─ 模型
│  ├─ 应用接入
│  └─ 用量
└─ 管理控制台
```

### 管理控制台

管理控制台继续使用后端动态菜单和现有 RBAC 数据，但使用同一 Ant Design Vue 应用外壳。管理页强调信息密度和可扫描性，不改造成营销页面。

### 默认入口

默认入口继续根据用户权限确定：

1. 有对话权限时进入 AI 对话。
2. 否则进入第一个可访问的 AI 资源页面。
3. 没有 AI 权限时进入第一个可访问的管理页面。
4. 直接 URL、刷新和浏览器返回必须得到一致模式。

## 平台组件架构

### `AntdConfigProvider`

平台唯一主题入口，管理亮暗主题、语言、组件 Token 和弹层挂载。

### `PlatformShell`

负责 AI/管理模式、桌面侧栏、移动抽屉、顶栏和主内容滚动边界，不持有业务数据。

### `WorkspacePage`

统一页面标题、说明、状态、工具条、内容宽度和刷新时间。

### `ResourceTable`

统一模型、部署、应用、Key、用户、角色和审计资源的列表语言。支持桌面表格、移动精简列、空态、过期数据和分页。

### `ResourceDrawer`

统一创建、编辑、接入和详情流程。负责稳定宽度、移动全屏、操作区和关闭确认，不持有业务 API。

### `AsyncState`

统一首次加载、空数据、失败、过期数据、配置缺失和重试。已有数据刷新失败时保留旧数据并标记可能过期。

### `PermissionAction`

复用现有权限码，同时提供模板可见性、禁用状态和 handler 入口防线。隐藏按钮不能替代后端鉴权。

### `SecretField`

专门处理 Credential 和 API Key：

- 秘密字段不回填。
- 完整 Key 只在创建或轮换结果中展示一次。
- 不写入 URL、本地缓存、重复提交缓存、日志或错误详情。
- 上传型秘密执行大小、类型、字符和竞态检查。

### 公共能力适配

迁移期间建立薄适配层，将现有全局能力映射到 Ant Design Vue：

- 消息、通知、确认框和 Loading。
- 分页、上传、图片预览和字典标签。
- 表单校验、日期选择和状态展示。
- 动态菜单、权限指令和用户菜单。

适配层不复制业务状态，也不改变 API 请求。

## 页面设计

### 登录与注册

- 移除当前大幅照片和白色表单墙组合。
- 使用简洁品牌入口、克制背景和居中认证区域。
- 保留验证码、记住密码、注册入口、错误提示和重定向。
- 移动端表单宽度受视口约束，不出现横向滚动。

### AI 对话

- 最近会话、搜索、新建、切换和归档位于工作台导航区域。
- 消息区使用连续流式布局，不将每条消息包成装饰卡片。
- 输入区固定于内容底部，支持发送、停止、附件和快捷键。
- 保留 Markdown、代码、思考过程、用量、流式光标、失败和重试。
- 新请求开始时清理旧 Run 标识，取消请求不得指向上一轮运行。
- 移动端通过抽屉访问会话历史。

### 模型中心

- Platform Model、部署、凭据和 Runtime 状态保持既有业务边界。
- Chat、Embedding 和 Rerank 能力以统一能力标签和筛选呈现。
- 接入流程使用分步抽屉，保留失败前已成功资源，不做自动补偿删除。
- 列表、详情、连接测试、发布和停用保持现有权限及安全门禁。

### 应用接入与 Developer API

- 应用、Developer Key、授权模型和用量采用统一资源视图。
- 创建、轮换、吊销和授权继续遵守一次性秘密展示与审计约束。
- 未配置、无权限、网络失败和上游失败必须可区分。
- Key 创建所需模型权限必须与按钮可见性一致。

### 用量

- 先选择用户可访问的应用，再展示调用台账。
- 使用稳定筛选、时间范围、统计摘要和调用明细布局。
- 不新增后端聚合契约。

### 管理控制台

- 迁移用户、角色、菜单、字典、配置、日志、监控、文件、插件和代码生成等现有页面。
- 统一查询区、操作区、表格、分页、抽屉和弹窗。
- 动态路由、标签页、锁屏、暗色模式和权限指令继续可用。
- 管理页保持高信息密度，不使用大标题、插画或卡片墙。

## 数据、错误与安全边界

- 不改变 API 路径、方法、请求体、响应字段和 SSE 协议。
- 异步页面请求使用代次或卸载保护，迟到响应不得覆盖新状态。
- 首次失败和刷新失败必须区分。
- 已知配置缺失状态在刷新 pending 和普通网络错误期间继续保持写操作门禁，仅成功响应解除。
- 业务失败保留用户输入和已成功资源，重试前执行安全对账。
- 错误文案不得输出 Credential、API Key、认证头、完整请求体或内部 URL。
- Element Plus 移除不得改变后端稳定错误码或权限状态映射。

## 迁移顺序

1. 建立 Ant Design Vue 主题、基础组件和截图基线。
2. 迁移登录、注册和全局应用外壳。
3. 迁移 AI 对话、会话历史和流式状态。
4. 迁移模型中心、Embedding/Rerank、凭据和部署接入。
5. 迁移应用、Developer API Key、授权模型和用量。
6. 迁移管理控制台页面与公共组件。
7. 替换全局消息、弹窗、上传、分页、字典和权限相关能力。
8. 删除 Element Plus 注册、样式、图标和依赖。
9. 完成真实后端联调、视觉对比、暗色和权限组合回归。
10. 将完整迁移结果一次合并到目标分支。

每一步使用独立提交并保持可回滚。未完成迁移的内部提交不部署为用户验收版本。

## 测试与验证

### 静态和单元测试

- 主题 Token 与亮暗模式。
- 路由模式、默认入口和动态菜单解析。
- 权限动作、异步状态和秘密字段转换。
- SSE 解析、停止、失败和重试。
- 模型接入、应用 Key 和 Embedding/Rerank 前端契约。
- Element Plus import、标签和 CSS 引用最终为零。

### 组件与集成测试

- 表单校验、抽屉关闭和用户输入保留。
- 首次失败、过期数据、配置缺失和迟到响应。
- 权限最小集合不触发越权 API。
- 完整 Key 只展示一次，关闭后不再存在于 DOM。
- 管理动态菜单、标签页和权限指令可用。

### Playwright 视觉验收

固定验证 `1440px`、`1024px`、`390px` 和 `320px`：

- 登录与注册。
- AI 对话空态、历史消息、流式响应、失败和停止。
- 模型中心四类视图与接入抽屉。
- 应用、Key 一次性展示、授权模型和用量。
- 用户、角色、菜单、审计和监控代表页面。
- AI/管理模式往返、侧栏折叠和移动抽屉。
- 亮色、暗色、空态、失败和过期状态。

预设稿是硬性基线。验收比较页面结构、空间比例、字体层级、控件形态、色彩和信息密度，不能用“构建成功”代替视觉一致性。

所有场景要求：

- 无文档级横向溢出。
- 无文本、按钮或弹层重叠。
- 浏览器 console error 和 page error 为零。
- 真实后端关键请求成功。

### 构建验证

- 前端插件测试通过。
- 生产构建通过。
- Element Plus 不出现在生产依赖和构建产物中。
- 现有后端 AI 与权限回归通过。
- `git diff --check` 通过。

## 风险与控制

### 迁移规模

当前大量业务文件直接使用 Element Plus。通过平台组件、公共适配层和按域提交控制风险，不执行无审查的机械全局替换。

### 双栈样式污染

双栈只允许存在于迁移分支的内部阶段。Ant Design Vue 主题必须限定入口，最终删除 Element Plus CSS 后重新完成全量视觉回归。

### 业务回归

视觉迁移不修改 API 和状态机。每个业务域在迁移前建立关键流程回归，迁移后使用相同契约验证。

### 大包体

迁移期间监控构建产物。最终删除 Element Plus 后比较 JS/CSS 体积，并保持路由级异步加载。

### 长分支漂移

迁移使用独立提交并定期同步目标分支。最终合并前冻结其他前端视觉改动，解决冲突后重新执行完整验证。

## 完成标准

- 登录、全局壳、AI 对话、模型、应用、用量和管理控制台均达到预设稿视觉标准。
- Ant Design Vue 是唯一业务组件库。
- Element Plus 注册、组件、图标、CSS、依赖和产物引用全部移除。
- 现有路由、Pinia、Axios、API、权限和业务状态机保持兼容。
- Chat、Embedding、Rerank、模型接入和 Developer API Key 关键流程真实可用。
- 四个验收视口、亮暗主题和权限组合通过。
- 无浏览器错误、无页面级溢出、无混搭页面。
- 完整结果一次合并并可通过提交边界回滚。
