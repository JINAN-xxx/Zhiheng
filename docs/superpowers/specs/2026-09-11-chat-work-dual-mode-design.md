# 聊天与工作双模式设计

日期：2026-09-11

## 背景

当前智能对话页面同时暴露平台模型、用户技能和知识库，智能体试聊又存在于管理抽屉中。用户需要理解模型、技能、知识库和智能体之间的配置关系，才能选择正确入口；普通问答与持续工作任务也共用相似的对话形态，产品边界不清晰。

本设计参考豆包网页端空态中心的“对话 / 工作”切换方式，但保留智衡平台现有的工作台导航、权限系统、已发布智能体和管理后台。参考页面：`https://www.doubao.com/chat/?channel=browser_landing_page`。

## 产品判断

平台提供两个含义明确的用户模式：

- **聊天**：用于临时、开放式问题。用户选择平台模型，并可按消息选择技能或添加图片。
- **工作**：用于需要持续推进和留存状态的任务。用户选择一个或多个已发布智能体，每次明确指定当前执行者。

工作不是“换了模型的聊天”。工作任务拥有目标、成员、状态和独立历史；智能体封装模型、系统提示词、技能和知识库，使用者不需要也不能在工作页面直接修改这些配置。

## 目标

- 在新建空态中心提供“聊天 / 工作”分段切换。
- 第一条消息发送后固定会话类型，避免运行中改变语义。
- 聊天和工作的历史记录完全分开。
- 聊天移除知识库选择器和知识库列表请求，保留模型、技能和图片能力。
- 工作任务可包含多个已发布智能体，由用户逐条选择执行者。
- 工作任务服务端持久化，页面刷新后恢复目标、成员、消息、状态和运行进度。
- 多智能体共享任务上下文，并明确保留每条回复的智能体身份和版本。
- 对智能体携带的技能和知识库建立清晰的授权与审计边界。

## 非目标

- 第一版不做智能体自动编排、任务自动拆解或智能体之间的自主调用。
- 第一版不做预设“智能体团队”。
- 第一版不支持多人共享或协同编辑同一个工作任务。
- 第一版不提供“聊天转为工作”。
- 第一版不新增文件产物、任务画布、看板或流程编排器。
- 不改变智能体管理、发布、公开 API Key 或现有试聊能力。

## 信息架构

### 路由

- `/ai/chat`：聊天空态。
- `/ai/chat?sessionId=<id>`：已有聊天会话。
- `/ai/work`：工作空态。
- `/ai/work?taskId=<id>`：已有工作任务。

中心模式切换只在 `/ai/chat` 和 `/ai/work` 的无消息空态显示。发送第一条消息后进入带标识的地址，不再显示中心模式开关。用户通过侧栏“新建聊天”和“新建工作”创建另一种类型。

### 侧栏

侧栏顶部同时提供两个明确命令：

1. 新建聊天
2. 新建工作

当前模式决定下方历史列表：

- 聊天模式只显示聊天会话。
- 工作模式只显示工作任务。

两类记录不混排，也不提供“全部记录”视图。管理后台和智能体扩展等资源入口保持现有结构。

## 聊天模式

聊天继续使用现有平台聊天会话与流式接口。页面保留：

- 平台聊天模型选择。
- 每条消息的技能选择器。
- 图片上传。
- 对话偏好、停止生成、用量展示和历史会话。

页面删除：

- 知识库选择器。
- 知识库列表加载和重试入口。
- 新消息的 `knowledgeBaseIds` 提交。

历史兼容规则：旧聊天消息已经保存的知识库 ID 和快照继续只读展示，后端继续接受旧字段；新聊天不再产生知识库绑定。数据库迁移不得删除已有知识库消息字段。

## 工作空态

工作空态中心依次展示：

- 标题“今天要完成什么工作？”
- “聊天 / 工作”分段控件，其中“工作”选中。
- 可使用的已发布智能体快捷选择。
- “添加智能体”入口。
- 任务目标输入框。
- 当前执行智能体和任务成员摘要。

创建任务至少选择一个智能体。第一条消息作为完整任务目标；任务标题默认取清理后的前 40 个字符，用户后续可以重命名。首次发送分成两个可恢复步骤：先在一个数据库事务中创建工作任务、成员快照和第一条用户消息，再用同一个 `clientMessageId` 启动智能体运行。任务创建成功但运行请求中断时，页面进入已创建任务并允许重试，不会重复创建任务或消息。

## 工作任务页面

工作任务页显示：

- 任务标题、目标和状态。
- 当前任务成员及版本状态。
- 当前执行智能体。
- 共享任务消息时间线。
- 输入区、执行智能体选择和停止按钮。

用户可以添加已发布智能体、移除未运行的成员、切换当前执行者、重命名任务、修改目标、标记完成和归档任务。

切换执行智能体只影响下一条消息。移除成员不会删除它生成的历史消息；被移除成员不能继续执行。任务至少保留一个可用成员，否则只能查看、归档或删除，不能运行。

## 工作任务生命周期

任务状态：

- `active`：可以继续发送消息和管理成员。
- `completed`：保留历史，默认不可发送；用户可以重新打开。
- `archived`：从默认工作历史隐藏，只能通过归档筛选查看或删除。

同一个任务同一时间最多有一个活动运行。活动运行结束、取消或失败后才能启动下一次。任务状态与单条运行状态分开；一次运行失败不会自动把任务标记为完成或归档。

## 数据模型

### `agent_work_task`

- `task_id`：不透明任务 ID。
- `owner_user_id`：任务创建者。
- `title`：1-100 字。
- `goal`：完整任务目标。
- `status`：`active | completed | archived`。
- `active_agent_id`：上次选择的执行智能体。
- `version`：乐观锁版本。
- `created_at`、`updated_at`。

### `agent_work_task_member`

- `task_id`、`agent_id`：联合唯一。
- `agent_name_snapshot`。
- `published_version`。
- `config_snapshot`：服务端保存的已发布配置快照，包括模型 ID、系统提示词、技能 slug、知识库 ID、温度和最大输出长度。
- `added_at`、`removed_at`。

`config_snapshot` 不返回前端。前端只接收名称、版本、状态和可用性。

### `agent_work_message`

- `message_id`、`task_id`。
- `client_message_id`：仅用户消息使用的幂等键，同一任务内唯一。
- `role`：`user | assistant`。
- `content`。
- `agent_id`、`agent_name_snapshot`、`published_version`：仅智能体回复必填。
- `reply_to_message_id`：智能体回复关联的用户消息。
- `run_id`、`run_status`：仅智能体回复使用，状态为 `pending | streaming | completed | cancelled | failed`。
- `usage_snapshot`、`error_snapshot`。
- `created_at`。

MySQL 和 PostgreSQL 必须提供语义一致的迁移。

## 智能体版本与授权

任务成员加入时固定当前已发布版本和配置快照。智能体后续重新发布不会自动改变已有任务。任务成员显示“有新版本”提示，用户主动确认后才能更新快照。

快照固定模型选择、系统提示词、技能 slug、知识库 ID 和推理参数，不复制技能正文、模型或知识库数据。技能启停、模型可用性和知识库内容仍是实时资源变化，并在每次运行时重新校验；界面需要把“配置版本固定”和“资源当前可用”作为两个不同状态展示。

每次运行仍检查：

- 原智能体记录存在且当前为已发布状态。
- 任务所有者仍有 `agent_extension:agent:use` 权限。
- 模型当前可用。
- 快照引用的技能仍启用。
- 快照引用的知识库仍存在且允许运行。

第一版不建立跨用户智能体共享 ACL：普通用户只能把自己创建并发布的智能体加入任务；管理员可以使用任意已发布智能体。任务只对创建者和管理员可见。

智能体的 `agent:use` 授权代表可以使用该智能体封装的能力，不代表可以浏览其系统提示词、技能正文或知识库内容。知识检索继续在服务端完成，响应只暴露允许引用的来源标识。

## 多智能体共享上下文

工作任务持久化完整消息历史，但每次模型调用只装配受以下现有限额约束的最近上下文：

- 最多 96 条消息。
- UTF-8 总字节数不超过现有 `MAX_HISTORY_BYTES`。
- 最后一条必须是当前用户消息。

上下文中的智能体回复必须转换为带来源的明确文本，例如：

```text
[智能体：研究助手；发布版本：3]
已完成市场背景整理……
```

这样后续执行智能体能够区分其他成员的结论，前端也能按智能体名称和头像呈现消息。系统提示必须说明其他智能体输出是共享工作上下文，不是高优先级指令。

## 调用流程

### 聊天

```text
用户消息
  -> 平台模型 + 用户选择的技能 + 可选图片
  -> 现有聊天流式接口
  -> 保存聊天会话和消息
```

聊天初始化不请求知识库列表，新请求不发送知识库 ID。

### 工作

```text
用户消息 + taskId + agentId + clientMessageId
  -> 校验任务所有者、状态、并发运行和成员
  -> 读取任务成员的已发布配置快照
  -> 装配带智能体身份的共享上下文
  -> 复用技能解析、知识检索和模型运行能力
  -> 流式返回 meta/content/reasoning/usage/error/done
  -> 持久化用户消息、智能体回复和运行结果
```

工作调用使用新的内部鉴权接口，不复用公开 API Key，也不复用只面向配置验证的非流式 preview 接口。底层继续复用 `prepare_agent_call`、模型运行引擎、技能解析器和知识提供者。

## API 设计

内部接口前缀：`/agent_extension/work-tasks`。

- `GET /work-tasks`：分页列出当前用户任务，支持状态和关键词。
- `POST /work-tasks`：在一个事务中创建任务、成员快照和首条用户消息，使用 `clientMessageId` 保证幂等。
- `GET /work-tasks/{task_id}`：读取任务、成员和消息。
- `PUT /work-tasks/{task_id}`：重命名、修改目标、完成、重新打开或归档，要求 `expectedVersion`。
- `DELETE /work-tasks/{task_id}`：删除任务及其消息。
- `POST /work-tasks/{task_id}/members`：加入当前已发布智能体。
- `PUT /work-tasks/{task_id}/members/{agent_id}`：主动更新成员快照。
- `DELETE /work-tasks/{task_id}/members/{agent_id}`：移除成员。
- `POST /work-tasks/{task_id}/runs`：为指定用户消息启动当前智能体流式运行；相同 `clientMessageId` 返回或恢复同一运行。
- `POST /work-tasks/{task_id}/runs/{run_id}/cancel`：取消运行。

创建任务与后续运行都使用 `clientMessageId` 幂等。首次运行引用创建任务时已经保存的用户消息；后续运行在启动事务中创建新用户消息。服务端返回或恢复同一消息和运行，而不是重复执行。

## 前端组件边界

- `WorkspaceModeSwitch.vue`：空态中心的聊天/工作分段切换。
- `ChatEmptyState.vue`：聊天标题、建议和模式切换。
- `WorkEmptyState.vue`：智能体选择、任务成员和目标输入。
- `WorkTaskPage.vue`：任务头部、状态、消息和输入区。
- `WorkAgentPicker.vue`：只展示有权使用的已发布智能体。
- `WorkMemberBar.vue`：成员、版本状态和当前执行者。
- `WorkMessageTimeline.vue`：按智能体身份显示共享历史。
- `RecentWorkTasks.vue`：工作模式的独立历史列表。
- `workTask` Pinia store：任务列表、当前任务、运行状态和请求代次。

现有聊天页面删除知识库状态和控件后继续使用现有 chat store/API。侧栏只根据当前路由选择 `RecentSessions` 或 `RecentWorkTasks`，不把两类数据合并到一个 store。

## 权限

- `agent_extension:work:list`
- `agent_extension:work:query`
- `agent_extension:work:add`
- `agent_extension:work:edit`
- `agent_extension:work:remove`
- `agent_extension:work:run`
- `agent_extension:agent:use`

智能体配置、发布和试聊权限保持不变。无权限按钮不渲染，后端对每个接口重新校验权限和任务所有权。

## 错误与恢复

- 创建任务失败时保留目标文本和已选成员。
- 成员失效时保留历史并标记不可用，要求切换执行者或主动更新版本。
- 模型、技能或知识库不可用时记录可审计错误，不把内部配置或敏感详情返回前端。
- 运行失败保留用户消息、失败状态和原始草稿，并允许使用同一智能体重试。
- 停止生成写入 `cancelled`，刷新页面后不恢复为运行中。
- 页面刷新读取服务端任务状态；遗留 `pending/streaming` 运行由恢复逻辑标记为 `interrupted`。
- 路由切换和组件卸载必须中止本地流读取，过期事件不得写入新任务。
- 任务删除、归档或版本冲突使用明确提示，不静默跳转。

## 测试范围

### 后端

- 工作任务 CRUD、所有者隔离、管理员访问和状态流转。
- MySQL/PostgreSQL 迁移与唯一约束。
- 已发布智能体选择、配置快照、主动版本更新和下线拦截。
- 多智能体共享上下文中的名称与版本标记。
- 模型、技能和知识库不可用错误。
- `clientMessageId` 幂等、单任务并发限制、取消和中断恢复。
- 完整消息持久化与调用上下文上限。

### 前端

- 空态中心模式切换与首条消息后模式锁定。
- 聊天与工作历史完全分开。
- 聊天存在模型、技能和图片，不存在知识库控件和请求。
- 工作创建失败保留输入和成员。
- 多成员添加、移除、切换执行者和版本更新。
- 每条智能体消息正确显示来源。
- 刷新、前进后退、任务切换和旧流事件隔离。
- 取消、失败、重试、完成、重新打开和归档。

### 视觉与构建

- Playwright 覆盖桌面和移动端的聊天空态、工作空态和任务页面。
- 最长任务名、智能体名和消息内容不溢出或遮挡。
- 输入区、成员栏、侧栏历史和停止按钮不引发布局跳动。
- 插件契约测试、后端定向测试、E2E 和生产构建全部通过。

## 验收标准

- 用户无需理解模型、技能或知识库配置，也能明确知道正在聊天还是执行工作任务。
- 聊天只使用模型和按消息选择的技能，不再加载或提交知识库。
- 工作任务至少包含一个已发布智能体，并可人工添加和切换多个智能体。
- 工作具有目标、成员、状态、独立历史和可恢复运行结果。
- 智能体配置版本稳定，跨智能体上下文来源清晰，知识能力不会越权暴露。
- 桌面与移动端页面无按钮裁切、文本溢出、消息遮挡和不可达操作。
