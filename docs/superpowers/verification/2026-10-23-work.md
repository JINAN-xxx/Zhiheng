# 内置 Work 验收记录

日期：2026-10-23。分支：`refactor/ai-core-modularization`。本组恢复原 Work 工作模式，接入内置业务模块和统一持久运行。

## 已实现行为

- 原聊天/工作模式切换、工作空态、目标和成员选择、共享时间线、最近工作搜索/过滤/分页、重命名和删除。原8个组件样式经格式归一核对保持一致。
- 任务 active/completed/archived 状态、归属权限、版本冲突与单运行占用；成员最多10个，加入或显式升级冻结发布版本、名称、配置和技能内容。新发布不自动改旧成员，移除不改历史，重新加入冻结最新版本。
- 创建事务保存任务、成员及第一条目标；随后以前端同一创建请求键执行首轮。服务端冻结首轮执行者，修改可变 active 字段不能改变原请求意图。同键重放先于后续版本变化，改内容冲突；共享 runtime 键与其他调用碰撞时稳定返回409。
- 每轮人工选一个成员，共享带当时姓名/发布序号署名的正文；推理单独显示、保存，不回灌模型。上下文裁剪有条数/字节边界，完整历史仍保留。
- Work 使用专用 Run 观察/取消接口，任务原 owner 和管理员可访问；管理员代执行按任务原 owner 授权并计费，私人聊天的通用 Run 权限保持独立。
- 预留、Run、outbox、消息与占用原子接纳；claim、投影、终态、pending取消、失联恢复同事务更新 Work 消息。running取消保持占用，直到供应商关闭/终态才释放并递增任务版本。未知用量保留预留，失联不自动重复生成。
- 前端按任务保留运行/结果未知锁，以版本拒绝旧列表解锁；关闭观察、换任务、注销和迟到保存均有请求所有权。已接纳后只能恢复观察；明确失败重试新键。已确认创建即使详情失败也留在已知任务恢复页，后续新建不会误用旧创建键。输入法确认文字不误发送。
