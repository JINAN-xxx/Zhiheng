# 正式环境模型服务恢复

日期：2026-10-27。入口：<http://127.0.0.1:19080>。本记录对应正式实例 `0007_knowledge`，图谱新版本尚未部署，MinerU 按当前安排暂缓。

后续交付更新：本记录完成后，正式实例已保留上述模型配置并升级至 `0008_graph`，图谱能力现已可用，详见[图谱验收](2026-10-27-lightrag.md)。以下保留模型恢复时的验证过程。

正式实例的原管理员登录、12 个核心接口、七个页面、向量可用性和连续 JSON readiness 实测通过。检查发现模型连接及模型目录为空；用户随后明确选择沿用旧项目的模型服务。

恢复前先保存正式 PostgreSQL dump，并使用 `pg_restore --list` 校验。旧项目保持停止，从其停机数据卷制作独立副本；临时 PostgreSQL 无网络、无发布端口，查询默认只读。核对旧模型目录、资源绑定和凭据后，通过新平台正常管理 API 恢复一份硅基流动连接和以下四个模型；密钥由新平台重新加密。

| 模型 | 类型 | 实际验证 |
| --- | --- | --- |
| Qwen3.8-27B | Chat | 标准持久 Run 完成，返回 OK，用量已知 |
| GLM-5.3-Flash | Chat | 标准持久 Run 完成，返回 OK，用量已知 |
| bge-m3 | Embedding | 标准持久 Run 完成，返回 1024 维向量，用量已知 |
| bge-reranker-v2-m3 | Rerank | 标准持久 Run 完成，返回一条重排结果，用量已知 |

每个模型只提交一次稳定请求键的连接测试，再轮询原 Run。四次调用均经当前正式 API、worker、模型适配和用量记录完成，没有将测试替身写入正式模型目录。

真实 Chromium 复查确认：模型管理页可见四个模型，聊天选择器可选 Qwen 和 GLM，页面错误为零；浏览器复查未创建测试会话或发送聊天消息。数据库中保存的上游密钥为密文，API 读取只返回凭据存在标记。

本次范围为已有服务凭据、模型目录及启用/发布和视觉配置。旧模型未设输出上限时，聊天采用 4096、Embedding/Rerank 采用 512 的显式上限，可在模型管理中调整。旧应用、访问 Key 和费率没有自动搬迁；公开开发 API 使用前仍须创建新应用/Key、授权模型并配置适当费率。

核验完成后，临时数据库容器及副本卷已精确删除，解密后的临时配置和包含旧密钥的容器信息副本已删除；旧实例及原始卷保持不变。备份、迁移映射、真实 Run、浏览器截图和收尾证明保存在仓库外私有 `model-service-restoration/20261027` 目录，密钥不进入源码或文档。
