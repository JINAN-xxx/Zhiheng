## 真实容器链路与升级

独立 `zhiheng-core-parity-audit` 从空库启动 PostgreSQL、Redis、migrator、worker、API、Nginx。Chromium 没有拦截接口，使用真实 API/数据库/队列及本地模型 HTTP 服务，完成 12 次上游调用：

1. 原模型接入、测试，两轮聊天、历史重载和静默生成取消。
2. 向量和排序模型的真实分类测试。
3. 原应用/Key 页面创建、一次显示/复制、关闭后清空，浏览器存储不含明文。
4. 公开 Chat JSON/SSE、Embedding、Rerank；无授权模型拒绝且没有上游请求。
5. 调用账本四笔费用分别为 0.12、0.12、0.06、0.50；费率 v2 后新调用 0.32，历史行费用不变。
6. RPM=1 的第二次调用返回 429，不增加上游请求；Key 轮换、宽限、撤销及应用停用/启用生效。
7. 手机宽度、退出登录、无浏览器异常。

正常 `zhiheng-core` 更新前保存数据库 custom dump、配置、容器信息和原镜像回退标签。停止 API/worker/web 后取一致数据快照，升级 `0001_core→0002_developer`；按升级前列清单逐行比较原有数据，仅规范化迁移新增的绑定修订字段。已有数据核对通过，原管理员登录、健康检查、新应用 API、公开 API 鉴权与接口文档通过。测试资源只存在于独立验收项目。
