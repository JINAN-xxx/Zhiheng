# 知识库与存储入口整合验收

2026-10-28。正常入口仍为 <http://127.0.0.1:19080>，沿用 Vite 热更新与 API 源码重载。

## 当前入口

- 主导航只保留“知识库”。具体库中的“管理文档”负责上传、文件夹、预览、原文权限、删除和索引任务；对话附件仍从聊天上传。
- 管理员在知识库首页进入“存储管理”，查看知识文档与对话附件的存储统计、权限、引用、回收、审计、保留策略、提醒和对账。治理页面不再单独上传，提供返回知识库按钮。
- 正式地址为 `/knowledge/storage`；旧地址 `/files`、`/system/file` 保留为别名，并选中知识库导航。三个地址均受管理员路由校验，普通成员不展示入口。
- 后端 `modules/files` 保留共享存储职责，本次不迁移文件、不改变业务归属，不执行数据库迁移。

正常实例核对时发现原有 `/api/files/reconcile/stats` 返回 500：SQLAlchemy Result 暴露 `keys()`，直接 `dict(rows.tuples())` 被当作映射读取。将元组结果物化后再构建字典，保留空状态补零和查询前管理员校验。新增测试使用真实 SQLite/SQLAlchemy 分组结果，仅将执行调用适配为异步；修复前空数据、部分状态和全部状态三项均复现相同 TypeError，修复后通过，实际 PostgreSQL 接口及治理抽屉复测通过。

正常实例目前知识库数量为零；真实核对验证了列表、入口和存储治理，没有为验收新增知识库或上传文件。文档交互由上述 12 项浏览器接口夹具回归覆盖，不将其描述为真实向量索引或模型调用验收。

本轮没有构建安装包或镜像，没有调用付费模型。原始失败、通过日志、正常实例截图和只读指纹保存在工作区外 `knowledge-storage/20261028` 验收目录。
