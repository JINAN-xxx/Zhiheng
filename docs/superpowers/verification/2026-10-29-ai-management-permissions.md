# AI 平台管理权限与角色编码验收

用户确认保留普通账号的基础对话和本人资源能力，将平台级管理操作交给角色授权。本轮也将新角色编码改为后端自动生成。

## 当前行为

- 新建角色不再要求填写或提交编码；后端生成 `role_` + UUID4.hex。已有编码及显式 API 编码兼容保留，编辑不允许改码，内置角色仍受保护。
- 权限目录由原 20 项系统管理扩为 20 + 8 项，并以中文分组显示。AI 权限不提供后台系统管理入口，授予与分配仍受调用者权限子集约束。
- 模型目录的侧栏、路由、数据加载与操作同步调整：普通账号可查看已发布模型，不请求凭据或完整目录；获得模型维护授权的普通账号可接入模型及凭据。
- 模型配置、连接测试、费率、共享技能和存储治理分别授权；只读接口显式允许相应 read/write。原 `system:*` 精确匹配不变，超级管理员继续按既有身份授权。
- 本人智能体、知识库、开发应用和基础模型调用继续遵守原所有权、共享、配额与用量规则。存储治理授权不绕过私有原文 ACL、跨所有者创建、转移或处置规则；例如对他人文件 purge/repair/quarantine 仍会拒绝。

| AI 代码 | 用途 |
| --- | --- |
| `ai:models:read` / `ai:models:write` | 模型与凭据配置查看 / 接入维护 |
| `ai:models:test` | 连接测试，沿用配额、账本和请求幂等 |
| `ai:rates:read` / `ai:rates:write` | 费率查看 / 配置 |
| `ai:skills:write` | 平台共享技能导入、启停、删除 |
| `ai:storage:read` / `ai:storage:write` | 策略与治理记录查看 / 策略和维护任务操作 |

新用户需要接入模型时，管理员在角色中勾选“模型与凭据配置 · 创建、编辑、启停、发布与删除”，再在用户管理绑定该角色；用户刷新页面即可加载新权限。需要测试连接时另选“模型连接 · 测试”。后端每次请求重新计算有效角色权限，角色停用或撤销后已有会话的新管理请求立即被拒绝。

## 验证

| 范围 | 结果 |
| --- | --- |
| 身份与角色 | 69 项单元/HTTP/内置角色及 17 项真实 PG/Redis 集成、并发、迁移回归通过；覆盖生成唯一、旧码稳定、显式重复409、28项授权、越权拒绝、既有会话与撤销 |
| AI 后端 | 75 项模型、技能、聊天接纳、模型锁与文件回归通过，其中最终 AI 权限专项 7 项；覆盖直调与 HTTP 的只读/写入/拒绝，以及私有文件 ACL |
| 权限基础与架构 | Principal 6 项通过，原精确权限不变；架构门禁 28 项通过 |
| 前端核心 | 71 项通过 |
| 浏览器 | AI 专项 11 项与角色/旧链接选定场景组合共16项通过；完整管理/模型/技能/文件39项回归通过，覆盖桌面/手机、模型入口、读写分离与本人文件操作 |
| 真实端到端 | 当前 UI → 隔离 API → PostgreSQL：普通用户只读目录；管理员仅填写角色名并选择 AI 权限，自动生成编码；实际为用户绑定角色；非管理员新增连接与模型；撤销权限后同一会话403，刷新恢复只读。未授予系统后台、测试或费率权限 |
| 正常实例 | 原管理员登录、真实28项目录/8项AI权限、创建表单无编码、既有模型管理入口与服务就绪通过；未修改真实角色配置、用户密码或模型凭据 |
| 静态与独立审查 | 前端全量类型/ESLint/Prettier通过；后端12个修改源文件分组Mypy及Ruff/格式通过，独立需求/安全审查通过 |
| 运行 | 检查无活动运行/知识任务后重新加载正常Worker，API/Worker就绪；源码模式生效，无迁移或SDK升级，不打包 |

模型执行测试使用本地协议供应商，真实角色联调只创建隔离环境中的假凭据与模型配置，不触发收费推理。原始失败和通过日志、截图、权限矩阵与脚本保存在仓库外 `ai-management-permissions/20261029`。初期浏览器用例曾把聊天模型下拉误认为目录，已增强 URL/标题/侧栏断言，定位并修正旧入口限制；端到端脚本改为核对 Ant 抽屉关闭状态，避免把保留的外层节点误判为打开。

基础设施复用现有 Python 3.12 依赖镜像；缺依赖的旧环境尝试不计为通过，未安装或升级 SDK。原 57 份优化哈希不变，隔离 API/PG/Redis/网络及两个匿名卷已清理。数据库仍为 `0011_builtin_admin_role`。
