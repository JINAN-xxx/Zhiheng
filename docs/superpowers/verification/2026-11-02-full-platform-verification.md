## 发现与处理

三个前端/CI 测试仍使用旧菜单或常驻历史栏；已按当前页面调整入口，保留原业务断言。普通用户应保留基础模型目录，旧“没有目录入口”的断言改为检查只读入口。后端图谱取消锁用例缺少显式 Milvus 依赖注入；迁移用例把新增 `points_enforced=false` 列误判为旧行变化，现改为冻结旧列逐字段验证，并额外核对默认值和账务表。

验收环境曾把不同队列的 Main/OPS/CI Worker 放在同一 Redis 逻辑库，ARQ 默认定时任务标识未含队列名，造成心跳竞争和知识准备调度超时。测试环境改为独立逻辑库后，心跳稳定、实际检索和调用通过。没有为此放宽产品超时或修改账务/权限。

公开智能体最初返回模型不可用，实际是积分关闭的 QA 模型没有配置历史货币费率。补齐合成费率后，以新请求标识完成同一智能体/知识库调用；旧失败意图继续保留。没有增加模型授权或绕过收费规则，这一项不列为产品授权缺陷。

完整图谱构建则捕获了真实 PostgreSQL 死锁：图谱先锁知识库再锁模型，与其他 AI 调用的模型优先次序相反。已统一为模型/连接先于知识库的锁顺序，并补齐配置改选、缓存中的取消/epoch、权限撤销和退役代际 pin 复核；失败或旧 epoch 的停止证明不依赖模型活性。14 项定向回归与独立代码审查通过，没有添加 SQL/模型请求重试或延长超时。实际 Python 3.12 API/Worker 完成九文档图谱构建，同时向量检索返回八条来源，图谱查询返回九条带身份与内容哈希的来源，画布与手机交互共八个检查通过，0 页面脚本错误。
