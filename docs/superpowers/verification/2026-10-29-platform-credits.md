# 平台积分验收

## 交付范围

平台积分内置于 `billing`，采用独立账户、不可变价格版本、预占、实际结算和流水。管理员可发放、追加、回收、暂停和核对；新用户默认零积分，积分长期有效。普通用户可查看本人账户、消费与流水，管理操作使用 `ai:credits:read/write`，费率沿用 `ai:rates:read/write`；只有超级管理员可以切换全平台积分计费。

聊天、连接测试、智能体试聊与公开调用、Work、公开模型 API、知识检索/索引 Embedding 和图谱模型回调均经统一用量入口。API Key 共用应用所有者账户，可设置独立月积分上限；原 RPM、TPM、并发和金额预算保持各自语义。积分模式保留历史 Token 统计，不再以旧终身 Token 总额阻止积分调用。

切换和模型接纳使用数据库事务读写锁，包含可在稍后派生模型调用的知识任务；切换时检查在途工作和模型缺价。调用冻结所有者、模式及价格，后续价格变更不影响旧预占。供应商缺少可结算计量时保留预占；按检索单元收费的 Rerank 无需捏造 Token。人工核对只补未知计量，已确认值（含 0）不可覆盖；有正用量时不能声明“未执行”。历史计量与积分在同一 Savepoint 中更新，任一拒绝均完整回滚。

真实浏览器链路使用源码 Vite → HTTP API → PostgreSQL Outbox → 独立 Worker → LangChain → 本地供应商。管理员在实际页面创建积分价、发放 100 积分并启用；普通用户实际输入 8 / 输出 2，按输入 100、输出 500 积分/百万 Token 扣 **0.0018**。同一请求重放不重复调用或扣分；供应商不报告用量时保留预占。价格改为新版本后，管理员在同页核对旧调用，仍按原价扣 0.0018，最终 **99.9964 可用 / 0 预占 / 0.0036 已消费**。旧 Token 上限刻意设为 5，实际累计 10 Token 的积分调用仍正常完成。本人积分页面和手机宽度通过，未出现浏览器脚本错误。

一次真实流程因表单字段 ID 重复而暴露标签关联错误，已修复为每个表单实例唯一名称并增加回归。测试中另纠正了新建费率的 HTTP 201 预期和实际使用 CSS class 的页面定位，未改产品绕过断言。

## 迁移与启用

`0012_platform_credits` 新增 7 张积分表，给 Key 增加可空月积分限额，给历史调用增加默认 false 的模式标记，并将累计 Token 计数扩为 BIGINT。保留原值与单位，不生成用户充值、不设置价格、不追扣历史；默认控制行为 false/version 0。存在积分账务或配置后拒绝直接降级，避免丢账。

正式实例的备份、原列/原行指纹对比与健康检查将在源码切换时记录。当前交付默认保持积分计费关闭。

启用顺序：

1. 在“模型目录 → 费率配置 → 积分计价”给所有启用且已发布的模型设置价格；免费模型显式勾选免费。
2. 在“用量与调用 → 用户积分”搜索用户并发放积分；积分管理员角色需授予对应读写权限。
3. 等待运行及知识任务结束，由超级管理员填写原因并点击“启用积分计费”。

本轮不含支付充值、积分过期、定时配额、供应商价格同步、历史金额补扣或生产负载压测。MinerU 继续按既定安排暂缓。
