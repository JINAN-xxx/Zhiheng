# 平台积分验收

## 交付范围

平台积分内置于 `billing`，采用独立账户、不可变价格版本、预占、实际结算和流水。管理员可发放、追加、回收、暂停和核对；新用户默认零积分，积分长期有效。普通用户可查看本人账户、消费与流水，管理操作使用 `ai:credits:read/write`，费率沿用 `ai:rates:read/write`；只有超级管理员可以切换全平台积分计费。

聊天、连接测试、智能体试聊与公开调用、Work、公开模型 API、知识检索/索引 Embedding 和图谱模型回调均经统一用量入口。API Key 共用应用所有者账户，可设置独立月积分上限；原 RPM、TPM、并发和金额预算保持各自语义。积分模式保留历史 Token 统计，不再以旧终身 Token 总额阻止积分调用。

切换和模型接纳使用数据库事务读写锁，包含可在稍后派生模型调用的知识任务；切换时检查在途工作和模型缺价。调用冻结所有者、模式及价格，后续价格变更不影响旧预占。供应商缺少可结算计量时保留预占；按检索单元收费的 Rerank 无需捏造 Token。人工核对只补未知计量，已确认值（含 0）不可覆盖；有正用量时不能声明“未执行”。历史计量与积分在同一 Savepoint 中更新，任一拒绝均完整回滚。

## 迁移与启用

`0012_platform_credits` 新增 7 张积分表，给 Key 增加可空月积分限额，给历史调用增加默认 false 的模式标记，并将累计 Token 计数扩为 BIGINT。保留原值与单位，不生成用户充值、不设置价格、不追扣历史；默认控制行为 false/version 0。存在积分账务或配置后拒绝直接降级，避免丢账。

正式实例已完成私有数据库备份并从 `0011_builtin_admin_role` 升级到 `0012_platform_credits`，源码已从功能分支快进合回原工作目录。升级前后 **63 张原表 / 1195 行**的原字段指纹一致；57 份原有未提交优化逐文件 SHA-256 一致。新增积分业务表为空，控制开关 false/version 0，历史 Key 月积分上限为 null，旧调用模式标记均为 false。备份和完整数据不进入 Git。

API 与 Worker 已加载原目录的新源码，`19080/health/ready` 返回真实 JSON `{"status":"ok"}`。正式管理员登录后，8 个接口和 8 个页面只读复查通过，包含积分、模型、智能体、开发接入、知识库、工作、角色权限和聊天；新增权限目录共 30 项，无脚本/接口错误，也没有发起业务写入或模型调用。登录/注销本身正常记录认证审计，不计入业务数据迁移指纹。

重启时 Compose `start` 尝试启动一份旧的非源码 migrator，因旧迁移代码无法识别新版本而阻止依赖启动。随后直接启动已有源码 API/Worker，并以源码 overlay、`--no-build` 重建 migrator，迁移幂等执行成功；现有 Web/UI 和审计实例保持运行。当前积分计费关闭，未自动发放或配置真实积分价。

本次独立测试 API、Worker、模型服务、PostgreSQL、Redis、匿名数据卷和专用网络已清理，15197 Vite 已停止；保留功能分支、提交与仓库外验收资料，当前根目录继续提供正常源码服务。

启用顺序：

1. 在“模型目录 → 费率配置 → 积分计价”给所有启用且已发布的模型设置价格；免费模型显式勾选免费。
2. 在“用量与调用 → 用户积分”搜索用户并发放积分；积分管理员角色需授予对应读写权限。
3. 等待运行及知识任务结束，由超级管理员填写原因并点击“启用积分计费”。

本轮不含支付充值、积分过期、定时配额、供应商价格同步、历史金额补扣或生产负载压测。MinerU 继续按既定安排暂缓。

## 启用失败的提示修正

2026-10-29 用户反馈启用失败。正常实例日志记录 `PATCH /api/billing/state` 返回 409；在数据库只读事务中运行原启用预检，确认错误为 `credit_rates_incomplete`，四个已发布模型尚无积分费率，运行和知识任务均空闲。前端此前将所有 409 都显示为版本冲突，掩盖了缺价原因。

账户操作和用量核对现在只对 `version_conflict` 提供刷新指引，缺价、任务未完成、回收余额不足、已知用量冲突等均显示后端具体原因。未更改启用条件、配置真实费率或自动开启计费。

5 项新浏览器用例先复现 4 项失败、1 项真实版本冲突通过；修复后积分浏览器完整 18 项通过（42.816 秒），类型检查、相关 ESLint/Prettier 和差异空白检查通过。正常 19080 源码入口已返回两处修正组件，就绪检查仍为 JSON `{"status":"ok"}`；无需打包或重启后端。红绿日志位于仓库外 `platform-credits/20261029-enable-failure`。

## 定价与全局启停备注选填

用户确认简化定价表单后，“定价原因”改为选填“备注”，首次配置价格可直接保存。全局积分计费启用/停用也允许不填备注；启用保留价格检查，停用不要求价格齐备。发放、回收、账户暂停/恢复和人工核对继续要求操作依据。

前后端契约均接受省略备注、空字符串或纯空格，统一保存为空字符串；填写的备注去除首尾空白。操作人、时间、价格版本、切换版本及幂等标识仍自动记录，不填备注不会取消审计或重复执行。不变更数据库结构，不自动设置正式价格、发放积分或操作正式计费开关。

红绿验证：费率省略/空白备注的 3 项契约失败、启停的 3 项契约失败、2 项真实 HTTP 失败和 2 项浏览器失败均准确复现旧强制校验。修复后 31 项契约、36 项真实 PostgreSQL HTTP/核心、20 项积分浏览器和 80 项前端核心通过；HTTP 验证空备注下仍保存操作人/时间/版本、同请求重放不重复创建，新增未定价模型后仍可停用。后端 165 个源文件 Mypy、修改文件 Ruff/格式、架构边界，以及全前端类型/Lint/格式检查通过。

正常实例 OpenAPI 已核对：`CreditRateCreate` 与 `CreditStatePatch` 的 reason 选填，`CreditAdjustment`、`CreditAccountStatePatch` 和 `CreditReconcile` 仍必填；原 19080 源码页面已加载选填备注组件。详细日志保存在仓库外 `platform-credits/20261029-optional-notes`。
