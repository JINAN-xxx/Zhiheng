# 智能对话图片与附件实现计划

> **面向 AI 代理的工作者：** 使用 subagent-driven-development 实施；按已固定接口分离后端文件读取、消息组装、前端输入框与部署任务。

**目标：** 修复智能对话图片链路，支持用户指定的 PDF、DOCX、TXT、Markdown、XLSX、CSV 附件，并保留历史引用。

**设计：** 使用现有 `/common/files/upload` 受保护上传。发送接口延续 `images: [{fileId}]`，新增 `attachments: [{fileId}]`（最多 5 个，单文件 20MB，单文件文本 4 万字符、总文本 6 万字符）。图片保留现有 10 张与用户大小偏好。服务端从受保护元数据解析用户自己的有效文件，检查真实内容和文件边界，图片转标准多模态块，文档解析为带文件名的参考文本；不执行文档中的指令。

历史保存附件引用与文本快照，响应仅公开文件名、类型和大小。刷新后可查看/下载附件，后续对话携带文档上下文。图片选择受视觉偏好及模型能力约束。前端显示上传状态、移除和失败重试；上传未完成时禁止发送，切换会话取消并清空待发文件。只有文件时发送明确的默认分析提示。

## 工作项

- [ ] 文件适配器：新增 `plugins/ai/infrastructure/chat_file_adapter.py` 和独立测试；实现 `resolve(user_id, file_id, *, max_size_bytes)` 返回共享 `ResolvedPlatformImage`，`resolve_attachment(...)` 返回共享 `ResolvedPlatformAttachment`。只允许本人有效文件，拒绝缺失、过期、路径越界/符号链接、类型伪造、超限、损坏和无文本文件。验证图片及 6 种文档，包括 XLSX/CSV。
- [ ] 消息服务：修改请求/响应模型、消息 ORM、服务和依赖注入，新增 PG `010_chat_attachments.sql` 并登记清单。新 `attachments` JSONB 列默认空数组、历史向后兼容；幂等校验包含图片与附件 ID；固定脱敏错误；图片响应允许元数据字段。新增附件当前消息与历史上下文、所有权错误、重复请求和纯文件 UI 默认提示对应服务测试。
- [ ] 前端：上传使用受保护接口和共享客户端；新文件队列工具/组件、上传进度、失败重试、名称和预览/下载，拆分图片/文档请求。约束数量/大小，保留失败草稿，切换会话或卸载取消上传并释放 object URL。补充行为测试和桌面浏览器回归。
- [ ] 部署：Nginx 配置上传上限与通用上传能力匹配；为 `/app/vf_admin` 挂载持久目录并保留已有文件（检查时公开/私有目录均为空）。当前 `20260916-knowledge-milvus-only/manage.sh` 为基础组合，保持 FRP 8060、12580 入口与 127.0.0.1:19099 后端限制。
- [ ] 验证：先观察失败测试再实现；运行文件适配、平台聊天、前端插件/桌面测试，审查后构建。集成测试使用临时数据库/文件和隔离模型响应验证文件内容进入模型请求；不绕过生产登录或 CAPTCHA。真实公网复查上传大小、鉴权、验证码和入口，检查迁移与持久目录。
- [ ] 发布、记录迁移/回退入口和实际验证范围，整合代码并清理工作树。

## 已确认的运行约束

- 当前启用的 deepseek-v4-flash 模型记录为 vision=false，图片理解需支持视觉的模型；不擅自更改能力标记。
- 解析型 PDF 支持文字提取，扫描件和加密文档明确拒绝；PDF 页面、Form 和字体映射流共享解码预算，Office 文档有解压预算。
- PostgreSQL 主依赖固定增加 pypdf 和 python-docx；保持现有知识库 Milvus 限制。
