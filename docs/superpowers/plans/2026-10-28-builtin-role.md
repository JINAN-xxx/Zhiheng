# 内置超级管理员角色补齐

已核实正常实例 admin.is_admin=true、角色0条、用户角色关联0条。用户指出角色列表与admin身份不一致，本轮补默认角色及真实关联，保留所有现有授权和账号状态。

- [x] IdentityRole 增加 system_key: str|null（唯一，普通角色null，系统超级管理员为super_admin）。0011显式迁移插入受保护“超级管理员”角色并给所有is_admin账号关联；原普通角色、原关联不覆盖，重名代码用安全备用编码。
- [x] 内置角色由系统维护，不能改名、停用、删改权限或删除；不允许通过普通role_ids给非管理员分配该角色。管理员的系统身份仍由已有is_admin决定，保留模型等全平台管理能力。普通账号不会因此提权。
- [x] CLI/后台新建管理员、提升/取消超级管理员时自动同步内置角色关联。管理表单包含旧系统role_id时，以最终is_admin为准维护系统关联；普通资料编辑保留关联和会话。
- [x] /admin/roles DTO增加 system_key（可缺省null兼容旧夹具）、member_count（可缺省0）；/users/options.roles增加system_key可缺省null，前端原有关联显示名称但禁用手工选择内置角色。用户role_ids是真实关联。
- [x] 角色页展示“系统内置”“全部管理权限”和成员数，提供只读查看；编辑、停用、删除禁用或不展示。用户页/账户菜单把系统管理员称为“超级管理员”。
- [x] 测试先复现缺口，验证迁移老管理员、代码重名保留、内置角色保护、新管理员自动关联/降级移除、非法授权拒绝、页面可见与普通角色原CRUD不回归；隔离真实PG和浏览器验证后接回当前源码平台。仅新增角色元数据和关联，保持旧密码/账号/业务记录。
- [x] 根据用户补充要求，主侧栏移除“平台管理 → 后台管理”；只在左下角账号菜单按权限提供后台入口，保留进入后的管理功能导航。验证超级管理员/授权成员可进入、普通成员入口隐藏且直接访问受限。
