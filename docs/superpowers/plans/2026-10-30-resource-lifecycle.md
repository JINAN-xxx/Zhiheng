# 资源生命周期修复

**目标：** 落实用户确认的[排查清单](../reviews/2026-10-30-resource-lifecycle.md)，让管理员能移除可选内置技能及不再使用的资源，保留历史和有效依赖保护。

**工作区：** `fix/resource-lifecycle`，基线 `d88a671b`，隔离工作树 `.worktrees/resource-lifecycle`。复用缓存 Python 3.12 / Node 24 / LangChain 1.4.7，不安装依赖、不打包。正常实例在验证和备份完成后更新到原目录。

## 已确定的规则

- 技能、模型、凭据、智能体和应用均用软删除保留身份与历史；一次确认完成必要的停用/取消发布。内置可选技能同样允许有技能管理权限的人移除。
- 删除只被当前有效依赖和在途任务阻断。智能体检查非删除草稿与当前发布指针；工作检查活动任务及有效成员；密钥检查有效期、撤销/轮换状态与应用状态；知识域保留索引、图谱与准备阶段的真实依赖。
- 历史 Run、旧金额费率、旧发布版本、已删除资源和已移除成员不永久阻挡目录移除。历史内容、冻结绑定、账单和凭据修订保留。
- 错误详情使用 `error.details.references` 列出引用类型、标识、名称、状态及站内处理路径。其他用户的私有资源隐藏名称、标识和路径；仅给出通用依赖说明。
- 同 slug 技能保持同一身份，安装预检明确区分 install/update/restore/unchanged。更新追加不可变修订，恢复重新启用；确认目标身份、版本和动作被冻结，旧确认重放返回原结果。
- `0013_skill_revision_history` 解除技能修订一对一限制，添加草稿目标、版本及冻结确认字段，回填旧确认；旧列与旧修订内容不改。存在多修订或新确认数据时保护降级。
- 停用应用仍可改名。应用重新启用时校验有效 Key 的模型；工作重新打开时校验冻结模型、智能体、技能和知识范围，再复核任务版本。锁顺序遵循 Model → Connection → Agent → Task → Skill。
