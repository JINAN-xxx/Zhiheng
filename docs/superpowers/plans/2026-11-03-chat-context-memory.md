# 会话滚动摘要与上下文预算实现计划

> **执行方式：** 当前会话使用 subagent-driven-development 逐任务实现，规格审查后再进行质量审查。用户已确认策略并要求落代码，无需重新确认同一范围。

**目标：** 普通对话未压缩的完整问答累计 30 轮时生成滚动摘要，压缩后保留最近 15 轮原文；Token 预算可以更早触发。原始消息完整保留，摘要任务按本人模型权限和现有积分账本计量，后台运行，不阻塞普通聊天。

**工作区：** `feat/chat-context-memory`，`.worktrees/chat-context-memory`。基线 `4ee64eca` 包含原来 17 项现用功能改动；原根目录及其 743 项未提交文件已做独立指纹和原字节归档。原实例 19080、公网 frp 8060、审计实例 19081 在验收前保持原状。

**技术栈：** 现有 FastAPI / SQLAlchemy / PostgreSQL / Redis / ARQ / 原 Run-Outbox-Worker / LangChain 1.4.7。不增加第二套队列、执行器或积分账本，不引入知识库挂载，不打包前端。

## 已确认的行为

- 以完整问题及其最新成功回复为一轮，失败和不完整回复不计入；重新生成不会增加轮数。
- 首次第 30 轮完成后，将第 1～15 轮并入摘要，保留第 16～30 轮；累计第 45 轮时，旧摘要合并第 16～30 轮，保留第 31～45 轮。
- 摘要记录覆盖边界、原问题/选定回复及来源指纹；旧摘要与尚未压缩的消息连续衔接，不跳过未归档的中间消息。原聊天历史不删除。
- 摘要目标约 1024 Token。输入上下文默认预算 8192 Token，结合可配置模型上下文窗口扣除本次输出和安全余量；轮数是软触发条件。计算当前问题、系统提示词、技能、附件与图片占用，按完整问答保留；当前必需输入单独超限时明确拒绝，禁止悄悄截断当前问题。
- 模型窗口未知时使用保守的平台预算，不以“最大输出长度”假冒上下文窗口；Token 估算和计费额度是独立概念，原积分/用量语义保持。
- 在后台增量更新摘要。生成失败、超时、被截断、权限变化或来源失效时保留最后有效摘要，按安全的近期窗口降级。尚未得到模型确认的摘要不得标记成功。
- 摘要是会话资料，按真实用户/会话隔离，不提升为系统指令。正文历史中的约束、目标、已确认事实、决定及待办是摘要重点；不发送历史思考过程。
- 摘要调用复用当前模型，走原价格、额度、用量、执行权 fencing 与取消/恢复流程，用量记录标记“会话摘要”。并发、重复投递和重试不重复创建同一摘要任务/模型调用/计费。

## 文件和职责

- `modules/chat/`：轮次选择与纯策略、摘要状态/来源边界、摘要任务发布事实、聊天调用采用的上下文快照；继续由 `ChatService` 负责会话归属和完整历史。
- `application/chat_context.py`（可拆为同目录小模块）：构造上下文、预算、原摘要与新增历史编排、后台摘要的调度/授权/发布；不在 HTTP handler 中调用模型。
- `modules/models/`：可选的上下文窗口元数据和模型能力边界。新可选字段为 None 时须保留旧绑定序列化/指纹和已冻结配置兼容。
- `runtime/contracts.py`、`bootstrap/container.py`、`worker/`：注册内部摘要 Run，继续使用同一 Outbox、模型执行器和账本。摘要 Run 应以独立任务 ID 为 resource_id，避免原 `has_active(conversation_id)` 将后台摘要当作普通聊天阻塞。
- `migrations/versions/0017_chat_context_memory.py` 及 schema 注册：只做必要新增表/列，不重写旧消息、模型价格、原 Run payload 或账本。
- `frontend/`：只补必要的窗口元数据、上下文状态/降级说明以及用量来源标签，沿用当前白底 UI；普通聊天不重新引入知识库选择器。

## 关键一致性约束

- 模型调用必须先创建有确定幂等身份的原生 Run 并预留费用；禁止在持有会话事务锁时发 HTTP 模型请求。
- 摘要任务存储期望状态版本及来源指纹，发布前 CAS 和重新授权；较早或已取消的任务不能覆盖较新摘要。
- 后台摘要独立于聊天运行占用。Worker 崩溃后通过原 Outbox/运行恢复及待发布检查继续，不依赖进程内 `create_task`。
- 摘要来源涉及的文件仍需按当前归属/状态和 SHA 检查，压缩不能绕开原附件权限；原始图片不作为大段 base64 加入摘要文本。
- 普通请求和重新生成的原有幂等重放优先返回原 Run/上下文快照。会话归档或删除后不再新花费生成摘要；执行前复核、发布时复核，必要时通过原取消流程停止待执行任务。
