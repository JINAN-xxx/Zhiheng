# 内置 Work 实现计划

> 使用 `subagent-driven-development` 执行；每个实现任务先规格、再独立质量审查。保留用户当前工作区、原界面和 legacy 未提交优化。

**目标：** 接回原 Work 工作模式：持久任务、成员冻结发布版本、人工选一个成员执行一轮、署名共享历史、推理、停止与重新查看。没有自主分工、自动路由或 DAG。

**架构：** `modules/work` 拥有任务、成员、消息和运行关联；`application/work_runs.py` 编排 Agent 公共快照、模型/技能授权、上下文、Run/outbox 和统一账本。生命周期投影由 application 层协调，runtime 不导入业务模块。前端保留原 Work 组件布局，通过模块 API 和共享 Run 传输接入。

## 契约

- 普通用户只读写自己的任务；管理员代操作时仍按任务原 owner 校验 Agent 目录，按智能体原 owner 校验其技能/知识绑定。内部执行不要求公开应用 Key；费用记任务 owner，Run 操作权限允许任务 owner 和管理员通过 Work 专用入口访问，不能放宽私人聊天权限。
- 任务 title≤100、goal≤32000、status 为 active/completed/archived，整数字段严格校验。所有用户文本拒绝 NUL 和不合法 Unicode。创建选 1..10 个唯一已发布 Agent，active 必须在其中，使用 UUID `client_request_id`；同 owner/key/同规范化目标与成员集合重放创建结果，内容冲突409。创建只保存任务、成员和首条 user 消息，不自动生成。
- 任务有 `version/current_run_id/active_agent_id`。编辑、成员变更和运行接纳使用 expected_version；运行占用中禁止编辑、删任务及改成员。completed 须先重新打开，archived 只读或删除；最多一个活跃运行。流增量不增加 task.version。
- 加入/显式升级成员保存 Agent 独立发布序号、名称、完整配置及不可变技能 revision/content/hash。重新发布不自动升级成员；升级请求明确预期发布序号。移除软标记，历史仍显示当时姓名/版本。重新加入按最新发布版本冻结；旧成员取消发布后禁止新运行。可用目录只返回摘要，详情不返回完整系统提示词/技能内容。
- `/api/work/tasks`：GET 分页/search/status、POST 创建；GET/PATCH/DELETE `/{id}`；POST `/{id}/members`、PATCH/DELETE `/{id}/members/{agent_id}`；POST `/{id}/runs` 接纳202；GET `/{id}/runs/{run_id}`、GET 同路径 `/events`、POST `/cancel`。新 DTO snake_case 严格输入，成员删除请求使用 query expected_version；无 body 的 DELETE 仍使用当前 CSRF/JSON 元数据约定。
- 每轮请求 `{agent_id,client_request_id,message,expected_version}`。按 task+client_request_id 幂等；同消息/成员先返回已接纳 Run，忽略之后的业务版本变化，禁止重复供应商调用和扣费；相同 key 改内容/成员409。首条目标可用创建时 key 执行，存在更晚消息时禁止倒插。明确失败后的重试换新 key。
- 模型上下文为成员冻结系统/技能、任务当前目标和“其他成员输出作为参考”的约束；共享 user/assistant 正文，assistant 添加 `[Agent: 名称; publishedVersion: N]`，不回灌 reasoning。保留最近最多96条/64KiB正文，从旧端丢弃，保留最新用户输入；完整审计和历史单独持久化。部分失败/停止正文可作为后续参考。
- 当前 Agent、冻结模型和技能仍须可用；不因为管理员调用而越权。空知识绑定直接执行；非空且检索未接通时返回 knowledge_unavailable，不伪造检索成功。之后知识库域补齐真实检索和来源。
- 接纳事务原子写消息、Run、运行关联、任务占用、Token 预留和 outbox。Run 类型 `work_turn`，仍通过 LangChain 统一 executor。取消 pending 时已知零用量且立即释放；running 仅写 cancel_requested，供应商关闭/终态提交前维持占用。worker 失联后中断、结算未知与清占用一次提交，不自动重执行。
- 运行投影将正文、reasoning、状态、用量和错误写入 Work 消息；所有 finish/cancel/recover 路径同事务清相同 current_run_id。过期 attempt 或旧运行不得覆盖新消息或清新运行占用。业务投影不进入 runtime，统一 application 协调器被 executor、取消与失联恢复复用。
- 锁序在实现中写明并测试：模型/连接→Agent→Task→技能；多资源按 ID 排序。Run 终态→用量账户→Task；接纳锁 Task 后必须先确认空闲，再取账户锁，避免 busy task 等待账户形成反向环。不得持数据库锁执行外部检索或模型 HTTP。
