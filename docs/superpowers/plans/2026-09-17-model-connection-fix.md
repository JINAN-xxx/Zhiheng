# 模型连接复用与诊断修复

用户已要求修复这类问题。已复现：硅基流动旧凭据 siliconflow-embedding 只保存 API Key；原向量部署保存 api_base。新 DeepSeek Pro 测试漏掉该地址，落到 OpenAI 默认地址，60.02 秒超时；同一凭据补齐硅基地址后 4.15 秒成功。另一完整硅基连接 3.61 秒成功。

## 设计

- 后台统一解析已有连接，凭据显式地址优先；缺失时从引用该凭据的部署中推导唯一有效地址。无地址、多个冲突地址或含敏感 URL 成分时拒绝不明确的复用；不根据凭据名称猜测。分页读取全部部署，不能只检查默认前 50 条。
- GET credentials 增加可选 connectionProfile：`{status: ready|missing|conflict|invalid, apiBase: string|null, providerIds: string[]}`。只暴露安全服务地址和允许的服务商标识，不暴露密钥。已知 OpenAI 兼容协议按服务地址区分硅基流动、DeepSeek 官方、OpenAI 官方及自定义接口；原生提供商仍按其自身引擎匹配。
- 测试和创建部署均使用同一解析结果，补入实际 api_base 并验证所选服务商与连接一致。已有凭据不被改写，成功接入的新部署明确保存解析得到的地址。
- 前端按 connectionProfile 筛选，未知或冲突连接不能自动选中。选择已有连接后显示实际地址；模型名称示例随服务商调整。旧接口数据仅用于受控兼容，不在新的接入页把未知地址的 OpenAI 协议连接视为通用连接。
- 连接测试增加可选失败类别，后端只返回有限类别对应的固定中文消息；前端使用固定映射显示超时、网络、鉴权、权限、额度、限流、模型名称和参数问题，不输出上游原文。
