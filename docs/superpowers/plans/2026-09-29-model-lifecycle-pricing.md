# 剩余模型引用与费率边界实施计划

**目标：** 完成用户明确要求的两项剩余模块化主线：模型删除引用保护和费率管理归属，随后集成回归，不再把这两项留待下次确认。

**架构：** 各模块通过声明的持久资源查询检查自己的数据，平台负责汇总；已安装插件停用后仍参与检查。模型目录通过公开费率服务管理费率，原 URL/DTO 与事务提交责任保留。已有工作区、迁移和运行服务不变。

## 1. 模型删除规则

存在持久引用即拒绝删除，包括聊天、开发密钥授权、费率/用量记录、Agent 草稿与发布配置、Work 成员快照/运行审计，以及知识库当前配置、图谱版本/预览和索引模型引用。允许停用保留引用；解除/删除相关业务数据后才能删除模型。现有“仅未发布草稿或已停用模型可删除”规则保持。

检查不可用、插件源码缺失、尚未完成升级的查询失败或元数据损坏不能视为无引用。默认空 checker 替换为明确的不可用检查器；HTTP 装配真实组合检查器。

### 所有权与并发

- 核心新增可选 manifest `backend.resourceReferences` 声明及公共查询调度。按已安装状态遍历，不能只看启用插件；保留 registry 中已安装却缺少源码的 ID，遇到它们拒绝不完整检查。调用方拥有事务。
- Agent 公开查询只访问自己的草稿/发布 JSON、成员快照及运行审计。SQL 查询在删除事务中使用当前锁定读取。创建 Agent 引用与冻结快照取得模型行锁并保持至自身事务提交，删除使用同一行锁。
- 知识库使用已有 metadata 目录中的专用跨进程锁，模型删除从检查到 SQL 提交期间持有该锁；新增数据库、修改图谱模型、构建和预览创建新引用时，在同一共享锁范围内先验证模型再写 metadata；删除使用独占锁。metadata 自身的原子事务和库级锁保留。
- 原 SQL 外键继续提供并发兜底。查询不能级联删除业务数据，也不能替调用者提交事务。

## 2. 费率服务

新增 `plugins/ai/public/rate_cards.py` 的 `RateCardService`，拥有列表、计费模式匹配、版本生成、价格字段与生效时间映射。服务返回原 RateCardModel，无 commit/rollback。ModelCatalogService 使用公开服务而不是开发接入 DAO/费率 ORM。

保留 token/search_unit 模式、max+1 版本、只追加记录、价格与时区处理。创建从模型查询开始纳入目录服务的 `_run_write`，使模型不存在或版本读取失败也正确结束事务；成功只提交一次。
