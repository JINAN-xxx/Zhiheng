# 工作空间任务 Agent

工作空间围绕目标、资料、计划和成果执行任务。新任务直接选择聊天模型和技能，按当前账号权限按需加载文件处理与代码执行工具。智能助手保留独立的配置与对话入口，工作空间不再选择助手成员接力。

本期不提供知识库检索工具，也不读取助手绑定的知识库。任务使用用户明确加入的文件、所选技能、本任务已登记的成果，以及已配置的公开网页搜索。工作空间接口属于登录 Cookie 控制台 `/api/work`，尚未提供 Bearer Key 的工作空间资源 API。

任务页使用与“对话体验”一致的消息和输入区域。输入框左下方提供“添加附件”和“技能”，技能面板按“预置技能”“我的技能”分组，支持搜索和最多 5 项多选；已选技能在输入框上方显示为可移除标签，已有任务的选择会自动保存。右侧可切换下一轮使用的模型。执行过程在助手消息内折叠展示，文件处理、代码执行和已配置的搜索工具由 Agent 按需调用。右上角“资料与成果”打开文件抽屉，保留上传、预览、下载和历史版本入口，已有成果也可从回复下方直接打开。

## 权限与资源边界

所有操作都需要 `platform:work:enabled` 和查看权限；使用、创建、编辑、删除分别检查 `platform:work:use/create/update/delete`。文件处理另需 `platform:work:execute_code`，勾选模块或授予“使用”不会自动授予代码执行。选择技能还需要 `platform:skills:use`。

每个任务属于创建人，超级管理员也不能凭管理身份读取他人的任务内容。文件仍通过公共文件服务验证当前归属、ACL、状态和 SHA-256。模型目录管理与凭据管理权限不因使用工作空间而开放。

任务受理、模型子调用和每次工具调用都会复核当前权限。执行工具按当前账号权限提供，无任务级代码执行开关。撤销代码执行权限后，普通问答和资料阅读仍可继续，执行工具会被撤下；实际调用还会复核权限。沙箱只在执行工具需要时创建；缺少沙盒时明确拒绝文件执行，不在 API 或 Worker 宿主进程执行代码。

## 配置与任务接口

| 方法与路径 | 行为与主要字段 | 操作权限 |
| --- | --- | --- |
| `GET /api/work/options` | 可选模型、技能、`can_execute_code`、`sandbox_available` | 查看 |
| `GET /api/work/tasks` | `page`、`page_size`、`search`、`status` 分页筛选 | 查看 |
| `POST /api/work/tasks` | `client_request_id`、`model_id`、可选 `goal`、`skill_slugs`、`file_ids` | 新增 |
| `GET /api/work/tasks/{task_id}` | 目标、配置、消息、计划、执行记录、资料和成果 | 查看 |
| `PATCH /api/work/tasks/{task_id}` | `expected_version` 及标题、目标、状态、模型或技能 | 编辑 |
| `DELETE /api/work/tasks/{task_id}?expected_version=...` | 删除任务，释放对应资源引用 | 删除 |

`goal` 可以留空以创建草稿；技能最多选五个。配置变更使用版本检查，执行期间不允许修改任务或输入。已受理运行冻结模型绑定、技能修订、输入文件版本及运行镜像；后续编辑不改写历史记录。

任务返回 `mode=agent`，`configuration` 为当前配置，`execution_state` 为执行状态。`status` 是任务管理状态 `active/completed/archived`，与一轮执行的状态分别保存。`members` 等历史兼容字段不作为新任务的配置入口。

## 资料与成果

| 方法与路径 | 行为 | 操作权限 |
| --- | --- | --- |
| `POST /api/work/tasks/{task_id}/files?filename=...` | `application/octet-stream` 原始请求体上传并加入任务 | 使用 |
| `DELETE /api/work/tasks/{task_id}/inputs/{file_id}?expected_version=...` | 移除未被运行历史消费的资料 | 编辑 |
| `GET /api/work/tasks/{task_id}/inputs/{file_id}/download` | 下载本任务输入原件 | 查看 |
| `GET /api/work/tasks/{task_id}/artifacts/{artifact_id}/download` | 下载指定成果版本 | 查看 |
| `GET /api/work/tasks/{task_id}/artifacts/{artifact_id}/preview` | 读取已登记预览；无独立预览时按支持格式读取原件 | 查看 |

单次上传不能为空且不超过 20 MiB；每次 `file_ids` 最多 20 个，受理时任务输入总量不超过 100 MiB。同名输入保留不同文件版本，已用于历史的资料不能直接移除。输入挂载为只读，工作目录分为 `inputs/`、`working/` 和 `outputs/`。

正式成果保存文件 ID、逻辑路径、版本、大小、SHA-256、检查结果和预览 ID。同一路径的新内容产生新版本，相同内容复用已有版本；旧版本的下载入口和字节保持。文件登记、来源引用和成果元数据使用同一事务，已提交但响应未知的对象留待核对，不误删。

正式文件和跨轮工作快照均存入平台 MinIO。沙盒临时卷承担本轮执行现场；下一轮从持久快照恢复，Python 内存变量与依赖虚拟环境不跨轮保留。空工作文件通过快照清单恢复，空正式成果明确报告无效。结构检查与 PDF 预览不能替代业务数字和版面验收。

## 执行、观察与取消

| 方法与路径 | 行为 |
| --- | --- |
| `POST /api/work/tasks/{task_id}/runs` | 使用权限；提交 `client_request_id`、`expected_version`、`message`，可附 `file_ids` |
| `GET /api/work/tasks/{task_id}/runs/{run_id}` | 查看权限；读取原生 `RunSnapshot` |
| `GET /api/work/tasks/{task_id}/runs/{run_id}/progress` | 查看权限；返回当前任务的执行状态、步骤、成果和计划。运行已离开当前任务时返回 `null` |
| `GET /api/work/tasks/{task_id}/runs/{run_id}/events` | 查看权限；SSE `snapshot` 事件及心跳，直到终态 |
| `POST /api/work/tasks/{task_id}/runs/{run_id}/cancel` | Agent 任务所有者有查看权限即可停止已有运行；旧版任务要求使用权限。持久记录取消意图并通知子调用与沙盒 |

创建时填写目标的首轮请求可复用任务的 `create_client_request_id`，`message` 与目标一致，避免重复写入首条消息。网络响应未知时使用原请求编号和相同内容确认，不另建请求。编号相同但内容不同返回 `idempotency_conflict`。

继续失败、暂停或取消的任务使用 `resume=true`、空 `message` 和新的请求编号，从可信检查点和工作快照继续，保留原用户消息及已确认的工具结果；补充信息或修改要求使用正常新消息。每个用户同时最多一个活动工作空间运行，平台沙盒并发默认最多两个。默认每轮最多 16 次模型调用、24 次工具调用和 600 秒，时限随部署的沙盒配置确定。超预算进入可继续的暂停状态，不无限自动运行。

`execution_state` 包含 `idle/queued/running/waiting_input/paused/completed/failed/cancelled`。刷新或离开页面不取消已受理任务；通过原 `run_id` 恢复观察。`steps` 保存真实模型与工具记录，`plan` 保存任务清单，`artifacts` 保存成果版本。一般工具结果很长时返回预览和执行编号，Agent 可调用 `read_history` 分页读取；已按上下文预算整理的文档页直接返回结构化正文，不再转为通用预览。

结果尚未确认的工具步骤标为 `unknown`，不自动重放可能已执行的写入；应先核对记录和已登记成果，再补充处理要求。取消会回收任务环境，但不会把已开始且未报告用量的模型调用计为零。

## 共享执行架构与工具协议

工作空间复用平台 `RunAdmission`、`RunStore`、事务 Outbox、ARQ、权限、模型目录、账本、技能修订和文件服务。父运行类型为 `work_agent`；Agent 推理和按需摘要使用原生 `work_agent_model` 子运行记录供应商用量。主 Agent 的正文直接流式进入用户会话，结束后不再额外调用独立模型改写答案；普通问答可一次调用完成，检索任务通常为“请求工具—基于结果回答”。父运行聚合展示，子调用独立准入和结算；旧 `final` 调用记录和账务保持原样。

主提示以最新用户消息为目标；感谢和认可简短回应，通用知识不为环境检测启动沙盒。提问时间以北京时间的 `request_datetime` 和 `timezone` 加入运行上下文；继续原请求保留原提问时间，保证已确认调用的恢复身份稳定。真实历史来源可用于后续对话，不能因本轮没有检索或文件就把已有结果判为无效。

有计划的任务仅在仍有未完成项目时进行一次有上下文的复核，已完成清单不额外生成一遍答案。新模型调用尚无正文时保留已经显示的内容，取消和超时继续保留部分正文。发布检查、权限校验和成果登记继续由公共工具与平台负责；普通新问题不会因历史输出而启动沙盒，显式恢复及本轮文件执行仍保留成果检查。

Agent 使用官方 LangChain `create_agent`、`TodoListMiddleware`、`SummarizationMiddleware` 与 PostgreSQL `work_checkpoints`。工具通过标准 OpenAI 兼容 `tool_calls` / JSON Schema 协议调用，模型服务必须支持这一协议。摘要依据所选模型的有效输入预算自适应计算；任务消息、审计和文件快照独立保留。

历史整理使用平台计算出的摘要输入、输出预算，并关闭 SDK 默认的 4000 Token 二次裁剪。系统前缀和当前问题使用统一的 Token 估算口径；模型窗口未知时保留保守策略，不从模型名称推测容量。无法在摘要输入预算内处理时明确暂停，原始资料和执行记录保留。

空摘要、SDK 的“对话过长无法摘要”等占位语不能替换历史，摘要调用失败也不推进可信检查点。用户明确继续任务时可以重新尝试失败摘要；同一轮的重复投递仍复用已确认调用。旧检查点若含已知失败占位语，仅沿当前任务可信检查点的父链恢复消息，保留原消息和工具结果的标识，随后重新整理上下文；不重放已经确认的工具操作，也不改写旧运行。缺少可信祖先时暂停并明确提示，不借用其他任务的历史。

| 工具 | 用途 |
| --- | --- |
| `list_inputs`、`inspect_file` | 查看本任务资料和文件结构 |
| `read_document` | 按可用上下文预算读取全文或分页，支持长段落、长表格的段内续读，返回真实文件来源 |
| `read_sheet` | 有界分页读取表格，返回真实文件来源 |
| `load_skill` | 加载本任务已选技能固定修订的说明、文件清单和沙盒路径 |
| `load_tools` | 按当前权限加载需要的工具组，加载结果写入执行记录与检查点 |
| `write_todos`、`request_input`、`read_history` | 更新计划、请求必要信息、核对执行记录 |
| `run_python`、`execute` | 在隔离环境执行代码与命令，按需声明 Python 索引依赖 |
| `write_file`、`read_file`、`list_files` | 操作任务工作目录 |
| `publish_outputs` | 检查并登记正式成果与预览 |

最后三组文件执行工具按当前账号的 `platform:work:execute_code` 权限提供，无需手动开启。技能正文是处理方法，上传文件是待处理资料，不能改变平台权限和系统规则。工具输出的 NUL 等控制字符用可见 Unicode 转义展示，原文件和快照字节保持原样。

## 技能包文件与脚本

所选技能的主文件、脚本、参考资料和二进制资源统一来自受理时冻结的修订。读取包前复核当前账号归属、技能可用状态和修订身份，随后校验原包 SHA-256 和解析后完整目录树哈希；继续使用上传时的安全解析器，拒绝路径穿越、链接和超限压缩包。技能更新不会改写已受理运行中的文件；新一轮按当前任务配置选择最新修订。

`load_skill` 返回 `revision_id`、`workspace_path`、`files` 和 `instructions`，不创建沙盒或自动执行脚本。首次使用文件执行工具时，全部已选技能文件放入 `inputs/skills/{slug}/` 只读目录；路径相对于 `/workspace`。按需加载相应工具组后，可用 `read_file` 读文本，用 `run_python` 或 `execute` 运行脚本。中间文件放在 `working/`，正式成果放在 `outputs/` 后发布。创建后续沙盒时从本轮固定修订重建技能目录，不要求重放检查点中已完成的 `load_skill`。

每个包继续受上传 10 MiB、展开 30 MiB、200 个文件的限制，全部资料与工作现场还受沙盒总大小限制。Python/Shell 沿用现有隔离环境和依赖规则。工作空间通过已开放的工具访问外部资源。

## 按需工具加载

工作空间保留原有 15 项业务工具，并增加 `load_tools` 发现入口。默认仅向模型提供 `list_inputs`、`read_document`、`read_sheet`、`load_skill`、`request_input`、`write_todos` 和 `load_tools`；已配置并受理了联网搜索能力的任务再提供 `web_search`。文件结构检查、完整历史和沙盒操作按需加载，无需用户按钮或额外模块开关。

`load_tools` 的参数为 `groups`，取当前工具 Schema 中允许的一个或多个分组：

| 分组 | 加载的工具 |
| --- | --- |
| `inspection` | `inspect_file`、`read_history` |
| `python` | `run_python`、`list_files`、`read_file`、`write_file`、`publish_outputs` |
| `shell` | `execute`、`list_files`、`read_file`、`write_file`、`publish_outputs` |
| `files` | `list_files`、`read_file`、`write_file`、`publish_outputs` |

`python`、`shell`、`files` 沿用 `platform:work:execute_code` 权限。加载请求包括缓存复用都会重新鉴权；加载不启动沙盒，也不授予执行权限。实际文件或代码操作继续通过公共服务进行当前权限校验。普通账号没有代码执行权限时，加载 Schema 只提供 `inspection`，旧检查点中的加载标记也不能开放执行工具。

工具组加载状态保存在官方检查点中，同一模型响应并行加载多个组时合并结果。继续任务保留已经加载的组，避免重复准备；正常发送新的用户消息时重置为轻量工具集。已有可信检查点若保存了旧版本待执行调用，仅恢复该检查点中的真实调用，继续遵守当前权限；新调用不能绕过加载步骤直接使用隐藏工具。旧节点标识、工具名称和已确认结果保持，HTTP 路由、任务配置及角色管理接口不变，无需数据库迁移。

模型输入预算与摘要阈值按当轮实际提供的工具定义计算。沙盒运行说明在相应工具组加载后注入；Python 任务优先使用 `run_python`，命令行程序使用 `execute`，办公原件与沙盒文本分别使用对应读取工具。生成文件后仍需 `publish_outputs` 校验和登记，平台结束阶段继续执行成果检查。

## 文档读取与完整性

已知任务文件编号时，Agent 可以直接调用 `read_document`，无需先调用 `inspect_file`。`file_id` 保持必填；`start` 默认 1；`limit` 可省略或为 `null`，表示按预算自动选择数量，也继续接受指定文本块数量；新增 `offset` 默认 0，表示首个文本块内的 Unicode 字符位置。

| 返回字段 | 含义 |
| --- | --- |
| `unit`、`total`、`items` | 保留真实文本块、行或页编号与正文 |
| `start`、`offset` | 本次读取的开始位置 |
| `next`、`next_offset` | 后续读取的文本块编号和段内字符位置；必须一起传回 `start`、`offset` |
| `has_more`、`truncated` | 后续仍有未返回的原文；不能据此声称已经读完 |
| `complete` | 仅本次响应从文档开头覆盖至结尾时为 `true`；分批读取需结合各次范围判断覆盖完整性 |
| `textless_pages` | PDF 中未提取到文字的页面；可能需要 OCR，不能把文字提取覆盖等同于理解了扫描页面 |
| `read_mode` | 新读取结果为 `budgeted`，正文已按预算整理，不再套用一般工具预览 |

预算使用当前所选模型窗口、输出预留和平台输入上限，并扣除真实系统提示、已加载技能、历史消息、工具描述和安全余量。消息与工具描述使用同一套 Token 估算规则，摘要触发阈值同步扣除非消息占用。需要继续分页时，正文页最多使用本次可用工具结果预算的一半，为下一次读取保留空间，避免最新 AI/工具消息对占满窗口。同一次模型响应的多次工具调用共享剩余预算；恢复待执行工具时，从可信检查点计算历史占用。未配置模型容量和平台输入上限时，以 65536 Token 作为本地读取预算上限，不宣称供应商具有该容量，也不根据模型名称推断 1M 窗口。预算不足时返回明确错误，不无声丢弃原文。

文档解析复用公共文件读取器及其受限子进程。DOCX 和文本按原文保留长段落、表格；较大 PDF 按最多 32 页的解析窗口推进，模型输入仍受剩余 Token 预算限制。单次文档正文页最多 131072 字符、512 KiB，提取文字资源限制为 8 MiB；这些是本地资源保护，不是模型容量。缓存以内容 SHA-256、格式和 PDF 窗口为键，最多 32 项、估算内存合计 16 MiB，5 分钟过期；过大的解析结果不缓存。每次读取仍重新验证文件权限与内容完整性，缓存不绕过权限。

HTTP 路由保持不变。新的读取参数和元数据向后兼容已有显式分页调用；旧确认结果和运行记录不会被自动重写或重放。

## 内置网页搜索

后台配置 `CORE_BOCHA_API_KEY` 后，工作空间自动提供 `web_search` 工具，模型按任务需要调用。无需用户联网开关或单独权限，继续沿用工作空间的使用权限和任务归属校验；未配置密钥时不注册该工具，其他任务能力照常运行。

工具参数为 `query`、`count`（默认 5，最多 10）和 `freshness`（`noLimit`、`oneDay`、`oneWeek`、`oneMonth`、`oneYear`）。结果包含真实标题、URL、摘要、站点、发布时间及查询时间；摘要不代表已读取网页全文。网页来源链接通过现有回答展示，查询、结果或错误保存在执行记录中。搜索在后端完成，不改变沙盒的网络隔离，也不向模型或前端提供服务密钥。

请求默认超时 15 秒，可通过 `CORE_WEB_SEARCH_TIMEOUT_SECONDS` 配置。博查费用与资源包由该服务商账户承担；平台不把搜索请求折算为模型 Token 或重复扣模型积分。额度不足会明确提示，需补足服务商额度后重试。

每个已受理运行默认最多 6 次搜索尝试，缓存复用不重复请求服务商；提示词引导普通查询优先一次检索，只有缺关键事实时再集中补查。额度不足、服务拒绝、未配置或无效响应会停止当前轮继续搜索，并从下一次模型调用的工具清单中撤下 `web_search`；同批已排队的搜索返回现有失败原因，不再请求服务商。结果包含 `search_policy`，说明剩余尝试次数、可用状态和停止原因。新一轮用户消息可重新尝试，旧运行恢复从自己的执行记录恢复预算；结果未确认的网络请求仍进入暂停核对流程，不自动重发。禁网沙盒不能作为搜索失败后的联网替代。

## 旧任务与升级

迁移 `0041_work_agent` 增加新任务配置、计划、步骤、成果、沙盒租约及官方检查点 schema。原成员任务保留为 `mode=legacy`，可查看历史和原运行，可按已有删除权限移除；不能继续发送消息、编辑成员或升级为新 Agent。需要继续处理时创建新任务并明确加入所需资料。

`0043_workspace_execution` 清理了任务级执行开关。已执行 `0041_work_agent` 的实例可按[部署说明](../deployment.md)升级至最新版本，补齐助手附件并保留工作步骤、成果版本及检查点。

旧 `/members` 写入路由及 `/agents/available` 已标为 deprecated，不能作为新工作空间客户端的成员入口。升级仍须备份、显式迁移并统一重建 API/Worker，不在服务启动时自动修改表结构。
