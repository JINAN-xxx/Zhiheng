# 知识库固定重排策略

知识检索必须具有有效的重排模型，召回候选后进行重排，再形成最终结果。没有候选时返回空结果，不调用重排模型。缺少配置、模型停用、连接不可用、重排调用失败时明确报错，不将未重排候选作为成功结果返回。

库内重排仅支持“使用默认重排模型”或指定已启用且连接可用的重排模型，不提供“不使用重排”。默认项显示实际模型名称；默认不可用时禁用该项，已有库可选择具体有效模型。联合查询的库配置不一致时，统一使用有效的默认重排。

默认重排是平台知识服务的必需配置，不能清空。新建知识库使用默认重排，默认重排缺失或不可用时拒绝创建，即使请求显式指定向量模型也无法跳过。新建界面同时检查默认向量与重排服务状态，库内设置保存及后端检索入口再次验证有效重排模型。

重排模型、继承方式的变更只影响新检索，不重建已有向量索引或资料副本。向量模型、切片参数变化仍沿用显式确认重建流程。已经接纳的检索使用冻结的重排模型和候选，恢复或重放不会重新召回或重复计费，模型与来源权限仍在执行前复核。

使用对象授权密钥直接检索已有知识库时，在应用「资源授权」中允许该库的检索动作，再在签发页勾选「知识检索」和目标知识库的「检索」动作。平台依据库配置执行向量检索和重排，并按实际模型用量计费。通过助手内部检索时，签发页选择「智能体调用」和对应助手即可。参见[多用途密钥示例](developer-keys.md)。

普通检索、聊天与其他业务的知识准备、图谱检索使用同一必需重排约束。暂时性重排错误不再沿用召回顺序；图谱 SDK 捕获重排异常后尝试降级时，适配层会保留并重新抛出错误。失败诊断保留重排任务与原因，界面显示明确错误并保留检索输入。历史记录中原有的未配置、降级诊断继续可读，新检索不再产生这些成功状态。

## 智能助手配置

智能助手通过 `knowledge_top_k` 设置多库合并重排后用于回答的片段总数，默认 8，支持 1–15 的整数。该上限在每轮受理时冻结，适用于配置调试、正式助手会话与对外推理；实际片段数还受候选数量、当前来源权限和上下文大小限制。普通知识检索与资源检索 API 的 `top_k` 仍为 1–8，候选池仍为每库最多 40、联合最多 80。新工作空间使用任务明确加入的资料，本期没有知识库检索入口；旧成员任务仅保留历史读取。

选择知识库后，由后端返回当前生效的重排模型和来源。所选库均显式使用同一重排模型时沿用该模型；均继承默认或配置不一致时使用平台默认重排。保存、启用和实际执行都会检查模型及连接可用性，配置展示不调用付费模型。旧助手未保存该字段时按 8 处理，不需要数据库迁移。

## API

知识准备传给模型的引用使用 `[1]`、`[2]` 等本轮数字编号，按最终片段结果中 `(knowledge_base_id, document_id)` 首次出现的顺序编号，同一文档的多个片段共用编号。控制台正文引用与下方文档列表使用同一顺序，可点击引用预览对应资料，预览和下载继续执行原有权限检查。历史回答中与真实来源匹配的 UUID 引用会显示为数字编号，不改写已存储的回答或代码块。

`hits`、助手 `sources` 中的 `source_id`、`document_id`、`file_id`、`chunk_id` 等字段仍保留真实标识，接口结构不变。API 调用方可按上述顺序建立回答引用与资料的对应关系；数字编号仅在对应回答内有效。

- POST `/api/agents/knowledge-policy` 接收 `knowledge_base_ids`，逐库检查访问权限后返回 `model_id` 和 `source`；`source` 为 `knowledge_base`、`platform_default` 或 `mixed_platform_default`。
- GET /api/knowledge/capabilities 保留 default_embedding_configured，增加 default_rerank_configured 和有效的 default_rerank_model_id。
- PATCH /api/knowledge/settings 不接受清空默认重排；部分更新未提供该字段时，现有默认重排仍须有效。
- PATCH /api/knowledge/bases/{id}/settings 使用默认时传 use_default_rerank=true、rerank_model_id=null；使用指定模型时传 false 和非空 UUID。不支持 false/null，也不忽略 true/非空 UUID 的矛盾配置。
- POST /api/knowledge/bases 和检索接纳会拒绝缺失、类型错误或不可用的有效重排模型。

## 升级

迁移 0024_knowledge_rerank_required 将旧的“关闭重排”库转换为继承默认，增加库设置版本；保留原有明确模型选择、资料、索引、分享成员和账务数据。数据库约束禁止再次保存关闭状态。未初始化的默认配置仍可读取，但管理员必须选定有效重排模型后才能保存有效配置和创建知识库。降级不会自动恢复关闭重排。

不选择或自动替换管理员的具体模型，不调用真实模型验证配置，不因重排变化触发全库重建。
