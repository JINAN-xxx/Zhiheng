# 私人智能助手与正式对话

私人助手由迁移 `0040_assistant_agents` 引入，开发者密钥对象授权由 `0044_key_object_grants` 引入。助手维护最新配置与启用状态，保存后用于下一次调用。正式会话与外部 API 要求启用。

## 配置与操作

配置包括模型、提示词、欢迎语、温度、输出长度、技能和知识库。输出长度必须符合模型配置。启用和停用使用 POST /api/agents/{agent_id}/enable 与 /disable，请求携带当前 expected_version，防止并发覆盖；它不是可选择的历史发布版本。

私人使用无需绑定开发者应用。通过外部 API 调用时，助手须绑定密钥所属的启用应用。打开助手的「API → 创建密钥」可快捷签发仅允许调用此助手的密钥。若还需调用其他助手、直接调用模型或使用资源 API，请在「开发接入 → 访问密钥」中组合授权。

对象授权密钥须含 `agents:invoke` 和当前助手的 `agent_id`。助手内部使用模型和检索依赖所产生的用量计入调用密钥及其所属账户。升级至对象授权后，外部客户端须使用重新签发的开发者访问密钥。参见[访问密钥管理](developer-keys.md)。

使用 `POST /v1/agents/{agent_id}/chat/completions` 发起外部调用，助手 ID 可在「API」抽屉的调用地址中取得。关联知识库时，为每个新问题生成一个 UUID 作为 `client_request_id`。收到 HTTP 202 后，用同一把密钥轮询返回的 `polling_url`。状态为 `admitted` 时用相同标识及原请求体再次提交，获取回答。

已受理的 Run 保存实际输入、模型绑定、技能修订、来源和费用事实。更新配置不能改写正在执行的请求。知识准备期间依赖变化会要求重新发送。停用后不接纳新正式调用，排队调用在执行前复核启用状态与权限。

## 会话与记忆

会话按用户、助手和会话隔离。管理员不自动获得其他用户的私人会话。欢迎语仅展示，不发送给模型，不产生推理费用。

正式会话使用持续 checkpoint 和自动摘要，保存完整业务问答。系统按模型输入容量整理较早历史并保留近期原文；摘要和主回答各自记录模型用量。配置调试和外部 API 每请求独立，调用方提交自己的 messages，不会共享服务器隐式记忆。

知识检索使用已有持久准备链，检索原文只作为本轮参考资料，不累积进用户问题。历史回答与摘要涉及的知识来源也会复核权限；资料被撤权或移出配置后，请新建会话。技能提供冻结指令，上传脚本不会自动执行。

刷新、断线、关闭页面后只恢复观察原 Run，不重新调用模型。相同请求标识返回原结果，内容变化返回冲突；同一会话不同时受理两个主回复。

## 网页接口

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | /api/agents/{agent_id}/conversations | 本人的会话列表，支持 before 游标 |
| POST | /api/agents/{agent_id}/conversations | 使用 client_request_id 幂等创建 |
| GET | /api/agents/{agent_id}/conversations/{conversation_id} | 会话及问答，支持更早消息游标 |
| PATCH | /api/agents/{agent_id}/conversations/{conversation_id} | 使用 title 和 expected_version 重命名 |
| DELETE | /api/agents/{agent_id}/conversations/{conversation_id} | 使用 expected_version 删除，成功返回 204 |
| POST | /api/agents/{agent_id}/conversations/{conversation_id}/runs | 提交 message 和 client_request_id，返回 Run 或知识准备信息 |
| GET | /api/agents/{agent_id}/conversations/submissions/{request_id} | 按 `create_id`、可选 `conversation_id` 和 `plaza` 查询本人请求的受理状态 |

运行查询、SSE 与停止继续使用 /api/runs。会话 DTO 的 version 用于并发修改校验；memory_available 表示能否继续新版记忆，summary_used 表示已接受记忆是否使用过摘要。回合保存助手名称与对应 Run，不再携带发布版本。

浏览器只保存待确认提交的标识，消息和附件信息只在当前页面内存中保留。刷新后按原标识查询受理状态。若已受理则打开原会话。若暂未查到，则由用户重新输入和选择附件，发送仍使用原请求 ID，避免与迟到的原请求重复受理。查询只返回 `conversation_id` 和 `accepted`，限定当前账号、助手和会话场景。

## 删除与升级

删除要求当前会话没有正在检索、排队或生成的主回复。已删除会话从列表、详情和对应内容读取入口隐藏；原创建请求不能恢复它。后台独立回收 SDK 状态，原 Run、审计与账务保留。

升级保留旧问答和精确调用快照。旧会话只读，新建会话使用自动记忆；不自动导入或清空历史。迁移前完成或明确取消活跃助手/Work 运行与知识准备，备份数据库，再统一升级 API 与 Worker。

执行、摘要计费和存储边界见[智能助手执行与记忆](../architecture/assistant-langchain.md)。

## 助手广场

授予「智能助手 → 广场发布」后，维护人可以在「我的助手」上架、更新或下架自己的助手。保存草稿后须执行「更新广场版本」才会更新广场。停用会暂停访问，重新启用恢复已上架版本。超级管理员可以从广场紧急下架。下架按上架版本校验，成功返回 204。

上架可选「所有可使用助手的账号」或一个有效部门。绑定知识库时需要明确确认授权，且知识库须由上架人拥有并已迁移到库级资料权限。使用者通过当前助手检索获准资料。查看、下载原文以及其他入口仍执行自身权限。下架或更新版本移除资料后，旧会话不会继续将已撤回的资料用于新回答。API 应用可以保留绑定，外部调用按现有 Key 授权。广场助手可绑定平台技能或发布者的个人技能。每次受理按发布者解析技能并保留执行快照。使用者可通过该助手使用绑定的个人技能，技能目录、详情和文件下载继续检查所有权。

广场详情只返回公开展示信息。拥有助手使用权限的用户可通过广场建立自己的会话，历史和用量按调用者记录。下架或停用后停止新调用，既有会话可在广场的「历史记录」中打开。

`GET /api/agents/plaza/history` 每次最多返回 12 条本人创建的广场会话，按创建时间倒序。传入本页最后一条会话的 ID 作为 `before` 继续读取。接口只接受本人的广场会话作为游标，下架后仍可读取和打开已有会话。

广场会话保留创建时的名称、简介和欢迎语。每次提交使用当时已上架的执行配置，并在运行审计中记录发布版本。只修改展示信息不会使已排队请求失效。模型、提示词等执行配置更新后，尚未开始的旧请求会要求重新发送。已下架版本不接受新消息，已有会话历史仍可查看。
