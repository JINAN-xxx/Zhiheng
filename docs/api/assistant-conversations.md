# 私人智能助手与正式对话

助手会话所需迁移版本：`0033_assistant_session_actions`。

侧栏“智能助手”展示本人拥有的助手。点击“使用”进入正式对话页面，沿用对话体验的消息与输入样式。顶部“历史记录”弹窗支持切换会话，并可通过每项的更多操作重命名或删除。也可新建会话、继续对话、停止生成或恢复观察。草稿调试保留在配置页与列表更多操作中；现有 `/preview` 和对外推理 API 继续使用原协议。

## 配置更新

- 正式使用要求助手已发布。私人发布不要求绑定开发者应用；开放外部 API 仍要求应用、Key、模型和 Scope 授权。
- 重新发布后，已有会话的下一条新消息采用最新发布的提示词、模型设置、技能与知识库配置。
- 已接纳的模型 Run 使用接纳时保存的请求，已有回复保留，不改写历史正文。
- 每轮保存使用的发布版本与助手名称，供运行追溯；用户不用选择版本。
- 草稿修改不直接影响正式使用，发布后才生效。
- 取消发布或删除助手后，不再接纳新的正式调用；历史会话仍按本人所有权保留。排队调用在执行前复核可用性。

## 会话与权限

会话按“用户—助手—会话”隔离。助手 ID 和会话 ID 都必须与当前用户匹配，管理员身份不自动越过这个边界。本版本没有共享助手或共享会话功能。

历史消息保存在 PostgreSQL。助手正文和运行状态使用既有 Run 持久投影；用户刷新、断线或关闭页面不会重新提交已接纳调用。会话和消息都支持游标读取。

模型上下文只使用当前会话内、已完成的近期问答，并遵循助手配置的历史轮数与上下文大小约束。不会混入其他会话。欢迎语在左侧使用与助手回复相同的 Markdown 消息组件，初次进入或新建对话时逐字显示，不发送给模型，不产生调用费用。

请求沿用 Outbox、Worker、LangChain 模型适配、用量预占与结算。绑定知识库时先走现有持久检索准备，再接纳主运行；来源展示复核访问权限。

## 新增网页接口

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | `/api/agents/{agent_id}/conversations` | 本人的助手会话列表，支持 `before` 游标 |
| POST | `/api/agents/{agent_id}/conversations` | 使用 `client_request_id` 幂等创建会话 |
| GET | `/api/agents/{agent_id}/conversations/{conversation_id}` | 会话信息和消息，支持更早消息游标 |
| PATCH | `/api/agents/{agent_id}/conversations/{conversation_id}` | 使用 `title` 与 `expected_version` 重命名；标题去除首尾空白后需为 1–100 字 |
| DELETE | `/api/agents/{agent_id}/conversations/{conversation_id}` | 使用 `expected_version` 删除会话，成功返回 204 |
| POST | `/api/agents/{agent_id}/conversations/{conversation_id}/runs` | 提交 `message` 与 `client_request_id`，返回 Run 或知识准备信息 |

运行查询、SSE 与停止继续使用现有 `/api/runs`。请求标识与内容绑定，重复提交返回原运行，改变内容返回冲突；同一会话不同时接纳两个主回复。

浏览器在会话存储中保存待确认提交的原标识。网络结果未知时提供“确认原提交”，沿用原命令读取或恢复结果。正式收到接纳信息后清除待确认凭据。

数据库升级新增会话与回合表，原助手配置、API、聊天、工作记录和计费数据保留。降级遇到已有助手历史时会中止，要求先保存数据。

会话 DTO 包含 `version`。管理操作按版本检查并发修改，过期版本返回 409。重命名不改变消息与助手配置；首次发送也会保留用户自定义的标题。删除要求当前会话没有正在检索、排队或生成的回复。删除后的会话从列表、详情及对应运行读取入口隐藏，原创建请求标识不可恢复已删除会话。运行和计费记录保留用于结算与审计。

点击发送后，页面立即清空输入框并在右侧显示问题；提交等待、知识检索、检索失败与停止状态统一显示在对应的左侧助手消息中。会话详情新增 `preparing_message`（活动检索的原请求标识与问题），检索期间刷新或重新进入时可从后端恢复展示；回合 DTO 的 `request_id` 用于将临时消息与已持久化回合合并，避免重复问题。
