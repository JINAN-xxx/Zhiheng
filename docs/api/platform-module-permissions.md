# 模块开关与操作权限

角色权限采用单列模块树：模块总开关下面集中展示查看、新增、编辑、删除及该模块特有操作。前台应用与后台管理使用相同结构；全选仅作用于当前模块。

## 开关语义

每个模块使用 `命名空间:模块:enabled` 作为总开关，例如 `platform:knowledge:enabled`。操作使用独立代码，例如 `platform:knowledge:create`、`platform:knowledge:delete`。

- 开启模块不会自动全选操作。
- 查看是基础权限。勾选其他操作时前端补选查看；取消查看会同时取消本模块其他操作。后端拒绝缺少查看依赖的角色授权。
- 关闭模块只移除 enabled，保留子操作设置；这些子项在后台不生效。重新开启后恢复原勾选。
- 模块没有查看权限时不会显示菜单，直接访问地址或接口同样受限。
- 新角色默认全部关闭，不自动添加固定基础角色。
- 每个角色先过滤模块关闭后的无效子项，再对多个启用角色的有效授权取并集；其他角色的查看权限不能激活已经关闭的角色子项。关闭一个角色的模块不覆盖其他角色仍授予的权限；用户有效权限页面可以查看授权来源。

GET `/api/admin/permissions` 返回模块与操作两类条目：kind 为 module/action，操作包含 parent、module、action。角色 DTO 保留完整设置，GET `/api/auth/me` 只返回当前生效的权限。

## 核心模块

| 模块 | 子操作 |
| --- | --- |
| 工作台 | 查看 |
| 对话体验 | 查看、使用、编辑会话、删除会话、分享回复 |
| 智能助手 | 查看、使用、新增、编辑、删除、草稿调试、发布与撤回 |
| 工作空间 | 查看、使用、新增、编辑、删除 |
| 模型目录 | 查看、查看配置、新增、编辑、删除、启停、试用与连接测试 |
| 知识库 | 查看、检索、新增、编辑、删除、导入资料、重建索引、共享管理 |
| 技能 | 查看、使用、新增、编辑、删除、启停 |
| 开发接入 | 查看、新增应用、编辑应用、删除应用、启停应用、签发/轮换/撤销/删除 Key、资源授权、API 调用 |
| 用量与调用 | 查看本人记录 |
| 凭据管理 | 查看连接信息、新增、编辑、删除、启停 |

用户管理、角色管理、部门、参数、公告、日志、在线会话、监控、积分、费率和存储等后台模块使用同样的 enabled + 操作格式。重置密码、分配角色、配置角色权限、发布公告、积分调整与用量核对等分别授权。

功能权限不扩大资源归属：私人助手、会话、知识库、技能、应用与文件仍遵循现有所有权和 ACL。超级管理员身份不变，系统保留既有内置角色与最后管理员保护。

## 模型和凭据独立

模型目录使用 platform:models，凭据管理使用 ai:credentials。两者有独立总开关；模型目录全选不会勾选任何凭据权限。

模型配置人员通过 GET `/api/models/connection-options` 选择已有连接，仅获得 ID、名称和启用状态。服务商地址、密钥配置状态由凭据接口提供，必须拥有凭据模块及查看操作。已保存的完整密钥不明文回读。

凭据管理使用独立入口 `/credentials`，不会因此开放 `/models`。新增、编辑、删除和启停在服务层分别校验。模型配置新增权限不能删除模型，也不能修改凭据或发起测试。

## API 与异步执行

Key Scope 协议和现有 API 路径保留。实际权限取账号当前操作权限、应用与 Key 状态、Scope、模型允许列表、应用资源授权及当前 ACL 的交集。

Scope 中 knowledge:write 不能绕过角色中“只允许新增、不允许删除”的限制；每个资源接口及原请求恢复分别检查具体操作。API 排队步骤执行前重新读取权限；模块关闭、角色停用和撤权会阻止后续执行。

Key 签发、轮换、撤销、删除及实际 API 调用分别授权。模型 API 不依赖模型目录管理入口，但必须拥有开发接入模块、查看和 API 调用操作。知识库、技能、助手调用还需要相应操作权限。

Cookie 和 Bearer 不互相替代；跨用户、跨应用的 Key、资源与嵌套 ID 保持隔离。

## 升级

迁移版本为 `0034_permission_tree`。升级前备份数据库；将已有明确授权转换成对应的门控操作组合，并增加角色版本，防止旧页面覆盖授权。

旧“知识库使用”转换为查看、检索；旧“维护知识库”转换为新增、编辑、删除、导入和重建，不附加共享或检索。旧模型配置权限只转换模型操作，不产生凭据权限。不会创建默认角色或扩大原授权范围。

角色设置仍保存在现有 permissions JSON 中。停用模块时保存的子项可以被角色管理员查看与恢复。降级遇到门控授权时会中止，要求先恢复经过核对的权限备份。
