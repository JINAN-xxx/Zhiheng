# 应用治理与个人隔离

已确认规则：个人应用、密钥、智能体和工作任务继续按本人隔离，超级管理员没有个人内容读取或代签发密钥的例外。后台“用户管理 → 应用治理”单独提供平台容量和启停控制。

治理接口仅接受当前有效的超级管理员 Console Cookie。普通用户、用户管理角色、积分维护角色和 Bearer Key 均不能调用；跨站写入仍被拒绝。

| 接口 | 能力 |
| --- | --- |
| GET `/api/admin/applications` | 分页读取应用标识、名称、所有者标识、用户／平台状态、容量上限及原始文件计数；可按 owner_id 筛选 |
| PATCH `/api/admin/applications/{id}/state` | `{enabled, expected_version}` 调整独立平台开关 |
| PATCH `/api/admin/applications/{id}/resource-quota` | `{source_file_limit, source_byte_limit, expected_version}` 修改容量上限 |

列表不返回私有配置、资源清单、调用内容、密钥或密钥派生信息。接口不提供名称修改、资源绑定、删除应用或创建密钥等管理动作。个人 `/api/developer/applications/...` 入口始终验证所有者。

所有成功治理写入都递增应用版本并记录审计，旧版本返回409。文件数量上限为正 int32，字节上限为 JSON 可精确传输的正整数；不通过改变额度删除文件或改写账本。

`platform_enabled` 与用户自己的 `status` 分开。平台停用后，Key 的创建、轮换、新调用和接纳后未开始的执行会复核平台状态；用户不能用原有启用动作解除平台停用。管理员恢复平台开关不会覆盖用户自己已停用的状态。已发生的上游调用继续按冻结身份及实际用量结算，不因为开关改变取消费用。

升级0029为已有应用设置平台允许，保留原用户状态、版本、Key和账本。存在未删除的平台停用应用时拒绝降级，避免旧代码误将其恢复可用。

## 存储治理

存储模块启用且有查看权限后，`ai:storage:configure` 管理保留策略，`ai:storage:maintain` 执行对账、隔离和验证修复，`ai:storage:delete` 执行批量永久回收；这些操作分别授权。批量永久回收只选择已到回收期的文件；业务引用、派生产物及保留保护继续复核。维护权限不允许通过普通文件详情／下载接口获取他人私有内容，也不允许直接调用个人文件清理接口绕过所有者。

存储用户目录还需相应用户目录权限。知识库只通过邀请明确加入，不再用知识库所有者身份枚举平台账号或使用已关闭的 ACL 修改接口。
