# 代码规范

适用于后端核心、前端业务模块、维护脚本和测试。依赖边界以架构检查器和模块公开接口为准。

## 1. 组织与依赖

1. 一个业务模块必须明确资源、数据和公开接口的所有者；按职责命名，不使用含义不清的 manager、helper、common_service 作为长期归宿。
2. 模块内部使用普通函数和少量类；按真实复杂度拆文件，不为简单 CRUD 建立成套工厂、基类和转发服务。
3. 其他模块只访问 public.py 暴露的契约。HTTP 入口、跨模块用例装配和测试替身使用明确的允许入口清单。
4. shared 只承载少量公共值类型、Principal、基础错误和不依赖业务的协议；shared 不导入业务模块、FastAPI 或供应商 SDK。
5. infrastructure 提供数据库连接、Redis、对象存储等技术实现，不承载模型授权、聊天规则、配额结算等业务政策。
6. 供应商、LangChain/LangGraph、文档解析器等适配留在所属模块；框架类型只在适配边界出现。
7. 公共接口返回值对象或 schema，不返回 ORM、数据库 session、供应商客户端或包含密钥的配置。
8. 顶层导入不读取实例配置、不连接服务、不建表、不启动任务；资源由 bootstrap 显式装配。
9. 跨模块禁止直接操作对方 ORM、仓储、私有函数和运行时装配；通过 AST/import 检查实施，覆盖函数内导入与动态导入。
10. 对静态检查无法解析的动态导入采用注册清单，不用拼接模块路径作为业务装配机制。

## 2. 命名与文件

| 对象 | 规范 |
| --- | --- |
| Python 包、模块、函数、变量 | snake_case；模块名全小写 |
| Python 类型 | PascalCase；异常以 Error 结尾 |
| Python 常量 | UPPER_SNAKE_CASE |
| Vue 组件 | PascalCase.vue |
| TypeScript 普通文件、函数、变量 | camelCase；composable 使用 use 前缀 |
| 接口字段 | 新 HTTP JSON 使用 snake_case；兼容接口由 adapter 显式转换 |
| 标识符 | 使用业务名称，如 model_id、run_id、invocation_id，不使用无上下文的 data1、obj2 |
| 状态和事件 | 使用枚举或 Literal/判别联合；状态迁移集中定义 |

ORM 使用 orm.py 或 orm/，请求响应使用 schemas.py，业务服务使用 service.py 或 services/，数据访问使用 repository.py 或 repositories/。只有职责复杂后才拆成目录。

评审时关注组件/函数是否承担多个职责；行数用于提示，不作为强制拆分成碎片的理由。避免以“便于扩展”为由预建未使用的抽象。

## 3. Python 基准

- 新平台首版最低 Python 版本为 3.10；依赖锁定与 CI 需验证最低支持版本。
- Ruff 负责 lint、import 排序和格式化；沿用 120 列、单引号。开发、CI、镜像使用同一固定工具版本。
- CI 只检查，不运行 unsafe 自动修复；需要自动修复时审查 diff。
- 新核心包启用 Mypy；公共函数、跨模块协议、状态和持久化返回类型必须完整。
- 禁止在公共边界使用 Any。第三方无类型返回值在 adapter 内收敛为明确的 TypedDict、dataclass 或 Pydantic schema。
- Pydantic 校验 HTTP、文件导入、持久队列 payload 等外部边界；内部已成立的类型和约束不逐层重复解析。
- 模型能力不支持时返回稳定的能力错误，不能静默丢弃 tools、视觉、结构化输出等参数。
- 使用枚举或判别联合表达有限状态，避免动态增加字典键来承载运行状态。
- 跨模块公共接口使用关键字参数表达业务上下文。参数多时引入有意义的请求值对象，避免十几个标量位置参数。
- 只为需要替换、测试隔离或跨模块协作的边界定义 Protocol。

## 4. 异常、日志与配置

- 统一 AppError 的 code、message、http_status、可公开 details；API 错误适配在统一处理器完成。
- 业务预期错误与编程错误分开处理。未知异常记录 trace_id，返回固定的内部错误，不输出堆栈或密钥。
- 禁止吞掉异常后返回空结果或成功；可选能力失败以明确的 degraded/不可用状态表达。
- 避免为普通错误类增加不可变元编程、构造令牌、pickle 支持和多层索引工厂。
- 日志使用结构化字段：trace_id、request_id、run_id、attempt_id、invocation_id；原始提示词和正文按配置脱敏或不记录。
- 不记录 API Key、JWT、Pepper、数据库密码、供应商响应中的凭据。
- 运行配置由 bootstrap 加载并通过构造参数传入；业务代码不随处读取环境变量或全局 app.state。
- 模块级配置不伪装成系统全局常量；需要热更新的业务配置由持久化所有者管理，并有版本化失效规则。

## 5. 数据库、事务与时间

1. 一次用例只有一个事务所有者：单模块命令服务或跨模块 application 用例。
2. Repository 接收 session，不自行 commit/rollback，也不在异常时替调用者更换 session。
3. 外部模型请求、解析器调用、向量库请求不占用业务数据库长事务。
4. 请求接入和待投递事实同事务落库；提交后投递队列。投递失败由 outbox publisher 补发。
5. PostgreSQL 保存业务事实；Redis 维护投递、事件和可重建协调状态。跨存储一致性使用明确的补偿与幂等设计。
6. 金额和费率使用 Decimal；分别记录实际用量、上游成本和平台计费结果，不用 float 计算金额。
7. 时间字段使用带时区 UTC 时间。未来独立数据导入若涉及无时区字段，必须显式指定来源时区。
8. 稳定 ID、幂等键、不可变快照和乐观锁版本有明确业务含义；新模型按新业务定义，不直接复制旧表结构和占位字段。
9. 并发变更使用唯一约束、行锁或版本条件更新；单纯“先查再写”不能替代并发保证。
10. 数据表只由 migrator 的版本化迁移修改。API、worker 和普通 CLI 不执行 create_all 或自动收敛 DDL。
11. 跨模块外键可以保留，但表的写入和清理归所属模块。引用检查失败不当作“没有引用”。

## 6. 异步与任务

- 每个持久任务有稳定业务 ID、attempt token、租约和终态所有者；所有终态写入验证当前 attempt。
- 重复投递属于正常情况；注册 handler 必须说明幂等键、外部副作用及允许的重试范围。
- 不为队列重试承诺外部副作用 exactly-once。对不可幂等操作记录执行意图和结果，禁止不加判断地重放。
- 取消意图先写 PostgreSQL；执行端有独立取消观察，不等待下一段模型输出才检查。需要 Redis 加速通知时仍保留数据库恢复路径。
- 不吞掉 CancelledError；关闭网络流、释放连接和写入终态使用有期限的收尾保护。
- 禁止业务代码 fire-and-forget 创建持久任务。publisher、reconciler、心跳等进程期协调 task 必须生命周期明确、可取消且受监督；持久业务执行另有数据库事实与所有权。
- API 与 worker 关闭时停止接收新工作，明确收敛或交出未完成任务；恢复职责不依赖一次性初始化 writer。
- 模型重试、队列重试和工具重试共享明确预算，避免嵌套重试倍增请求与费用。

## 7. Vue 与 TypeScript

- 用户已明确保留原前端界面，内部目录和代码可以整理。复用原布局、品牌、视觉 token 和交互，不以整理代码、补齐类型或统一组件为由另行设计产品界面。
- 新平台模块统一使用 Vue 3 Composition API、script setup 与 TypeScript；复用旧组件时同步补齐类型与新模块边界。
- 开启 TypeScript strict 和 vue-tsc 模板检查；禁止以 any 或宽泛类型断言绕过模型、权限和 SSE 事件错误。
- 建设过程中 tsconfig.json 检查 app/shared 及已实现模块，strict 开启；扩展检查范围按域推进，禁止把新增核心文件排除在检查外。独立交付前覆盖新入口的全部代码，原有 JS 源码不因留在工作区而成为新平台依赖。
- 新模块显式导入有类型的模块公开接口，不借助全局 any 声明或旧自动导入兜底。第三方 JavaScript 库在明确 adapter 内收敛边界类型。
- 显式导入 Vue、Pinia 与模块公开接口；新核心代码不依赖隐式全局自动导入。
- views 组合页面；components 用 props/events 协作；api 封装协议；composables 管理可复用行为；store 保存跨组件状态。
- shared/http 的身份获取与失效处理由 app 注入，禁止 shared 反向依赖 identity store。
- 普通 HTTP 只能从模块 api 调用；组件不拼装 URL、不直接操作 token、不自行实现错误转换。
- SSE 解码在协议边界验证事件类型、完整快照和必要字段；内部逻辑使用判别联合。后续版本化增量协议另行校验 schema_version，不能静默兼容未知事件。
- 请求、轮询和 SSE 有明确的取消所有者。切换会话、任务、路由和退出登录时撤销旧请求，并拒绝过期响应更新新上下文。
- 模块只通过 public.ts 和 routes.ts 向应用开放 API、状态选择器、路由元数据；根布局不导入模块私有视图。
- 内置路由显式注册，前端导航由路由元数据、服务端权限与能力状态计算；后端始终执行最终授权。
- 当前已接通页面使用 Ant Design Vue，优先复用原有同类组件与交互。其他既有组件的迁移按页面实际需要单独验证，不把全量替换 UI 组件库作为后端重构的前置条件。
- 使用统一设计 token，保留已有第三方许可说明；不在业务组件引入第二套颜色和间距常量。
- ESLint、Prettier、vue-tsc 分别负责代码规则、格式和类型。格式化不承担业务正确性判断。

## 8. 测试与审查

- 单元测试覆盖纯规则和状态迁移；集成测试覆盖真实 PostgreSQL/Redis 并发语义；浏览器测试覆盖构建后的真实页面链路。
- 测试断言对用户或调用者可见的行为，不用源码正则代替运行、Vue 挂载、事务与网络取消语义。
- 静态依赖检查、权限声明完整性等结构约束可以使用 AST/源码契约测试，并明确它们的验证范围。
- 模型契约测试使用固定本地 mock provider，覆盖 JSON、流式、图片、tool call、结构化输出、usage、错误和取消。
- 真实付费供应商验收独立于普通 PR CI，配置供应商与模型的支持矩阵，禁止误把缺少密钥的跳过记成通过。
- 复现稳定性缺口的测试要验证触发条件、已有保护和恢复结果；避免只增加等待时间使测试偶然通过。
- 低影响、可逆的文档/格式修改不新增镜像实现的测试。
- 变更说明交代业务行为、数据影响、验证范围和回退条件。禁止把未运行的构建、全链路或压测写成通过。

## 9. 目标自动门禁

以下命令是新工程应提供的验收入口，实施阶段需创建对应配置和脚本后接入 CI：

| 范围 | 门禁 |
| --- | --- |
| 后端格式与规则 | ruff check；ruff format --check |
| 后端类型 | mypy 检查新核心包，兼容层例外有清单 |
| 模块依赖 | AST/import 规则检查，覆盖 private、函数内和受控动态导入 |
| 数据升级 | 空库初始化、新平台版本升级、单一 migration head、启动版本兼容验证 |
| 前端安装 | 已提交的 package-lock.json 与 npm ci |
| 前端规则与类型 | ESLint 零 warning、Prettier --check、vue-tsc --noEmit -p tsconfig.json；覆盖范围按域扩大 |
| 前端交付 | production build + 对构建产物运行 Playwright 冒烟 |
| 业务集成 | 真实 PostgreSQL/Redis + 本地 provider 的关键用例 |
| 运行恢复 | 重复投递、并发、取消、失联、重启、租约过期与 stale attempt 回写 |
| 发布 | 新平台实例与发布链独立；源码/锁文件/工具链/镜像摘要可追溯；数据契约决定回退能力 |

门禁首次落地时先记录当前基线和例外，禁止以全局忽略、关闭规则或修改期望值掩盖新增问题。
