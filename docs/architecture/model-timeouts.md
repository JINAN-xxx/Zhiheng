# 模型执行时限

公共执行器管理模型调用的总截止时间，供应商适配器负责有界连接及网络读取，后台队列和 API 等待期限为结果保存留出余量。首响应和流空闲分别计时，正文、思考、有效工具参数增量及完成结果会更新有效活动时间；空包、心跳和用量计数不会延长生成等待。工具参数完整并通过校验前不作为可执行调用返回。

## 默认配置

在 `deploy/core/.env.core` 配置以下变量，API 与 Worker 使用同一份配置：

| 配置 | 默认秒数 | 含义 |
| --- | --- | --- |
| `CORE_PROVIDER_CONNECT_TIMEOUT_SECONDS` | 10 | 供应商连接及连接池等待 |
| `CORE_PROVIDER_FIRST_RESPONSE_TIMEOUT_SECONDS` | 120 | 开始调用供应商后等待首个有效输出 |
| `CORE_PROVIDER_IDLE_TIMEOUT_SECONDS` | 90 | 两次有效输出之间的最长间隔 |
| `CORE_PROVIDER_TOTAL_TIMEOUT_SECONDS` | 600 | 单次原生运行的总预算，包含会话摘要和结果收尾 |
| `CORE_KNOWLEDGE_QUERY_TIMEOUT_SECONDS` | 60 | 一次交互检索的总期限，包含召回、重排、排队和受理 |
| `CORE_KNOWLEDGE_RERANK_TIMEOUT_SECONDS` | 20 | 每个重排批次的上限，同时受检索剩余期限约束 |
| `CORE_KNOWLEDGE_EMBEDDING_TIMEOUT_SECONDS` | 30 | 查询向量化上限，同时受检索剩余期限约束 |

`CORE_PROVIDER_TIMEOUT_SECONDS` 保留为历史配置回退；在直接启动进程、未配置首响应或空闲时限时，分别使用其值。它不再作为流式生成的总时长。Compose 显式提供上表默认值。

工作空间整轮仍使用 `CORE_SANDBOX_RUN_SECONDS`（默认 600 秒）限制模型、工具和成果处理。所有模型与摘要子调用携带父运行的剩余截止时间，连续输出和重试不会延长当前轮的父预算。用户明确继续任务时创建新一轮，沿用已确认的步骤与检查点。已受理检索保存自己的截止时间和阶段预算，配置变化不延长旧检索。

## 结束原因与恢复

连接超时、首响应超时、流空闲、结果收尾和总期限分别返回固定错误原因。收到供应商完成标识后，如果会话检查点等收尾迟迟未完成，错误指向结果收尾，不将已返回内容误判为上游停流。

普通生成达到总期限时标记为 `interrupted` 并保留增量内容；工作空间遇到模型时限中断后进入可继续状态。用户停止仍走原取消链路。既有成功工具结果和成果不因模型中断而重做；尚未确认的调用继续保留其不确定性。

模型流被中断后不透明重试。供应商已报告的 Token 保持真实值；未收到用量则保留未知，不能因超时改成零。原有积分豁免规则继续按运行事实判定，超时策略不改写历史账本。

知识重排超时不会返回未重排候选；原文件和用户问题保留。对外推理 API 传递明确的超时错误码，SSE 已输出部分保留，后台队列和客户端结果等待不会再套用较短的旧生成时限。
