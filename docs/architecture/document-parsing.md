# 文档解析服务

知识库入库使用固定优先级：自部署 MinerU、已启用的云端 MinerU、原生解析。纯文本等轻量格式直接读取。聊天附件仍使用现有准备流程，长附件的异步解析可继续复用本模块，不改变智能体、技能或 Work 的业务定位。

管理员在「知识库 → 知识服务」配置文档解析。服务地址为 `/v1` 之前的 API 根地址，可以包含反向代理前缀。自部署服务可在同机 Docker，也可位于另一台服务器。平台不需要安装 MinerU 或 GPU 推理依赖，且服务未配置时仍能正常启动。

云端默认关闭。只有配置并启用后才会作为后备；关闭时不会向云端提交文件。云端目前对接 MinerU V1 Tasks 契约，真实服务使用的协议和密钥须与该契约匹配。服务密钥加密保存；更换服务地址后需重新填写密钥，旧凭证不会自动发送到新地址。保存后的配置只影响新的解析任务，已接纳任务保留原配置快照。

## 接口与状态

- `GET /api/knowledge/settings/parsing`：读取配置，要求 `system:configs:read`，不返回密钥。
- `PATCH /api/knowledge/settings/parsing`：按 `expected_version` 保存配置，要求 `system:configs:write`。
- `GET /api/knowledge/settings/parsing/status`：检查本地服务；普通页面的能力探测有短缓存，未启用的云端不会被探测或调用。

平台持久化解析任务、源文件快照、上游 task_id、配置快照与产物引用。Worker 独立处理有限的解析 tick，知识库父任务在 `waiting_parse` 状态释放入库槽；完成后继续原有分块、向量化和发布流程。

本地解析并发初始为一个任务，忙时先排队，超过配置的队列等待预算后才选择已允许的后备。连接超时与任务整体期限分开处理。损坏、加密、超限文件在本机隔离子进程中预检，不通过换服务绕过文件错误。源文件或权限变化会停止结果提交。

上游任务创建不自动重试。已知 task_id 的查询、传输失败继续检查原任务；创建结果未知时标记待确认，不重复创建或自动切到云端。用户取消会联动取消已知上游任务。

MinerU 4.2 的自部署 Tasks 记录保存在服务进程内。平台 Worker 重启可以恢复查询仍存在的任务，但 MinerU 服务本身重启后可能返回 task_not_found；平台会明确报告原任务失效并保留原文件，要求重新解析。给容器挂载目录不能自动让该内存任务表具备持久化能力。已完成的解析结果会登记进平台文件库，之后无需依赖 MinerU 保留结果。

## 缓存与索引

MinerU 产物版本包含服务版本、地址、档位、转换格式版本和配置修订的指纹；缓存继续绑定源文件身份、哈希和当前访问权限。基础解析覆盖检查改进后采用 `native-2`，旧产物与已有索引仍然保留。

调整配置或恢复服务不会自动重建全库。新入库、明确重解析或重建时按本次配置选择产物；原生降级结果不会永久遮蔽更高优先级的解析器。预览复用文档已绑定的解析产物，因此扫描 PDF 经 MinerU 入库后不会再次落入原生 OCR 错误。

原生解析无法完整提取扫描件或混合扫描 PDF 时会报告需要 OCR，不发布空文本或残缺的新索引。列表显示实际解析方式，基础后备显示「基础解析」。

## Docker 部署

平台与 MinerU 无硬启动依赖。地址配置使用容器可达的服务名称或内网地址，不能把平台容器中的 `127.0.0.1` 当作宿主机或另一个容器。

当前部署使用的两个网络分别为 `zhiheng-core_default` 与 MinerU Compose 的 `docker_default`。接入同机服务可将 MinerU 连接到平台网络；新环境应通过 Compose 的外部网络声明保留这一关系。例如在 MinerU 的 Compose 覆盖文件中配置：

```yaml
services:
  mineru-api:
    networks:
      default: {}
      platform:
        aliases: [mineru-api]
networks:
  platform:
    external: true
    name: zhiheng-core_default
```

网络名称应匹配实际部署的 Compose 项目名。没有 MinerU 的环境无需创建这个服务，也不要给平台加上必须等待 MinerU 健康的 depends_on。

升级时固定服务版本、提前处理进行中的解析任务，并验证 `/v1/health` 与实际文件解析。模型缓存、日志和文件保留按 MinerU 所选部署方式配置；平台业务文件和解析产物继续使用现有文件存储及权限体系。
