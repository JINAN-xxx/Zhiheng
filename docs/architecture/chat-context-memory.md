# 普通对话的上下文与滚动摘要

普通对话使用“近期原文＋滚动摘要”，默认不预设输入或输出 Token 上限。聊天原始消息完整保存在会话中，压缩仅改变后续请求带给模型的历史表示。

## 默认策略

| 设置 | 默认值 | 环境变量 |
| --- | --- | --- |
| 未压缩成功问答触发轮数 | 30 | `ZHIHENG_CHAT_SUMMARY_TRIGGER_ROUNDS` |
| 压缩后保留原文轮数 | 15 | `ZHIHENG_CHAT_SUMMARY_KEEP_ROUNDS` |
| 输入预算 | 不设置；显式配置时才启用 | `ZHIHENG_CHAT_CONTEXT_INPUT_TOKENS` |
| 摘要输出上限 | 1024 Token | `ZHIHENG_CHAT_SUMMARY_OUTPUT_TOKENS` |

触发轮数必须大于保留轮数。配置由 API/Worker 启动时读取，两者应使用相同配置。Token 计数为适合中文的保守离线估算，不等同于供应商 tokenizer 或最终账单；实际用量继续按原模型返回的用量结算。

一轮是一个已完成问题及其最新成功回复。重新生成的多个版本只取一个，不完整、失败或被长度截断的回复不计入。首次完成第 30 轮后，摘要覆盖第 1～15 轮，原文保留第 16～30 轮；完成第 45 轮后，将旧摘要与第 16～30 轮合并，保留第 31～45 轮。

显式配置输入预算或模型上下文窗口后，达到预算时可以更早触发摘要。系统提示词、技能、本次问题、附件和图片先占预算；历史按完整问答选择，不切开消息。当前必需输入本身超过已配置预算时返回带估算值与上限的错误，输入区保留附件和草稿供调整，不悄悄截断当前问题。输入预算及模型窗口均未配置时，不再按 8192 Token 或普通对话的旧 64KB 预占阈值拒绝附件。

模型目录的“上下文窗口”是可选 Token 配置。已配置时，输入预算扣除本次显式输出限制与安全余量；未配置时不推断供应商容量，也不把目录中的输出参数当作上下文窗口。普通对话“输出长度”留空时不向供应商发送 `max_tokens` 或 `max_completion_tokens`，填写后继续遵守所选模型的配置约束。供应商自身的实际容量仍由供应商校验。

未指定输出长度时，计量使用 4096 Token（目录参考值更小时取较小值）作为预占估计，该值不作为输出请求参数；最终按供应商实际用量结算，未知用量继续保留预占。附件总大小继续限制为 50MiB，文件权限、格式解析与图片数据约束独立校验。

## 连续覆盖与后台执行

摘要只合并旧摘要与新增的连续历史，保留目标水位。内部摘要任务继续使用有限批次（未配置输入预算时为 8192 Token）和 1024 Token 的输出设置，这些参数不限制用户的普通对话。单次摘要输入装不下时按前缀分批：例如第 30 轮需要覆盖到第 15 轮，首批只装下前 7 轮，后续批次仍继续到第 15 轮，不能因剩下 23 轮小于触发阈值而提前停止。目标、待执行任务和覆盖范围都在数据库中保存，进程重启后可继续。

摘要通过原生 `chat_summary` Run、同一 Outbox/ARQ/InferenceExecutor 执行。其 resource_id 是独立摘要任务 ID，普通聊天的运行占用与后台摘要分别管理。摘要调用使用当前对话模型，受模型可用性、原费率、用户额度及积分约束；用量来源显示“会话摘要”。没有第二套模型客户端、队列或账本。

失败、超时、空输出、未正常结束或长度截断不会覆盖最后有效摘要。自动处理进入降级状态，不随每条新消息反复创建付费尝试；用户可以点击“重试整理”。重试使用 owner＋client_request_id 的持久身份，接纳结果未知时保留原键；重放、重复投递和并发发布不重复执行同一尝试。

## 归属、来源与快照

会话按真实用户隔离。摘要作为历史资料以普通消息传入模型，不能替代系统提示词。摘要不包含历史思考过程，不把图片 base64 当作文本；旧图片参考此前回答中的视觉结论和附件来源。

每次聊天保存实际采用的摘要版本、问答来源、附件 ID/SHA 和输入预算快照。无输入上限的新快照使用 `input_budget=0` 保存，控制台查询映射为 `null`；已有快照的数值与历史 Run 保持。新请求只加载实际需要的近期附件内容，已覆盖历史使用轻量元数据复核，避免每轮重新加载旧图片和思考过程。来源文件继续按当前权限、状态与 SHA 检查。

已接纳请求重放返回原 Run；原输入和计量结果保持。重新生成保留原问题与上下文，并保证冻结技能版本与真正发送的正文、审计快照相符；新接纳时重新验证当前模型窗口。历史知识检索问题的当前命中来源或 wrapper 已变化时明确拒绝复用旧 prompt，避免发送旧来源内容却绑定新出处。普通聊天没有新增知识库选择入口。

## 实现边界与锁序

- `modules/chat/context_policy.py`：整轮选择、连续覆盖计划、离线估算、来源指纹。
- `modules/chat/context_orm.py` 与 `context_store.py`：摘要状态、摘要任务及每次 Run 使用的上下文快照。
- `application/chat/context.py`：输入构造、摘要调度、来源授权、幂等重试与 CAS 发布。
- `worker/` 与 `bootstrap/container.py`：原生执行及周期补偿接线。
- `frontend/src/modules/chat/composables/contextObservation.ts`：可见性、用户/会话作用域与静默状态观察。

状态写入通过会话 `FOR NO KEY UPDATE` 串行化。普通聊天完成时持有账户锁；后台整理在拿摘要状态锁前发现普通运行活跃会延期，保留 dirty/pending/目标信息。手动新重试在普通生成中明确返回忙碌提示，已存在的请求身份仍可安全重放。该顺序避免账户与摘要状态互相等待，也不阻塞普通完成插入消息需要的外键 key-share。

数据库迁移 `0017_chat_context_memory` 新增三个 chat 表与模型可选窗口列，不重写原消息、模型价格、已冻结 payload 或账本。已有会话在升级时不批量调用模型；后续使用产生符合条件的新运行才启动后台整理。
